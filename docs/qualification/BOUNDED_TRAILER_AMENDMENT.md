# 有界尾区兼容补充协议

日期：2026-10-04。状态：待独立反方审查。本文件只修订资格探测的压缩帧边界；首批产品内核、原失败证据、D01代码与协议均保留。

## 依据与最小选择

[D01实测](baostock-acquisition-results.md)确认96回复的声明压缩正文后、13字节结束标记前另有12字节。官方SDK 0.9.4的`socketutil.py`仅解压`[21:21+N]`，等待结束标记，不解释这一尾段。因此不再追加请求猜测尾数字或校验算法；对齐已核SDK的正文切片，同时明确限制尾区。

本轮不授予附加尾区CRC校验或网络真实性资格。zlib流自身校验、响应身份／字段预检及精确单元格核对仍须全部通过；附加尾区保留为内存中的不透明协议字节，不落盘、不打印，不用于行情语义。

## 接收约束

1. 仅既有96／99压缩类型进入此分支。固定21字节头、声明正文N字节及原有5MiB累计发送接收预算不变。超长声明、EOF、非法头立即失败。
2. 接收完成声明正文后，尾区包含结束标记在内最多64字节。只在这一尾区查找完整`<![CDATA[]]>\n`，不得把压缩正文中的相同字节误作结束。无完整标记达到64字节即失败，禁止无界寻找或重试。
3. 完整标记终止本帧；若本次已经收到的缓冲中还有标记后字节，拒绝。尚未接收的TCP字节不作无尾随数据保证，不为此等待另一个响应。不得把尾区吞进zlib输入。
4. 解压输入严格为声明的N字节，保留增量输出上限、eof／unconsumed_tail／unused_data检查及UTF-8限制。错误只产生安全代码。尾区允许0—51字节不透明前缀；这是资格探测的工程上限，实测只覆盖本次12字节。
5. login/logout等控制分支保持原行为；socket最多8秒、交换绝对10秒、父进程35／45秒不变。原响应预检仍先于page持久化；不得因传输可解压就保存未知或控制响应。

## 离线门槛与下一轮

负例至少包含：12字节不透明尾区、0／51字节前缀和超限，尾标每一处拆分，正文含伪尾标，已经接收的标记后多余字节，声明短／长、流未结束／压缩体内多余数据、累计线路／解压限额、绝对期限、敏感控制载荷无落盘。短声明允许到达解压阶段，但仍必须因不完整压缩流失败。现有分页、子进程、预检测试继续通过。

实现完成后记录代码SHA及独立复审结果，才允许**另建目录执行一次**原[P01→P02→P03](AUTOMATIC_ACQUISITION_PROTOCOL.md)有界轮次；原参数、上限、失败即停止、无自动重试全部不变。P01即使成功也仅称固定查询协议结束；P03一份首响应不推断全市场覆盖。

本补充协议不准许生产连接器、Schema变更、批量99格式导入、当前客户端导出兼容或UI解冻。
