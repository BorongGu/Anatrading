## 发现的 SDK 元数据问题

首轮保存的三份 SDK 解码响应尾部直接结束于复权字段 `3`，无换行。安装包 `security/history.py` 使用 `receive_data[21:-1]` 取消息体，末字符被截去，导致 `result.adjustflag` 为空；逐行 `adjustflag` 和保存响应中的尾字段仍为 `3`。日线响应末 12 字节为 `32312d30352d313401640133`。两份日线补样的 SDK 顶层字段也为空，逐行仍为 `3`。

这是这批响应与 0.9.4 代码配合时的可复现差异。当前未改供应商 SDK，也未在捕获阶段补写元数据。后续连接器应分别核对请求、响应及逐行标记，再决定处理或拒绝；不能只信任顶层字段，也不能凭请求参数伪造缺失的返回证据。

SDK 还有两个进入生产采集前需要单独验证的边界：`send_msg` 遇到空 `recv` 没有明确结束分支；分页 `next()` 在没有收到响应时可返回 `False`，却未必设置错误码。探测通过外部进程时限和小于单页上限的固定请求控制这两类范围，本轮未验证完整分页采集器。
