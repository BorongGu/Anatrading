## 实现范围

- 单股页面新增手动检索：固定20个来源区间、21个点；结果同时明确实际查询起止与自然日跨度，用户可改终点重跑。旧图的序号范围不作为研究前缀。只读流程不增加二次确认门槛。
- 纯核心先截截止，复用来源身份、日期分组与精确价格。坏/重复组保留原槽；无法定位日期拒算。源级未知失败拒算，已知量额检查失败单列披露；前缀内价格/身份/结构/位置/未知失败使相应窗口无效。已证明位于截止后的坏行不参与旧结果。
- 每窗先计算整数平方和、一次构造有理数，再按精确值执行三轮贪心扫描。主法、端点最近、时间最近分别去重。最多9个唯一展开窗口，账本保留全部候选、首个无效位置与三法最终重叠归属。
- GET `/api/research/path-match/{snapshot_id}?cutoff=D` 只接一个必填日期参数，一次预算计数、一次完整前缀读取、一次原件校验。沿用owner线程与安全错误映射，不修改Store、旧single结果或导出。
- 比例和距离以独立12位有效数字、half-even科学计数显示；排序不使用显示值。原价为精确字符串，图形只用舍入显示值布点。没有候选后续路径、概率、预测方向或经济收益输出。

## 20,000行固定资源边界

一次独立进程使用覆盖DECIMAL(38,18)宽范围的确定性合成价格，输入20,000行、候选19,959个。纯核心实测0.967秒，进程峰值RSS91,408KiB（包含解释器、模块与输入，非纯增量峰值）；结果JSON 2,101,946B，最长账本行含逗号94B，除账本/日期之外16,525B。普通价和宽范围两组预算测试均通过。

这些是当前Linux执行环境的一次记录，没有跨机性能承诺。实现同时检查账本每行≤160B、日期每项含逗号≤13B、其余≤256KiB与总JSON≤4MiB；HTTP包裹后再核总预算。超限整份失败，不截断账本或返回部分赢家。
