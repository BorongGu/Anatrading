## 2. 两种方法必须保持独立

SOH 指消息分隔符 `\x01`，消息头为 21 字节；本轮参数均为 ASCII。类型常量证据为 S5:112—115，头部构造为 S7:12—17。

### 2.1 单证券历史：95 → 96

S1:20—24 固定从第 1 页、每页 2,000 条开始，2,000 的常量位于 S5:189。S1:89—104 的请求正文顺序为：

```text
method | user | page | per_page | code | fields | start | end | frequency | adjustflag
```

成功响应正文按 S1:121—135 为 **13 段**：

```text
error_code | error_msg | method | user | page | per_page | JSON(record) |
code | fields | start | end | frequency | adjustflag
```

P01 固定 10 字段：`date,time,code,open,high,low,close,volume,amount,adjustflag`。P02 固定 9 字段：`date,code,open,high,low,close,volume,amount,adjustflag`。正文及行内身份都必须核对；禁止只信请求参数或 SDK 可变对象。原始 JSON 单元格保留字符串，独立解析不先删空白、不经 float。

S1:112 与 S2:97 使用 `[21:-1]`。已有五份响应尾字符为 `3`、没有尾换行，SDK 顶层 `adjustflag` 因此变为空；完整正文尾字段和逐行旗标仍为 `3`。该缺陷已有 [逐样本证据](baostock-samples.md#2-sdk-尾字段问题已独立复现)。首屏已定位的行为不能自动覆盖未知的后续页响应形状。

**恰好 2,000 行陷阱：** S2:67—79 仅在当前数据行数等于全局 2,000 时发下一请求，并把请求正文第 3 段改成下一页号。AStock 第 3 段恰为日期，因而会变为 `2`。多于或少于 2,000 行会停止。该结论为源码推导，尚未运行故障替身。P03 应只调用一次该方法、直接读取 `data`，禁止调用 `next()` 或 `get_data()`；官方示例的遍历循环不能作为此边界的保证。

所读官方正文描述指定日 A 股，示例只有沪市代码，未明确承诺北交所、退市历史或特殊品种范围。客户端也未在该方法中筛除某交易所。**当前无法确认含 bj，也无法确认不含 bj。** P03 只报告实际前缀及计数，覆盖率须另有该日有效证券分母；不能用响应本身作分母。本轮不追加证券清单请求。

## 4. 有界传输方案的必要细节

接受在**独立探测子进程内**临时替换 `baostock.util.socketutil.send_msg`。S1、S2、S6 均通过导入的该模块调用它，替换范围须包含登录、查询、翻页和登出。SDK 安装文件不改，报告明确标为“固定 SDK 调用 + 受限传输”；原生 socketutil 的可靠性不据此通过。

最低边界如下，均需本地负例验证后才联网：

1. 每次交换绝对 deadline 为 10 秒，socket 单次等待不超过 8 秒且不超过剩余时间。`sendall` 和所有接收循环都在此期限内。父进程 P01/P03 45 秒、P02 35 秒预算包含启动、登录、请求及清理；期限到即终止 worker，有限等待确认退出，确认失败则停止后续案例。每次 `recv` 的空返回立即形成固定错误。
2. 线路总字节最多 5 MiB，压缩头长度、实际可用压缩体、终止标记必须一致；超限不能继续累积。接收分块、短收和标记拆包属于正常 TCP 情形。任何未知帧、缺字节、额外消息或不完整压缩流均停止，不能为“兼容”而放宽。未证实的外层 trailer 语义保留未知，不声称认证了它。
3. 解码回复上限按 UTF-8 **字节**计 5 MiB，包含原 21 字节头部。使用 `decompressobj().decompress(..., max_length=...)` 一类有限输出接口；检查 `eof`、`unconsumed_tail`、`unused_data` 并禁止无限输出的末尾 flush。超出剩余预算即失败，不能先整体解压再量长度。Python 官方说明 `decompress` 的 bufsize 及 `flush` 的 length 都只是初始容量，`max_length` 才限制当次解压输出，见 [zlib 文档](https://docs.python.org/3/library/zlib.html#zlib.Decompress.decompress)。
4. 先有受限帧和受限解码，再核对预先批准的请求/响应类型、成功码、方法、匿名用户、字段顺序和字符串行结构，最后保存行情文本。仅在“调用了行情方法”这一条件下保存，仍可能误存控制响应。控制载荷可以被解析以完成会话，必须停留在短期内存；日志及异常对象不直接序列化。
5. 每次允许的行情发送前递增预算，包括无响应请求；P01 最多 3 次，P02/P03 各 1 次，整轮最多 **5 次行情请求**，不自动重试。必要 login/logout 单独计数并受各案进程期限约束。失败连接不用于“补一个请求”。

以上限制约束载荷尺寸和执行期限，**不把 5 MiB 称为整个 Python 进程的内存上限**。JSON/Unicode/列表对象有额外开销；此处无需引入通用流处理框架或新的产品存储层。探测产物大小、允许文件和安全元数据同样应有明确上限，避免把 SDK 任意输出变成另一条无界路径。

### 5.1 本地边界先行

### 5.2 仅执行已批准的 P01—P03

以 [有限接口验证协议](AUTOMATIC_ACQUISITION_PROTOCOL.md) 为请求清单，不增加旁路请求：

### 5.3 重试与“结果不明”的处理

本轮协议禁止自动重试。失败后保留此次明确终态与已经预检的完整页；请求已发出但未获合法响应，记为结果不明/未完成，禁止把旧 `error_code=0` 当作收到回应。控制响应只留安全码。

未来连接器若要重试，最低方案为：固定请求身份、显式有限次数、退出旧 worker 后建立新匿名会话、从第 1 页重新获得完整批次；不同尝试不能按页号拼接为同一快照。源码没有服务器分页快照 ID，盲目续页可能混入修订内容。身份/结构/权限/重复页拒绝不进行自动重试；短暂传输失败是否重试及退避时长须在连接器合同中固定。

若市场页已经取得，结果不明发生在本地发布阶段，应先查询本地 attempt/content 身份核对持久终态，不能立即重新联网。当前探测不访问产品数据库，此项只是未来合同门槛。两次历史捕获相同仅支持两个观察时刻未见变化。
