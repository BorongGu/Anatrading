## PR #34 精确提交审查补充

公开 PR 的首轮 Codex 审查在 `9c781c4` 上指出 P2：普通 `fs.symlinkSync` fixture 在未启用开发者模式或没有符号链接权限的 Windows 上可能于子进程阶段报 EPERM，掩盖预期的 release 拒绝。

已仅调整五个链接 fixture：Windows 使用目录 junction，Linux 仍使用目录符号链接；所有链接目标为绝对路径，且构造时已存在为本次新建目录。raw 链接指向已创建的 staging，staging 链接指向已创建的 store，数据库/锁链接指向已创建的 raw；raw 分片中的附加链接指向 staging。路径名称仍合法，继续断言 release 阶段；四个直接路径用例继续断言精确的异常路径类型和目标。生产 helper 的 lstat、路径布局和硬链接检查没有放宽，也没有新增 skip。

初次 junction 版本在 Linux 完整 Node 测试为 586/586；随后调整创建顺序，确保所有 junction 的目标在创建时已经存在，再用另一个全新临时根重跑完整 Node：586 通过、0 失败、0 跳过，含两条实际新建的合成 Store 桥接和全部 26 个生命周期用例。原有失败历史与日志保留。此结果只验证 Linux 实际执行路径；Windows junction 分支及 Windows 原生行为仍未执行，不宣称 Windows 验收通过。
