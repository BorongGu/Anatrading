# 首批数据证据内核：有限验收

日期：2026-10-04。对应 [首批数据合同](../contracts/INITIAL_DATA_CONTRACT.md) 和 [实施决定](../contracts/IMPLEMENTATION_DECISIONS.md)。本报告只评价已经实现的源值证据闭环，不关闭 G1/G2 整体门槛或完整项目目标。

## 1. 实际操作与实现范围

Windows 上通过 Python 调用接口和 `anatrading` 命令行完成：原文件导入、原件哈希保存、单批不可变快照、质量查询、源标签/序号截断、精确 JSON/Parquet 导出、离线备份和新空目录恢复。未实现 HTTP API 或图形工作台。

格式限定为已审计的通达信 GBK/逗号及 UTF-8 BOM/空白分钟文本、32 字节 `.day` 候选格式、BaoStock 0.9.4 行情解码响应。通用 CSV、当前同花顺文件、当前通达信客户端、分钟二进制和自动采集均未获得本次兼容结论。

原件、源 token/位、记录定位、质量结果、输入解释与合同内容身份进入快照血缘。未知规范身份/股数/金额保持空；调用方声明仅为 assumed。合同分别保存单位、累计域、复权与时间语义，公共未知状态适用于全部记录，不用截止值补造 `known_at`。

## 2. 数值及真实样本验证

源 OHLC/金额为 `DECIMAL(38,18)`，源数量为非负 `BIGINT`，转换前执行精确范围检查。原字段超过有效18位小数、范围溢出、非有限值或非整数数量时保留 token 和错误。零值、缺失、异常字段分别保存。汇总使用独立精确上下文，允许超过单值列范围的字符串结果，不经浮点或数据库隐式舍入。

产品全链测试的8份真实输入共24,151行：通达信1m、5m、日线三份，BaoStock日/分钟五份。每份经过 `import_file → query → JSON → Parquet`，逐项对照已冻结的原件哈希、规范数值哈希、六字段控制总量、原 token、质量结果及空规范列。其他文本变体和已知负面文件另由格式测试覆盖。

- 通达信1m严格条件边界异常1,228条、旧每股一分诊断211条；5m严格异常7条，日线2条。诊断携带股/元/同覆盖假设，不能当作正式单位验收。
- 对应固定3,168个窗口，1m与原5m的53个差异在查询、JSON和Parquet三条读回路线全部保留；O/H/L/C/V/A分别为13/2/0/18/51/52处不同。该比较仅为验收脚本，产品没有启用重采样器。
- BaoStock完整响应尾旗标与逐行旗标保留为3；SDK截尾缺陷未复用。两条日线金额差58.62/63.60，以及两天分钟与日线金额差+1.01/−0.15保持原样。
- 人造边界另验证 `9007199254740993`、BIGINT上界、38位Decimal上界、NULL/0、比单列更宽的总和；JSON中的行情数值是字符串，Parquet保留decimal128/int64及行状态。

真实基准来自 [TDX独立审计](tdx-public-samples.md) 和 [BaoStock逐字段审计](baostock-samples.md)。此前38,763行[独立数值实验](numeric-roundtrip.md)属于选型证据，与本次24,151行产品全链验证分开统计。

## 3. 事务、取消和恢复

每次导入先独立提交尝试记录。原件同卷暂存、刷新、校验后按哈希发布；随后单库事务提交批次、行、质量、快照和尝试终态。同内容同解释只复用批次/快照，新尝试仍单独保存。规则/解释变化产生新身份。

实际子进程用 `os._exit` 在尝试开始后、原件发布后、最终提交前、提交成功但返回前退出，重开后分别核对 interrupted/committed 与快照数量；未提交原件不自动生效。ENOSPC、重命名、复制和数据库异常采用故障注入，没有填满真实磁盘，也未做硬件断电实验。

取消只有在最后提交检查前接受；临界段后报告持久化结果。事务开始/提交实际生效后抛错、提交期间连接失效、取消或拒绝已持久化后返回异常均检查终态与可恢复性。无法核对时给出 `import_outcome_unavailable`，不伪报取消或提交成功。

数据根OS锁覆盖所有合作实例的访问、数据库关闭后的备份和恢复复制。测试包含第二进程、备份期间并发关闭、持锁重连、恢复期间第二实例、原件损坏/缺失、复制后数据库及原件损坏。恢复逐项比较目标哈希；失败留 `.restore-incomplete`，后续打开明确阻断。正常备份恢复后冻结查询内容相等。

BaoStock预检限定匿名成功行情信封及字段白名单。六类认证/控制/非行情负例的原始载荷、敏感标记均未进入原件、暂存、数据库或输出。

已测 Windows 11 build 26200、64位 Python 3.14.0、DuckDB 1.5.6、PyArrow 25.0.1、pytest 9.1.1。项目版本 `0.1.0.dev1`，本地 editable 安装及控制台入口已实际运行，`pip check` 无依赖冲突。没有升级原环境中的其他运行依赖。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests -q
.\.venv\Scripts\anatrading.exe --help
```

真实行情原件和运行产物不进入公开Git。`test_formats.py` 和 `test_real_pipeline.py` 缺少指定私有原件时明确skip，不静默下载，也不把跳过当通过。合成测试只能证明边界行为。已核12个原型存档哈希与冻结清单相等，两个web原型文件仍未变化。
