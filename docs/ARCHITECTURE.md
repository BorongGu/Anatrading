# Anatrading 架构

更新：2026-10-11。目标见[总体方案](MASTER_PLAN.md)，本轮边界见[实施方案](plans/2026-10-11-research-workflows.md)与[编码前独立复核](reviews/2026-10-11-research-workflows-review.md)。本文区分已有基础、已实现的首版研究模块和后续设计；内部紧凑读取、分钟 A 纯函数及第三批有界采集/格式通过冻结 Linux 回归与限定独立复核；第四批同伴 A 纯函数和筛选只读 API 完成独立实现复核、真实来源矩阵与联合回归；筛选 UI已接入并通过模型/静态组件、桥接、构建与独立实现复核。第三批旧捕获离线兼容通过，新运输真实网络仍阻断，完整验收按项目分别报告。首版基础见[实现后独立复核](qualification/research-implementation-review.md)。

## 1. 一套本地内核

- **平台**：通用导入、DuckDB/Parquet、研究计算、HTTP 和 Web 使用同一套 Linux/Windows 代码。通达信客户端调用、Windows原生进程和任务控制保留在专用适配器中，不把 SDK 的平台、位宽或 Python 限制扩散到研究内核。
- **结构**：本地模块化单体，Python **3.14** 后端、React/TypeScript 界面，依赖按现有 lock 文件安装。浏览器只负责交互和图形，统计真值由后端计算。
- **存储**：原字节按内容哈希保存；单一 DuckDB 保存批次、版本、查询和作业关系；Parquet 用于导出。只有主应用拥有数据库写入权。
- **计算**：原价格/金额保留 Decimal；新模型估计在明确边界用 float64，带单位、方法身份和失败原因。性能优化先测量，保留简单参考实现。
- **范围**：不新增微服务、消息平台、指标插件框架、第二套数据库、持久特征缓存或自动清理。国际市场按数据与规则扩展，通用数学不硬编码 A 股交易制度。

早期 Windows 优先的整应用限制已被本轮跨平台决定替代；历史存储简化、单写入者、精度和时间约定继续保留。原始[架构稿](https://github.com/BorongGu/Anatrading/blob/efbf14e76d4bc61bc903a0b82139fa93cd98e485/docs/ARCHITECTURE.md)与[取舍记录](REVIEW_DECISIONS.md)可追溯。

## 3. 原始数据与版本

- 原文件/响应保存原字节、SHA-256、来源/格式版本、实际取得时间和非敏感参数。同内容去重，不原位改写；来源修订生成新批次和版本，旧研究仍指向原输入。
- 格式约定逐项说明字段、数值类型、源单位、时间标签、复权、覆盖、缺失和版本适用范围。用户声明与已核验语义分开；无依据不生成规范字段。
- 股票身份需要证券、市场及有效日期，不能把六位代码当作跨市场永久身份。价格、数量、金额、指数点数及统计对象分别定义。同一证券多个版本不计为多只股票。
- 观察保留来源序号、原 token、原位置、质量原因和重复记录。无法定位日期的行单列，仍进入完整覆盖限制；不会悄悄删掉后称历史干净。
- `research_series.py` 传递已有来源检查：证券身份或复权声明明确冲突的日期组不可参与研究；已隔离/已知负例来源保持失格。原价格和日期槽保留，状态与窗口按坏组规则中断；无关量额缺失不会使有效价格自动失格。
- 已引用数据版本不可变；方法、Schema、规范化、质量、数值上下文和输入选择进入身份。新规则不能重新解释旧对象，迁移须产生新版本并保留旧读取路径。

完整历史分层实体仍保留：原件 `RawObject`、来源定义 `SourceContract`、观察 `Observation`、参考事件 `ReferenceEvent`、数据版本 `DatasetSnapshot`、派生事件 `FeatureEvent`、实验 `ResearchRun`。后几层的完整主数据/时点评价是后续设计，不代表当前 Store 已支持。历史实体细节见原稿及[首批格式约定](contracts/INITIAL_DATA_CONTRACT.md)。

## 4. 精度、单位与空值

1. 原价格/金额采用 Decimal或显式定点；整数股转换须先核实源单位。保留原始 binary32/64 的精确位值及其来源量化；转成 Decimal 不会恢复供应商已损失的信息。
2. 数据库、Arrow/Parquet、API和导出按同一精度/scale约定往返。超精度或溢出明确拒绝/隔离，不静默舍入；源误差与系统新增误差分开。原始精确值通过API字符串传递，画布才转浮点。
3. DuckDB DECIMAL除法会进入近似浮点；精确金额/量参考计算留在Decimal层。[数值说明](https://duckdb.org/docs/current/sql/data_types/numeric)与[Arrow Decimal](https://arrow.apache.org/docs/python/generated/pyarrow.decimal128.html)作为类型依据。
4. 新统计估计注明 `estimate_float64`，拒绝非有限、不可表示和正价下溢。估计结果不反写源价格/金额；突破条件仍用Decimal比较。
5. 零、缺失、非交易/停牌、部分柱、源补值、错误和无法定义分别表达。空结果带原因；零量均价、零分母相对量不可定义，不填零。缺失不能靠插值或删行凑满窗口。
6. 量额分别标明 `interval/cumulative_day/cumulative_session/trade/indicative`。累计量先核锚点、重置和缺口再差分；负差、缺首条和未知重置不给伪增量，虚拟匹配量不当作已成交。
7. 币种、股/手、元/万元、比例与百分比在结果中明示。金额一致性阈值随源精度与成交覆盖变化，不能统一用一分钱；指数不套股票倍率和无定义的VWAP。

## 5. 时间与可得性

来源日期、柱开始/结束、事件生效 `effective_at`、源公布/可得 `published_at/available_at`、实际取得 `observed_at`、研究截止 `known_at` 和结构确认 `confirmed_at` 各有用途。收盘标签不证明当时已取得最终收盘值；实际取得时间不能倒填首次公布时间。

当前新增研究只返回 `mode=retrospective`。它按提供的历史版本描述，保留复权、日历、闭合与历史可得性未知的限制。未来严格时点研究需逐次决策同时限制价格版本、主数据、证券池、训练数据和特征确认；不能用实验结束日统一授权过去的信息。

- 信号只能使用当前和过去输入；追加或改写未来行不能改变过去信号。需要右侧柱确认的拐点，确认时间晚于发生时间，不能倒填为当时信号。
- 后续标签在成熟后可更新，信号截止与评价截止分开。固定评价截止的结果必须稳定；跨测试起点的训练标签剔除。
- 有证据的历史时点与带假设的时点研究分开。混合输入继承较弱资格，假设随派生链传播，不因经过模型而升级。
- 当前成员历史回顾只称所选样本。历史动态选股需每个日期的成员/选择规则、入选与排除、退市和分钟缺失；缺数据的入选股票仍留在覆盖分母。

## 6. 本轮算法约定

公式、固定参数、数值阈值、原文阅读范围和专用测试以[026](research/026-causal-signals-and-evaluation.md)为准，竞争任务依据[027](research/027-competitor-workflows.md)。以下是边界摘要：

- **单股**：日线log(close)单侧局部线性Kalman，固定公开参数与Joseph更新；首根只初始化，20根预热；EMA作同尺度基线。EWMA使用原始log收益，冲击使用当期纳入前方差。不平滑未来、不全样本估参、不自动年化。
- **事件**：当前close严格高于此前N组high最大值；完整正OHLC校验不依赖量额。后续h来源记录步的简单价格变化，坏路径/未成熟分别计数；按时间贪心去重。Type-7分位与同资格日期基线，不输出独立样本置信度或成交收益。
- **双股**：先核对不同证券且同一市场，再找共同日期，计算相同起止区间收益；坏组保留为中断。收益相关/beta可含当前区间，价格回归仅用此前窗口；左右角色固定并回显。回归beta是log价格弹性，不能称固定对冲股数；退化残差不会抹掉仍可计算的相关或beta。
- **集合**：首版同一市场，沪/深/京归为CN_A，拒绝与US/HK混用；同一截止必须存在当日价。N+1来源日期组计算N步动量、ddof=1的log收益波动和非正最大回撤。每项真实起点/分母分别报告，按精确动量降序并列名次、稳定身份次序；广度为正动量数/有效动量数。
- **恢复**：坏价/重复日期中断状态，下一有效值显式重启。日历未知时不按自然日间隔自行补柱/重置。源记录步不承诺交易日等距；国际/跨市场关系另需同步约定。

统计相关、价格偏离、平滑和暖机结束不提供预测概率、协整、均值回归或套利资格。分钟Kalman、自动调参、PCA、组合优化和交易PnL留待后续独立研究。

分钟 A 按 [028 §4.4](research/028-intraday-research-candidates.md#44-独立首轮意见后的-a-输入输出合同候选)和[实现复核](reviews/2026-10-11-intraday-candidate-review.md)固定为 `intraday_sampling_report` 纯函数：一个 1m 来源版本、一个来源日期、显式 descriptor/cutoff，保持 `retrospective/source_template_only`。以固定首 close 为锚点比较同覆盖 1/5 名义分钟收益平方和，缺槽/坏价/已知未闭合阻断共同区间，尾部与未知覆盖单列；不自选锚点、不跨段合计、不认证真实时区或闭合。最多 20,000 源行、8 段、1,440 期待槽及 16 KiB 辅助说明，身份绑定来源、descriptor、截止与负闭合证据。该模块无存储、网络、HTTP 或界面操作，B/C 与分钟 Kalman 仍未实现。

同伴 A 按[030](research/030-peer-relative-research.md)及[实现验收](qualification/peer-relative-research.md)实现纯函数 `peer_relative_report`：4–50个固定成员、一个目标、明确a/b，仅腾讯日线strict/legacy合同。剔除目标后计算同伴精确中位数和均值，以Fraction返回来源价格变化及差；缺端点不回退、不删股改分母。组说明绑定身份，声明不取得历史行业/市场中性或经济收益资格。当前无Store写入、HTTP/UI或后台任务。

筛选按[032](research/032-explainable-stock-filters.md)、[实现复核](reviews/2026-10-11-explainable-filters-review.md)和[验收](qualification/stock-filters.md)复用一次集合事实：动量与最大回撤用Fraction，波动保留float64估计并以其精确二进制值比较十进制阈值。完整AND/OR三值逻辑保存所有原子、分支、见证和未知原因；源日期gate独立于价格事实，不能靠充分OR支路放行未定位来源。`result.conditions`共享规则原子，`source_contracts`仅合并完全同投影的合同；a/g是rule-local、r是member-local引用，来源/窗口/规则/分析身份仍绑定完整内容。最多两组、每组三原子，无任意表达式执行器。

## 7. 查询与研究 HTTP

复用现有同源FastAPI、Host/Origin/token校验与owner执行线程。所有Store调用在owner内执行，新研究没有第二个数据库写者。

已接通并有自动化测试的只读入口：

- `GET /api/research/single/{snapshot_id}`：可选cutoff、lookback默认20、horizon默认5、可选test_start
- `GET /api/research/pair`：left/right/cutoff必填，lookback默认20
- `GET /api/research/universe`：snapshot_ids与cutoff必填，lookback默认20
- `GET /api/research/universe-filter`：snapshot_ids、cutoff、rule必填，lookback默认20；rule为最多2,048 UTF-8字节的严格JSON，形状/参数失败在任何Store调用前拒绝

新增筛选入口保持同源/owner边界，2–50成员、单系列20,000/总200,000行预算。每请求每成员一次计数、紧凑加载、原件验证和规范化，返回旧集合基线及新筛选证据；不因规则复杂度二次读取。不增加持久缓存或通用队列。

请求严格拒绝未知/重复参数、无效ISO日期、重复版本、非法窗口和不支持周期。集合2–50个不同证券，单系列20,000源行、总200,000；按截止范围预检再加载。原件损坏或预算失败整份请求失败，不默默丢掉证券。前端取消等待不等于服务端已停止计算。

结果包含 `method_id/analysis_id/inputs/parameters/mode/limitations/result`；inputs保留有序的版本和query身份，analysis身份绑定方法、输入和全部参数。左右互换、截止变化和集合成员变化产生不同研究身份；集合仅调整传参顺序不改变身份。所有错误返回简洁原因码，不泄漏原始路径或堆栈。

递推从同一版本起点计算到截止，不接受图形序号窗口重新初始化。每次请求校验原件；单次请求可以复用已校验上下文，不跨请求缓存绕过原件变化。输出紧凑，不逐行重复全部窗口。

内部 `_research_query` 只投影研究所需列，直接保留 DuckDB Decimal，省去公开查询所需的质量汇总与全字段合计；完整 metadata、tokens/checks、源序号、NULL/未定位行、全批覆盖与来源身份保留。结构损坏的 checks/tokens 明确拒绝，不能因减少物化提升来源资格。全部成员先计数，再逐个校验原件与读取，任一失败整份失败；不缓存原件资格、不截取最后 W+1 行替代完整前缀。公开 `query`、`export_json`、`export_parquet` 和身份算法不变；完整/紧凑 HTTP 响应字节经独立差分复验。见[限定方案](plans/2026-10-11-compact-research-reads.md)与[实现复验](reviews/2026-10-11-compact-research-reads-review.md)。

SQL范围下推必须保持旧语义：`label=NULL`不被cutoff悄悄排除、完整`batch_unlocated_rows`计数、准确源序号边界、稳定排序、质量/汇总、`query_id`和导出一致。旧接口超过20,000行的历史上下文问题另行解决，本轮新请求限额不假装修复它。

## 8. 写入、进程锁与恢复

- 数据目录仅一个应用进程持有独占锁：Windows保留`msvcrt`，POSIX使用非阻塞`flock`；加锁/初始化失败关闭句柄，POSIX锁文件不删除。只承诺实测本地文件系统，不承诺跨OS网络共享互斥。
- 采集/解码子进程不直接写数据库。原件在同卷暂存并核哈希，唯一写者在同一事务提交批次、引用、版本、幂等结果、覆盖与作业状态。取消在提交前生效，进入提交后报告实际结果。
- 请求幂等身份含来源和请求语义，内容哈希区分源修订。同内容不重复发布；未知刷新/发布保留原作业核对，不靠重启/换数据根发新请求。
- 覆盖按证券/周期/分片记录，只有成功提交才推进。部分失败不能被其它证券最大日期掩盖；回查修订窗口按已测来源规则确定，旧区间未检查范围明确显示。
- 已引用原件缺失/损坏阻止相关版本读取；未引用临时文件不能自动晋级。磁盘满、提交前后崩溃、文件锁、坏对象、WAL和恢复分别测试；原子重命名不等于硬件断电保证。
- 采用离线一致备份：停止新写入、完成/取消在途作业、正常关闭数据库后复制DB与所有引用原件/清单，恢复到新空目录并核对。不完整恢复拒绝打开；崩溃状态不得丢弃WAL。[DuckDB并发](https://duckdb.org/docs/current/connect/concurrency)、[WAL](https://duckdb.org/docs/current/operations_manual/footprint_of_duckdb/files_created_by_duckdb)、[CHECKPOINT](https://duckdb.org/docs/current/sql/statements/checkpoint)
- Authorization、Cookie、登录响应、密钥和短期签名URL不进入原件、清单或日志。客户端适配仅使用明确行情方法，不开放任意方法或账户/交易入口。

### 有界公开来源采集

固定腾讯日线、新浪 1m/5m 最近窗口请求；不接收任意 URL、不重定向、不继承环境代理/凭据/CA，不自动换源。父进程监督独立 worker；15 秒单次截止、180 秒命令截止及最多 10 次发送，发送预算先持久化，跨恢复累计。可信来源限制状态按独立 blocked 记录停止；网络异常不能推断为限流。详见[接入方案](plans/2026-10-11-automatic-market-data.md)和[实现复核](reviews/2026-10-11-automatic-market-data-review.md)。

计划、日志、发送预留与原件使用受限目录操作、禁止符号链接跟随并同步落盘；能力不足在联网前拒绝。当前 Windows 缺少此新路径所需能力，返回 `durability_unsupported`，未建立 Windows 自动采集资格。唯一写者沿用 Store，恢复优先核对已有捕获/提交结果，不能把未知结果当作未提交后重新发送。

严格网络捕获使用 `public-market-capture-v1`；旧原件离线重建为 `public-market-legacy-reconstruction-v1`，合同与 raw/batch/snapshot 身份不同，明确头数量未记录、运输证据未建立。legacy 不可被网络恢复接管。腾讯较早上下文完整入库，目标视图仅显式映射原序号，不改变完整 query 或研究前缀；数量 token 保留，未核单位的数量/金额列为 NULL。

当前真实首发在隔离 worker 中返回净化的 `transport_network_error`，持久发送计数为 1；该记录不能定位 DNS、路由、CA 或来源原因。无响应/捕获/数据版本，新浪未发且未重试。详细证据见[新命令真实验收](qualification/public-acquisition.md)。后续须在受支持的环境条件下另行验证，不因旧网络脚本可用而降低隔离或运输要求。

## 9. 日历、复权与后续交易评价

这些是后续能力必须满足的设计条件，不代表当前全部实现：

- 交易规则按市场、品种和生效日期管理；集合竞价、连续竞价、午休、盘后和临停分别处理。“每日240根”只能作容量估算。
- 重采样先核同证券、同来源版本、同复权和成交覆盖，再按合法时段分桶；不跨午休。OHLC按顺序定义，量额守恒，缺失输出覆盖与部分状态；日/分钟只有同口径时才能直接对账。
- 原始未复权价和公司行动分开保存；复权视图绑定事件、算法、锚点和股本规则。成交价、收益价和执行约束价用途不同；价格复权不能随意施加到量额。
- 跨拆并股/送转边界先重新预热量能比较，保留原量和原因；无事件依据只显示可比性未知。手/股单位转换不与公司行动重复调整。
- 研究输出保留目标总体、全部候选/参数尝试、时间划分、基准、有效/排除覆盖和失败状态。训练相关转换不能读测试集；查看测试后修改即转开发数据。
- 成交评价需历史可交易规则、停牌/涨跌幅、数量单位、费用、滑点、容量、持仓现金和公司行动。OHLC不能确定柱内先后/限价排队时给可行区间或说明假设，不伪造唯一成交。当前描述性事件不扣一笔任意费用后改称净交易收益。
