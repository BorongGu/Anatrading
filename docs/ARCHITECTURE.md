# Anatrading 架构设计

状态：v0.1，提交独立反方评审的草案。2026-10-03。目标与范围以 [总体方案](MASTER_PLAN.md) 为准。**当前业务编码冻结。**

## 1. 核心决策

| 决策 | 草案选择 | 取舍与替代方案 |
|---|---|---|
| 部署 | 单用户、本地 Windows 优先；浏览器工作台 + 本机服务 | 用户已确认；全市场日线加自选股分钟数据 |
| 组织 | 模块化单体，数据连接器可按 SDK 要求隔离小进程 | 先保持一个可安装应用与单一数据所有者；已有大规模并发证据后才评估服务拆分 |
| 语言 | Python 数据与研究内核；TypeScript + React 交互 | 指标真值只有后端一份；浏览器浮点仅用于坐标和显示 |
| 存储 | 原始字节内容寻址 + 不可变 Parquet 数据段 + DuckDB 目录/查询 | 大行情不塞 JSON；不同时引入第二个元数据库；单写入者简化一致性 |
| 计算 | Python Decimal 参考实现；批量查询/扫描用 DuckDB，向量化按测量选择 | 不承诺 SQL DECIMAL 的除法仍精确；加速实现必须对照参考计算 |
| 界面 | 可审计图表、因果回放、研究工作区；成熟开源图表库 | 图表渲染复用，交易语义自有；暂不自研绘图引擎或脚本语言 |
| 接入 | 按接口和版本建立能力契约；官方/本地优先，导出文件为对账入口 | 各源独立存储；替换必须显式；开源第三方适配器不代表行情许可 |
| 研究 | 描述、假设检验、交易评估分层 | 原始事实和模型输出可同时查看；每个输出声明证据级别 |

Python 具体运行版本在 G1 官方 SDK 兼容探测后锁定；目标研究内核采用仍受支持的 64 位 Python。若某 SDK 仅支持特定版本/位宽，适配进程负责转换，不把其环境限制扩散到研究内核。尚不锁定 Polars/pandas 等第二套大表计算框架。

## 2. 依赖方向与模块所有权

数据流：**采集/导出 → 原始证据 → 标准化与质量审计 → 版本化数据集 → 描述/研究/成交评估 → 工作台**。

| 模块 | 拥有的职责 | 输入 → 输出 | 禁止越界 |
|---|---|---|---|
| 接入 adapters | 接口调用、分页、限速、SDK隔离、文件解码与源字段说明 | 请求范围/原文件 → 原始响应与采集清单 | 不偷偷复权、填缺失或合并不同供应商 |
| 主数据 reference | 证券历史身份、交易日历/时段、状态、公司行动、股本、成分 | 官方或获准来源事件 → 带有效时间与已知时间的版本 | 不把当前状态应用到全部历史 |
| 标准化 normalize | 单位、时间、数值、主键、部分柱和修订映射 | 原始证据 + 契约 → 标准观察值与转换账本 | 不删除异常以美化曲线 |
| 质量 quality | 硬错误、语义冲突、缺失、对账、采集覆盖与资格 | 标准值 + 主数据 + 对照 → 报告与字段级能力限制 | 不产出买卖信号 |
| 目录与查询 catalog | 数据清单、版本、血缘、快照、查询截止、唯一写入 | 已验证候选段 → 可复现快照 | 不接受未完成片段；不在查询时静默改源 |
| 描述 features | 因果指标、K线几何、量能/波动/结构、定义与可用时点 | 快照 + 参数 + 截止时点 → 特征/状态/不可用原因 | 不负责下单和收益评价 |
| 实验 research | 事件研究、基准、消融、参数登记、时间划分、统计检验 | 冻结协议 + 时点数据 → 版本化研究报告 | 不根据测试集反复修改后继续称留出检验 |
| 成交评估 simulation | 成交约束、订单意图、账户现金/持仓、费用、成交日志 | 已可得信号 + 规则/成本 → 成交、拒绝与组合轨迹 | 不从单根 OHLC 猜出唯一真实成交路径 |
| 组合 portfolio | 暴露、风险预算、再平衡、归因、情景 | 持仓/收益/成本 → 组合研究结果 | 不重写价格和公司行动事实 |
| 应用 application | 用例编排、作业状态、取消、导入/更新/回放/实验API | 用户操作 → 确定的数据版本与结果 | 不内嵌另一份指标公式 |
| 工作台 web | 图表联动、交互、证据与质量呈现、条件编辑 | API → 可核对的人机界面 | 不作为研究真值或获取凭据的公共服务 |

以上为逻辑职责，初期可以由少数文件承担；不要求每项成为服务、包或抽象基类。只有第二个实际实现出现后才提取共享接口，先保证契约明确。

## 3. 数据分层与核心实体

| 层/实体 | 必须保留的内容 | 版本原则 |
|---|---|---|
| 原始证据 RawObject | 原字节、SHA-256、来源/接口/版本、采集参数、采集时间、内容类型、许可引用、编码/精度说明 | 同内容去重，禁止原位改写；URL不是可复现证据的全部 |
| 接口契约 SourceContract | 支持品种/周期/历史范围、量额单位、价格调整、时区、柱标签、成交类型覆盖、是否补值、更新频率/延迟、权限 | 契约变化产生新版本；按接口版本细分，品牌名不足以确定语义 |
| 标准观察 Observation | 证券ID、市场、事件类别、区间起止、OHLC、量/额、覆盖标签、闭合状态、来源指针、质量位、源修订号 | 同一经济时刻可以有多源与多版本；不互相覆盖 |
| 主数据事件 ReferenceEvent | 身份/股本/分红送转配股/停牌/规则等，effective_at、published_at、observed_at及时间证据 | 时点查询；未知时间保留未知，不伪造历史 |
| 数据快照 DatasetSnapshot | 参与的数据段、主数据/契约/规则版本、选择策略、查询范围、known_at、质量资格、内容哈希 | 已引用快照不可变；新修订生成新快照 |
| 特征与事件 FeatureEvent | 方法版本、参数、输入快照、值、单位、确定/估计类别、confirmed_at、不可用原因 | 可重算；窗口或确认规则变化产生新方法版本 |
| 研究运行 ResearchRun | 研究假设、候选参数集合、训练验证测试划分、基准、成本、所有试验、代码/环境/随机种子、输入快照 | 结果与失败均保留；不能只存最佳参数 |

标准观察经济键建议：`instrument_id + venue + event_type + period_start + period_end + session_coverage`。来源观察键再增加 `source_contract_id + source_revision`。缺少稳定源修订号时，以内容哈希区分观察版本，不能按“后来的值更正确”自动覆盖。

证券身份用稳定内部 ID 与有效日期映射；代码、市场、名称、板块、ST状态和上市/退市日期为属性。不能只用六位代码当跨市场永久身份。

## 4. 时间模型：数据何时发生，何时能够知道

| 时间 | 含义 | 使用规则 |
|---|---|---|
| period_start / period_end | 柱覆盖的交易区间，保留源端点/标签约定 | 柱闭合前不当成最终柱；集合竞价/盘后可独立事件或明确并入口径 |
| event_time / effective_at | 逐笔发生或主数据变化生效时刻 | 不能据此推断信息已公开 |
| published_at / available_at | 源首次公布/可取得的时刻及其证据 | 未提供时允许空；日线收盘时刻不能替代真实发布时间 |
| observed_at | 本工具实际取得该版本的时刻 | 必须记录；不能用它倒填原始公布时间 |
| known_at | 实验假定决策者的信息截止 | 同时限制观察版本、主数据、特征确认与训练样本 |
| confirmed_at | 一个结构/事件被规则确认的时刻 | 右侧 N 根确认的拐点只在 N 根之后可知，不回填为当时信号 |

两种研究模式分开：

- **历史形态复盘**：允许查看目前能获得的历史版本；界面声明可能含事后修订/复权。适合描述，不能自动获得时点策略资格。
- **时点研究**：只有可证明在 known_at 前可得的数据版本、规则与证券池进入；对旧数据无法证明的公开时间采用明确假设并标记证据级别。相关结果只能在假设边界内解释。

测试“追加未来数据不改变过去特征”只能证明特征算法的一类因果性质。还需验证数据修订、公司行动、历史成分、公告时间和训练选择，才能支持时点研究结论。

## 5. 数值、精度和缺失契约

1. 原始文本/二进制保持不变。原始金额 float32 的精度损失必须记录；转成 Decimal 不会恢复信息。
2. 价格和金额规范层使用带 scale 的定点/Decimal；成交量使用整数基本单位。先保留 source_unit，再转换 standardized_unit；单位倍率只能来自已验证的接口契约。
3. Parquet 使用 Arrow Decimal，按数据契约固定 precision/scale 并验证无损转换。超精度/溢出隔离，不静默截断；原始证据仍可查询。跨 scale 计算先显式提升到足够精度。
4. 加减汇总需要守恒，除法结果允许有限精度表示并携带舍入规则。**DuckDB DECIMAL 除法返回近似浮点**，金额/量的参考计算留在 Decimal 层；大规模浮点派生值记录误差预算并对照参考实现。[E2]
5. API 对大整数/十进制真值使用字符串或带 scale 的显式结构；浏览器数字用于坐标，原值提示与导出保留精确表示。
6. 值状态至少区分：真实零、缺失、停牌/非交易、源补值、部分柱、错误、无法定义。返回空值必须给出原因。
7. 确认真实零成交且历史参考分母大于零时，RVOL=0；成交量分位仍可定义。零量的金额/量均价不可定义；未知缺失不能填为零；历史量分母为零时 RVOL 为空。
8. 百分比、小数比例、元/万元、股/手、每百万人民币的流动性代理必须在字段和界面同时标明。金额一致性阈值随源精度和覆盖定义，不全局固定一分钱。

## 6. 交易日历、复权与重采样

市场规则是带生效日期和品种条件的主数据。连续竞价、开收盘集合竞价、午休、盘后固定价格、临停等分别编码；规则更新要有来源。当前计划不能依赖固定“每日240根”作真值，该数字仅用于常规容量估算。

重采样前验证同证券、同版本、同复权、同源定义、同交易类型覆盖。以交易时段分桶，不能跨午休拼出一根连续区间。开/高/低/收按有定义的交易顺序计算，量/额求和；缺失子柱输出覆盖比例与 incomplete 状态。分钟汇总与日线的量额守恒只在两者覆盖的交易类型一致时要求成立。

保留未复权成交价格与公司行动事件。前/后复权价格为派生视图，包含算法版本、锚点、事件版本、股本规则；价格复权不能随意作用到成交量/额。收益价格、成交价格、执行约束价格用途分开。配股信息不全时不能声称生成了完整复权序列。

## 7. 自动采集与发布流程

1. 根据已合格的 SourceContract 检查品种、周期、可用范围、权限和版本。
2. 建立请求清单与幂等标识；按源明确限速，记录请求/响应时间与失败。
3. 写入原始证据，校验长度/内容哈希；SDK进程崩溃也不能提交半文件。
4. 解码、规范化、质量检查；异常保留并分为文件不可用、字段不可用、带标记可观察三类。
5. 与既有版本比较：全同去重；源修订追加；冲突未解释时不晋级。
6. 将候选 Parquet 段写到临时区，完成校验并原子重命名后，由唯一目录写入者在事务中发布快照。
7. 成功发布才推进采集水位。定期回查一个**源特定**的重叠窗口用于修订发现，窗口依据已测修订行为；不能假定最后一根之后全无变化。
8. 源失效保持旧数据并显示最后成功时间，暂停相关“当前”结论；切换来源生成新快照和差异报告。

崩溃恢复：目录未引用的候选段视为待核验，不自动变成正式数据；恢复时检查哈希与任务账本。目录已引用的缺失/损坏段阻止相关快照查询。垃圾回收需确认无快照/研究运行引用，保留可恢复期。

只有主应用进程打开 DuckDB 读写目录；采集/计算子进程不直接写目录，返回候选结果供主进程提交。读查询在同一进程使用独立连接，避免跨进程读写锁冲突。[E1] 初期一个作业队列和状态表足够，无需外部消息中间件。

## 8. 存储布局、查询和缓存

逻辑布局：`raw/<sha>`；`segments/<immutable-id>.parquet`；`catalog.duckdb`；`runs/<run-id>/`；`quarantine/`；`backups/`。均在个人数据目录，默认不提交 Git。分区先按来源契约、周期与日期范围，证券排序，避免“一证券一天一个小文件”；具体行组/分段大小在 G1 容量基准后固定。

查询必须包含数据快照和时点/复盘模式。显式投影字段与过滤区间；图表按可视窗口取数，缩小显示时按合法交易时段重采样，不能把价量简单抽点后仍称 OHLCV。[E3]

缓存键包含：输入快照、方法版本、参数、证券池/规则版本、known_at。不能只用证券代码与日期做缓存键。UI与导出使用同一查询结果；所有未来列在回放截止处受一致限制。

## 9. 研究与成交评估边界

特征接口约定输入快照、参数、截止与缺失策略，输出值、单位、有效样本数、不可用原因和确认时间。多个周期联动必须使用在截止时刻已闭合或显式标记部分的柱；不能读取尚未完成的当日日线高低收。

去噪是一种带代价的方法选择：原值保留，输出标记窗口、滞后、相位/确认延迟和参数。不能因平滑后“更像趋势”而认定更有决策价值。先定义任务，再比较未处理基准、简单替代和候选方法。

研究输出至少包含：样本覆盖与排除原因、训练/验证/测试区间、相关/重叠样本处理、全部参数尝试、基准、置信区间或不确定性方法、成本与执行假设、失败区间。市场级结论需要时点证券池/退市样本；缺少时降为明示自选池的探索结果。

成交评估消费已可得的策略意图，处理按日期/品种适用的买卖制度、涨跌幅/价格笼子、停牌、订单最小数量、税费、手续费、滑点、成交容量、公司行动和现金。若 OHLC 无法判定止盈止损先后或限价排队，输出可行区间/保守假设并披露，不能伪造唯一精确成交。首期不自动连接实盘下单接口。

## 10. 可用性与失效呈现

数据源中心展示最近成功、已覆盖区间、真实源周期、延迟类别、版本、质量与授权状态；研究台展示当前周期和数据口径、单位、方法说明、数据截止、证据级别。对部分/缺失/修订数据给出就地提示，不能仅在日志里出现。

界面首批工作流：一次配置合格来源 → 更新日线与关注池分钟 → 查看数据审计 → 日线定位 → 分钟联动回放 → 标记/研究事件 → 导出同版本结果。高级指标与多面板分层展开；不以大量同时显示的指标替代信息筛选。

## 11. 验收、发布与原型处置

每个核心模块有独立事实用例：手算/源字段比对、时间/单位边界、变异数据、版本修订、前缀不变、完整/缺失交易时段、存储崩溃恢复、备份恢复。图表需实际浏览器验证，接口绿色测试不能代替交互验收。

真实数据矩阵按软件/版本/接口/品种/周期/复权分格，区分：第三方公开样本、当前客户端真实导出、同版本接口与导出对账。公开仓库样本证明样本兼容范围，不能给同一品牌全版本担保。

代码、文档、研究配方与测试可公开；个人行情和受限数据留在本地。公开测试数据仅限许可明确的再分发样本或自造边界样本；其他真实样本记录源链接、哈希、获取过程和本地验证报告。

现有实验原型候选保留项：显式单位、原字节哈希、基础 OHLC 不等式、独立手算、因果前缀检查。必须重审项：固定交易时段、固定金额阈值、每数据集 JSON 存储、缺少版本/主数据/修订时间、原型数据资格、Python/前端依赖版本。未经 G0 审核不能直接继续扩展。

## 12. 外部技术依据

- [E1] [DuckDB 并发模型](https://duckdb.org/docs/current/connect/concurrency)：本文采用单进程读写模式；不依赖其新的远程多进程能力。
- [E2] [DuckDB 数值类型](https://duckdb.org/docs/current/sql/data_types/numeric)：定点除法会转近似浮点，精度上限与开销需要明确。
- [E3] [DuckDB Parquet 查询](https://duckdb.org/docs/current/data/parquet/overview)：支持列投影、条件下推，是否跳过行组取决于文件元数据。
- [E4] [Arrow Decimal128](https://arrow.apache.org/docs/python/generated/pyarrow.decimal128.html)：带精度/尺度的缩放整数表示，不能超出声明范围。
- 数据、论文与交易制度依据见研究文档 [001](research/001-data-and-price-volume.md)、[002](research/002-data-access.md)、[003](research/003-volume-microstructure.md)、[004](research/004-data-validity-and-evaluation.md)。002–004 为并行研究，成稿后复核本草案。
