# Anatrading 总体方案

更新：2026-10-11。现行实施顺序见[路线](ROADMAP.md)；本轮以[研究工作流方案](plans/2026-10-11-research-workflows.md)和[最终编码前复核](reviews/2026-10-11-research-workflows-review.md)为准。首版日线算法、API、界面与 Linux 通用修复已实现；第二批内部紧凑读取和分钟 A 纯函数通过冻结版本回归，紧凑读取合成性能复验支持保留该优化。第三批有界取数与格式已通过本地回归及独立实现复核，旧真实捕获完成限定离线验收，新命令真实网络尚未成功。完整验收仍有开放项。早期评审、取舍和原型处置见[历史决策](REVIEW_DECISIONS.md)，不将其初稿冻结状态延续为当前停止编码。

## 1. 目标与优先级

做个人可运行的股票研究工具，先服务 A 股，逐步扩展国际股票。用单股日线、单股分钟、双股日线、多股与明确成员的板块日线，回答当前状态、条件如何确认、历史结果如何、何时失效。完整目标覆盖日内研究、中长期择时与组合；优先日线判断波段、分钟选择时机与复盘。

算法与可验证功能优先于新增基础设施。每次交付连接输入、研究结果与反例，保持代码直接、可维护，性能以实际测量为依据。界面用自然中文和清晰字体，先呈现结论与图，再展开原始记录、数据版本和计算说明。

A 股完整范围仍为沪、深、京股票，历史研究需要退市、身份沿革和按日期确定的证券池。部分来源、几只自选股或当前板块成员都必须如实标明范围。国际股票扩展需分别确认数据使用权、证券身份、币种、时区、日历、公司行动和交易制度；相同日期标签不能代替跨市场同步。指数、ETF等另列资产类型，不套用股票量额定义。

一套代码库的通用功能支持 Linux/Windows，Windows 通达信客户端使用专用适配器。仓库为私有；真实行情、账户数据、密钥和本地运行产物不提交。自动实盘下单不在当前范围。

## 2. 三种结果分别验收

| 结果 | 用户得到什么 | 必须具备的依据 |
|---|---|---|
| 描述事实 | 价格结构、量能、波动、缺口、样本关系与覆盖 | 原始字段、公式、单位、输入版本、截止和不可计算原因 |
| 研究假设 | 条件出现后价格变化与基线的关系 | 预先固定定义、完整样本计数、时间分区、重叠处理、反例及不确定性 |
| 交易方案评价 | 成本、仓位、交易制度和不可成交情形下的结果 | 历史当时可得的数据、执行模型、费用、容量、样本外与纸面验证 |

描述工具即使没有预测增量也可能有用。界面允许“未检验”“暂无证据”“失效”，不把统计数字合成未经验证的买卖评分。计算通过、真实来源兼容和预测价值分别记录。

## 3. 本轮交付

- **个股研究**：日线固定参数 Kalman 与同尺度 EMA；原始收益 EWMA 波动；此前 N 根最高价突破；成熟后续 1/5/10/20 来源记录步的变化、全部合格日期基线与失败样本。无显式测试起点时只输出全段描述，参数不自动优化。
- **双股对比**：先对齐共同日期，再计算相同区间的收益相关/beta、相对强弱和此前窗口拟合后的偏离。保留缺失/重复/退化原因；不输出协整、均值回归或套利结论。
- **多股与板块样本**：身份明确的不同证券、同一截止日期，计算动量/波动/最大回撤及分项排名；分别报告有效数量和全部所选数量。板块是用户明确提供的成员样本，不推断历史行业成分。

以上已接入 API/界面的新研究只做日线，新增分钟 A 仅在独立纯函数中实现。每系列最多 20,000 源行，每请求总计 200,000，集合 2–50 个不同证券版本；超限明确拒绝，不截短递推历史冒充相同方法。双股和集合首版要求同一市场，沪/深/京均属于 A 股市场；跨市场相同日期标签仍不足以证明同步。详见[026 算法定义、文献与边界](research/026-causal-signals-and-evaluation.md)。

当前研究沿用 `retrospective`：只对提供的数据版本作历史描述。算法不读未来输入，与历史版本在当时已可得，是不同的保证。

实现后[独立复核](qualification/research-implementation-review.md)已关闭来源证券冲突、复权冲突和已隔离来源被重新取得研究资格的问题。来源声明矛盾或已隔离的记录保留原值与日期槽，同时失去研究资格并中断对应状态/窗口；复盘模式不放宽这一要求。

### 第二批有限扩展

内部紧凑读取减少研究路径的无用字段物化，公开 query、JSON/Parquet 导出、精确源值、来源资格和研究身份不变；完整 tokens/checks 与逐请求原件校验保留。限定方案、独立正确性复验和合成性能保留条件均已完成，见[紧凑读取方案](plans/2026-10-11-compact-research-reads.md)、[复验](reviews/2026-10-11-compact-research-reads-review.md)和[性能记录](qualification/research-performance.md)。

[028 分钟 A](research/028-intraday-research-candidates.md)实现固定来源模板下、单日期同覆盖 1/5 名义分钟收益平方和与采样敏感性；[独立复核](reviews/2026-10-11-intraday-candidate-review.md)接受其纯函数和测试。当前无 HTTP/UI、跨段收益/合计或实时闭合认证，B 同槽量和 C 日线联动仍需独立合同。真实来源、用户任务效果和预测增量不随数学验证获得资格。

### 第三批有界取数

已实现腾讯日线与新浪 1m/5m 最近窗口的固定格式、`acquire-public`/`resume-public`、持久发送预算及恢复；范围见[接入方案](plans/2026-10-11-automatic-market-data.md)和[独立实现决定](reviews/2026-10-11-automatic-market-data-review.md)。用户显式股票声明不升级为已核实品类，数量字符串保留但标准数量/金额为空，源价格与完整上下文不变。Windows 新采集因目录安全/同步能力不足在联网前拒绝，不影响原有通用研究功能范围。

40 份旧真实捕获使用单独 legacy 身份，首次入库、重复复用、重开与逐 token 对账通过；38,900 原始行和 34,205 目标视图分别报告。旧记录不补造 HTTP 头数量或新运输保证。新 CLI 首次腾讯日线请求网络失败，0 响应/捕获/数据版本，发送预算记 1，新浪未发且未重试；网络原因尚未确认。该边界见[格式与来源验收](qualification/public-market-formats.md)和[新命令真实验收](qualification/public-acquisition.md)。

## 5. 竞品对标与差异化

[027 竞品工作流研究](research/027-competitor-workflows.md)汇总 2026-10-11 实际核查的一手资料和读取范围。通达信已有跨股/板块公式；同花顺已有自然语言选股；东方财富/Choice已有组合筛选和数据研究；TradingView已有扫描与含执行假设的策略模拟；AmiBroker已有历史探索和滚动样本外；QuantConnect已有配对统计研究示例。不能把同类功能的存在写成原创优势，也不能因未读到资料而判定竞品没有某能力。

每个对标项记录产品/版本、权限、数据、公式公开程度、未来信息风险和待核项。文档事实、设计推断、客户端实测分开；商业黑盒可作输出对照，缺少定义时不宣称完全复现。广覆盖样本框保留于[国内矩阵](research/006-domestic-capabilities.md)和[国际矩阵](research/007-international-capabilities.md)，不声称穷尽全部软件与套餐。

采用同数据、同截止、同公式和同任务的比较：

1. 找到一次突破，说明发生/确认/失效，并检查相同定义的历史命中与失败样本。
2. 比较事件后续变化和基线，核对未成熟、缺失和时间分区。
3. 比较两股，解释对齐遗漏、收益相关与价格偏离的区别。
4. 比较指定集合或板块样本，核对日期、重复证券、广度分母和覆盖。

记录首次正确完成耗时、操作量、需编写代码量、数值一致性和解释完整性，不预填获胜结果。预测增量另行冻结实验、比较简单基线与成本后可执行性；没有改善时保存负结果。当前没有全面超越或收益优势的结论。

## 6. 数据与技术选择

优先用户有权使用的免费来源、同花顺/通达信本地文件与官方接口；导出文件用于逐字段对账。开源许可、接口费用、本地使用权和再分发权分别核验。某接口存在不代表其所有周期、字段或历史范围可用。

既有 Windows 通达信日线缓存/有限采集的真实记录继续有效于各自报告范围；分钟、持续更新、全市场和当前软件全面兼容仍需单独验收。BaoStock 既有捕获响应可以导入，不因此变成自动生产采集器。源失效保留旧数据并显示最后成功，不静默换源或把旧缓存称为最新。

历史回补、盘后分钟和盘中闭合分钟分别验证。OHLCV 不足以还原逐笔路径、真实主动方向、挂撤单或交易者身份；金额/量均价需要同口径字段，复权和股份变化另行处理。缺少数据不生成确定性解释。

腾讯/新浪第三批代码与本地故障注入通过；仓库外旧原件已取得限定离线格式/存储兼容资格。新隔离运输不继承环境代理或 CA 配置，当前首发网络错误无法定位到 DNS、路由或来源侧，也没有来源限流证据。旧脚本成功不替代新 CLI 验收；真实原件、库和派生行情均不提交。

保持本地模块化单体：Python 数据/研究计算，FastAPI 本机服务，React/TypeScript 交互，DuckDB 单写入者，原始字节按哈希保存，Parquet 导出。复用成熟 K 线绘图组件；前端不重算统计真值。外部 Parquet 主存储、分布式服务、自动 GC、在线压实和持久特征缓存继续留待实际瓶颈，不为本轮建立通用框架。详细约定见[架构](ARCHITECTURE.md)。

## 7. 研究与实施约定

每个新方法先写研究卡：用户问题、竞品定义、实际读过的一手文献范围、数据可识别性、公式/参数/时点、简单基线、失败条件、复杂度和验收。摘要不记为全文，阅读篇数不代替依据。新总体方案/架构及具体功能须独立反驳、逐项答复、修订和记录最终决定；历史 G0 的多方评审要求与原型处置记录保留。

实现按已批准范围推进。没有真实数据时可以完成数学和工程验证，真实兼容与有效性保持开放。研究协议要隔离训练/验证/最终测试，剔除跨分区标签，记录已查看/已用于选择的留出数据，保存全部参数和人工试验。前缀不变性不能取代公司行动、历史成分、发布时间和训练选择核验。

不自动删异常、补零、填缺失或抹平有效跳变。所有空结果有原因，原件和原始精度不变。分钟聚合、累计量转换、份额变化、复权与指数单位分别有定义，避免用统一倍率或每日固定柱数替代真实语义。

## 8. 性能与发布验收

当前 Linux 全套 Python 为 1,937 通过、0 失败、49 跳过、1 项依赖弃用警告（68.86 s）；跳过项为 48 项私有真实样本及 1 项 Windows 原生进程证据。前端本片未修改，最近一次 72 项通过、无失败或跳过，TypeScript/Vite 构建通过，仍有主包体积及 npm 环境配置警告。第三批按独立复核冻结实现执行。全部 public 455 项通过，其中独立对抗 173 项；既有紧凑读取 300 项和分钟 A 124 项复核保持原报告范围。这些定向子集不与全套计数相加；无 GitHub CI 通过声明。

5,000/20,000 行、W20/W252、最大总行数与成员数的合成公式/ASGI 复验已完成；39 次正式请求成功，完整/紧凑结果、原件和身份相同，主矩阵响应与旧基准逐字节一致。两种 200,000 行集合分别从 15.298 s 降至 11.988 s、14.719 s 降至 12.888 s，均为三次样本中位数。有限优化满足保留条件，仍有十余秒等待；ASGI 不包含实际网络、浏览器解析/绘图或并发排队，不能外推 p95。完整环境、阶段耗时、响应体积与限制见[性能记录](qualification/research-performance.md)。

紧凑输出不逐行复制全部窗口成员。20,000 行响应体积目标不超过 5,000 行的 4.5 倍；当前响应接近四倍且保留原响应字节。后续继续测实际 HTTP、并发/尾延迟、峰值内存与浏览器；O(nW) 最大窗口已纳入本次 ASGI 矩阵，进一步优化仍需独立数值参考。

既有设计目标仍为单证券查询 p95 ≤ 500 ms、首次可交互 ≤ 2 s；它们是目标，旧浏览器报告已有超时结果，本轮尚需重新测量。历史分钟容量估算、源响应耗时和单次公式测试不能代替端到端性能。

最终报告分别列：数学/异常/前缀测试、HTTP安全与资源边界、前端测试/构建、真实浏览器、Linux进程互斥与恢复、Windows原生、真实样本、性能和预测验证。界面切换、左右交换、集合增删、空结果、错误、窄屏和键盘操作都有验收；没有实际浏览器就不标界面已通过。
