## 1. 值得做什么，哪些收益尚未证明

这是一个体量适当的解释性基线。现有 `universe_report` 按每股最后 N+1 个来源日期取窗，真实起点可能不同；`pair_report` 的 normalized-price relative 则是比值变化，窗口和单位均不同。新增明确 a/b 可以关闭实际比较错误，并帮助回答“上涨却落后同伴”“下跌却较抗跌”。禁止把旧 momentum 字段直接相减是正确决定。

方向并不新颖。[StockCharts Performance Spread](https://chartschool.stockcharts.com/table-of-contents/technical-indicators-and-overlays/technical-indicators/performance-spread) 已定义同一时期两者百分比变化之差；[TradingView Compare 官方说明](https://www.tradingview.com/support/solutions/43000543053-how-to-use-the-compare-tool/) 已提供多个品种在可见区间的百分比比较。此次实际阅读日期均为 2026-10-11。可争取的阶段增量是固定端点/成员、可追溯版本、失败不改分母及同时显示两种基准；本文没有证明 TradingView 缺少这些能力，也没有进行它的完整功能实测。

对用户长期对标并超越 TradingView 的目标，A 可以作为较小的基础能力；单独增加一个数字或一张排名表不足以形成优势。首先应在预先选定的案例中证明它减少了具体误读。无需把首片扩成因子平台，也无需等到 alpha 已证明才允许来源研究。

### 已独立核对的数学

- 在同一完整 G 上，leave-one-out 均值差和中位数差均保持原始变化的严格顺序及并列。除了纸面核对，还对 N=4…7、每股变化取 `{-1/2, 0, 1/10, 1}` 的 **21,760 个有理数组合**穷举，全部满足顺序及并列不变。该结果不授予不同集合、缺失后变动集合或不同区间的可比排名资格。
- 目标 5%，九个同伴 `[0,1,2,3,4,5,6,7,80]%`：中位数差精确 +1 个百分点，等权差精确 −7 个百分点。保留极端同伴并同时报告两者有实际解释价值。
- 10% 对 5%：变化差为 5 个百分点；相对财富比变化为 `1/21`，约 4.7619%。[Price Relative 官方页面](https://chartschool.stockcharts.com/table-of-contents/technical-indicators-and-overlays/technical-indicators/price-relative-relative-strength) 的示例文字确实将二者混写；030 已明确纠正，不能在实现时重新混用。
- N≥4 是产品工程下限，不能当统计充分性。删去一个同伴后的敏感性检验可在 N=4 时临时剩两个同伴；它只属于测试/诊断，不能因此开放不足三个同伴的正式主比较。

## 2. 现有实现给出的具体约束

已读根 `AGENTS.md`、026/029/030、初始数据合同、研究工作流/精简读取评审，及 `pair_research.py`、`universe_research.py`、`research_series.py`、`research_api.py`、`store.py`、`numeric.py` 和腾讯候选格式/相关测试。

1. `daily_bars` 是 **完整正 OHLC** 的资格规则，非 close-only。实际构造 close=11、open 缺失的端点，结果为 `missing_ohlc`。直接调用它会比 030 的“两个正 close”要求更严格；绕开它又会失去来源冲突与重复处理。作者须选择，不能让代码偶然决定合同。
2. `daily_coverage.coverage_known` 只依据未定位行/批次未定位数量，不能认证完整交易日历。一个源 token 能读出为未来日期、但 label=None 的行，仍使它为 false。不能将这个全批布尔量直接当端点比较的资格开关。
3. `daily_bars` 先按 selection.cutoff 裁剪，日期之后的行级身份检查不再执行；`source_rejection` 又只直接处理 quarantine/known_negative。故“沿用归一化”不足以证明 030 所称全局矛盾已经检查。需要明确哪些矛盾是批次级、哪些是定位后的行级，不能把任意行失败一概升为全局或忽略。
4. Store 的 `query_id` 是 selection 的身份，非载荷内容哈希。`_research_query` 的 `daily_ohlc_input_v1` 保留完整来源 query_id，载荷省略 locator 等公开字段，但保留 ordinal、tokens、checks、metadata、counts、manifest。源行可以通过 snapshot/batch/ordinal 回查；不能虚构精简载荷已有 locator，也不能手工裁 rows 后继续声称 query_id 认证了完整性。
5. `symbol_identity` 能做符号/交易所声明规范化与重复检查；其 `CN_A` 只是市场分组映射，未验证品类或币种。独立实测 `900901.SH` 也返回 `market='CN_A'`。[上交所官方分类表](https://www.sse.com.cn/assortment/stock/areatrade/trade/detail.shtml?csrcCode=I65) 将 900901 列为云赛智联 B 股；[上交所股票介绍](https://english.sse.com.cn/markets/equities/overview/) 明确 A 股与以外币交易的 B 股有别。不能仅凭 SH/SZ/BJ 后缀认证 A 股或 CNY。
6. 腾讯候选 metadata 使用 `requested_adjustment='none'`、`coverage='unverified'`；合同的 price_unit、adjustment、closed、known_at 等仍 unknown。`unadjusted_request` 尚非通用现成字段。若直接要求原数据已经有此枚举、已知 CNY、已认证复权或 PIT，会误封当前真实样本。

以上均为新功能调用已有辅助函数时的适用边界，不意味着本次授权改写旧 pair/universe 或原来源合同。

## R1：输入查询范围与可信边界尚未冻结

**编码前阻断。** 两个端点并不需要整个历史路径参与数值计算，但需要知道输入是否人为隐藏了重复端点、未定位记录或资格失败。当前稿没有确定是否接受 cutoff<a/b、ordinal 裁剪、只有两个价格的手工 dict、或者多快照拼接后的伪 query。

建议首片选择最简单的已有路径：

- 每个成员只接受 **一个不可变日线快照的完整来源查询**，selection 为 retrospective、cutoff=None、ordinal_start/end=None；公开 query 和既有内部 OHLC projection 均可，纯函数绝不改写 selection/query_id。
- 必须有完整的 rows、unlocated、counts、batch_checks、metadata、manifest/来源合同及 source IDs。输入形状、计数非负、ordinal 正整数且全输入唯一、所列选择与身份对应关系先检查；缺失字段不能一律用“无异常”的空默认值补齐。
- 原件校验由现有 Store 每次加载执行，纯函数无文件系统、网络或时钟。合法 hash 字符串、重算 query_id 或调用者的 `verified=True` 都不能代替原件校验。合成单测可构造输入，但真实兼容验收必须走现有 Store 读取路径。
- 全成员原始输入行先完成 ≤50、每股≤20,000、总≤200,000 预检，再扫描/分组；先裁 `[a,b]` 后数行会绕过预算。本片只有 30×640 条上下文，完整快照选择不会因这三项上限阻断本批数据。
- a/b 是另传的计算日期，只用于端点和异常作用域；所有非端点原行继续属于被引用的来源版本。多块拼接仍需独立合同，本片不自动合并。

若作者希望接受 cutoff=b 的完整前缀，也可以另写清楚如何证明全局资格未被裁掉，并测试；没有必要在首片同时支持多种裁剪模式。仅向 `universe_report._at_cutoff` 仿写一段过滤并保留旧 query_id 不接受。

必要反例：只删一条重复端点；漏传 unlocated 但保留 batch_unlocated_rows；cutoff<a、a≤cutoff<b；两个快照拼成一只股票；同一 ordinal 同时进入 rows/unlocated；source/query IDs 缺失或与 selection 不一致；51 股、20,001 行、200,001 总行均在构造派生表前拒绝。

## R2：异常作用域与“能算来源值”的资格必须分开

**编码前阻断。** “任何异常关闭比较”和“所有正 close 都能比较”都不够具体。建议冻结如下小矩阵，不引入通用资格引擎：

| 情形 | 首片建议行为 |
|---|---|
| 批次 quarantine/known-negative；元数据或批次级明确证券/市场/调整冲突 | 整份调用拒绝，稳定原因；不返回借该成员组成的合格或诊断基准 |
| 确切 a/b 缺失、重复、非有限/零/负/超存储范围价格，或端点已知价格资格失败 | 保留全成员与具体端点原因，固定组比较为空；其它成员的独立来源变化可保留 |
| 无法确认日期，因而可能覆盖/重复任一端点 | 主比较为空，`endpoint_integrity_unknown`；不能凭源序号大推为未来，也不能取可定位子集重算基准 |
| 有可靠日期的非端点普通数值坏行、重复行或内部停牌缺行 | 不参与端点算术；保留路径异常/覆盖未知，端点算术可以成立；不估波动、每日收益或持续可交易性 |
| 行级证券/调整冲突位于 `[a,b]`，或日期无法定位 | 拒绝该区间比较；不能借端点有效掩盖区间内来源口径冲突 |
| 行级问题可靠定位在区间外，且无批次/元数据级冲突 | 披露为区间外问题，不改变固定区间算术；不得自动升格为全局冲突 |
| 只有 volume/amount 错误、未知单位，或源返回早于请求 start 的合法上下文 | 不阻断价格端点算术；保留来源限制与范围诊断 |
| 调整、日历、闭合、历史首次可得、完整公司行动覆盖未知 | 可以输出 `source_price_comparison_only`；上述各项仍未知，经济收益资格恒为 false |
| 已知区间公司行动未处理，但来源自身身份/请求口径一致 | 至多保留明确标记的 `diagnostic_only` 来源算术，附 `corporate_action_unresolved`；不能给可比经济表现/收益结论 |

日期“可靠定位”也须写成规则：优先使用来源合同产生的规范 label；label 不可用时，只可依据该合同的明确原日期字段作异常范围排除，不能修复成有效端点。若两个日期声明相互冲突，不能挑一个有利的日期排除异常。对于已能证明严格位于两端点之间的普通数值异常，端点唯一性与路径完整性是两件事；不应仅因日历路径未认证就封掉端点算术。

首片建议 **沿用端点的完整正 OHLC 检查**，并把正文改为“使用合格端点的 close”。这与已有日线资格一致，现有 30 股正常 OHLC 不因此失效，避免本片顺手重做字段级资格。作者若确实要允许缺 O/H/L 的 close-only 输入，须另外列出缺其它字段、其它字段非法以及 `close>high` 三种不同情况的资格规则和反例；不能只绕过 `daily_bars.reason`。无需修改旧函数。

公司行动状态缺省必须为 `unknown`，空事件列表不能解释成“已查无公司行动”。如提供负证据，最少绑定 symbol/snapshot、有效区间、事件类型、来源引用及版本；其缺省不得阻断原始价格研究，其修改必须改变研究身份。[S&P DJI 官方方法说明](https://www.spglobal.com/spdji/en/methodology/article/index-mathematics-methodology/) 将价格变化、股息再投资及公司行动处理分别定义；复权正确也不能自动取得总收益资格。

输出还需明确“同伴完整、目标端点失败”的行为。按当前固定完整 G 的提案，建议整个主比较为空，独立成员变化保留；不得将目标失败误报为同伴缺失。分母 `selected_peer_count=m` 固定，同时另报 `valid_peer_endpoint_count`，不能把“实际覆盖分母”含糊地改成可用同伴数。

## R3：成员、A 股范围与版本身份需要一个小型显式说明

**编码前阻断。** 目前缺少调用方如何提供 10 股组的选择日期、组轴、品类/币种声明和证据等级。既不能靠市场字符串自动认证，也不能要求当前数据补全整个证券主数据系统才能使用。

最小建议为一个有界的 group descriptor：

- 固定 schema version、组名、group_axis（业务同伴/上市板块/显式样本）、selection_date、`membership='current_members_retrospective'`、选择依据和引用；完整成员列表包括目标，目标规范 symbol 必须恰好出现一次。
- 每个成员绑定一个规范 symbol 与 snapshot/query；重复别名、同证券多版本、同 snapshot 重复均拒绝。没有已核永久证券 ID 时继续使用带 `source_claim/declared` 的来源身份，不承诺跨批永久身份或唯一发行人；已知代码/证券映射冲突拒绝。
- 明确 A 股股票、人民币来源价格、同一中国日线标签体系的 **声明及证据状态**。可接受来自本轮已选清单的 declared/assumed 状态，保留原 metadata 的 unknown；不能把该说明反写成源已认证。已知 B 股/ETF/指数/外币或不同市场冲突拒绝，完全缺少适用范围声明则输入不足。无需按代码段猜品类。
- 调整请求/声明统一为本片认可的未复权来源模式，保留各自原字段及证据等级。至少明确腾讯 `requested_adjustment='none'` 如何映射；其来源调整语义仍 unverified。若兼容 BaoStock/其它格式，逐个列实际字段映射；没有映射的格式给 unsupported，而非猜测。已知 adjusted 与 unadjusted 混合拒绝。
- 说明不因被 hash 或写入 `verified` 就提升证据等级。所选银行/白酒不自动成为完整行业；科创板轴保持 listing_board。选择日期晚于 a/b 仍允许 retrospective 研究，必须保留这一事实，不能要求伪造过去选择时点。

研究身份至少绑定 method/资格规则版本、a/b、目标、规范排序后的全成员及 snapshot/query、descriptor 的全部有效内容与证据状态、公司行动/停牌负证据。仅替换组名、组轴、选择日期或资格证据，也不能与旧身份混用。输入成员顺序不改变数值或规范身份；按来源版本改变后，即使 a/b 价格相同，analysis_id 也可以且应不同。

这里须纠正一种测试误读：追加未来数据通常产生新快照，故 **过去数值不变** 与 **整个报告 ID 不变** 不能同时要求。固定成员/端点/资格下，可靠未来纯价格变化不改算术；版本、批次全局负证据或不可定位异常变化可以改变身份/资格。应分别断言，不能靠忽略新资格来做出“前缀不变”。

## R4：数值输出、失败枚举和额外输入预算尚未可测试

**编码前阻断。** Formula 已足够，但“精确有理数计算、格式化另注明”尚不构成返回合同。首片不用图表，也不必立即设计通用数值组件。

建议直接返回 JSON 可表示的精确值：约分后的 `{numerator: 十进制整数字符串, denominator: 正整数字符串}`。各成员变化/基准的单位为 ratio，D 与等权 D 的单位为 percentage_point；零统一为 0/1。原 close 保留精确十进制文本，带端点日期、ordinal 及 snapshot/batch 回查身份。若作者选择固定小数串，也须冻结位数/舍入及 exact 符号判断，不能先舍入再取中位数或判断异号。无需双重输出大量浮点副本。

数值域沿用 `decimal_value` 的 DECIMAL(38,18) 可精确范围，拒绝 bool/float、NaN/Infinity、过大指数与超精度；有限且正仍不足以允许任意百万位 Decimal。先做边界验证，再构造 Fraction。median、均值、差及符号全部用有理数。严格异号标志定义为两种差的乘积 <0；恰有零的情况另保留零值，不发明 epsilon 或统计显著性阈值。

最小返回结构只需：身份/参数；全成员与目标角色；逐成员 a/b 追溯、来源变化和原因；固定分母/有效端点计数；median/mean/两种差/严格异号；资格、限制及少量异常计数/相关 ordinal。不要输出每个日期一行的滚动表或复制所有原件。

错误分两类并冻结枚举：

- 调用结构、日期/成员/范围、来源全局冲突或预算错误：稳定 ValueError code，类型错误不漏为 TypeError/KeyError，不回显原数据。
- 端点缺失/重复/坏价、不可定位范围或局部资格不足：有结构的空值报告与逐成员原因；不能将所有失败变成一个 unknown。多原因是否全保留以及主要原因优先级须固定，调换成员顺序不得改变原因。

group/证据说明还需一个小的总字节上限（可沿用既有纯函数 16 KiB 思路，作者冻结具体值），拒绝未知字段和递归/无限结构，限制列表为本组/本区间；没有必要建证据注册平台。源行预算不能限制无界的外部说明或无限迭代器。输出只随成员和必要异常追溯有界增长，不以截尾静默丢失败。
