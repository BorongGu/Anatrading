## 判决与 P1 闭环

**接受离线源值保存与往返验证，无新增 P1。** [017](017-tdx-live-precision-review.md) 的来源混合风险在本轮设计中闭环：唯一输入为指定哈希的缓存副本，HTTP 原响应保持独立，不替换整数数量或金额，不反推交易所真值。017 指出的 HTTP 精确数据接入门槛仍未通过，此处不放行 HTTP 导入或软件完整兼容。

现有 `_day` 按 uint32 精确读取成交量，以 binary32 原位精确构造 Decimal，报价整数／100 明标候选；token 保留报价整数、金额位字节、保留字节及日期。`decode` 将声明保存为 assumed，标准单位及时间语义保持 unknown，`instrument_id` 为空。SourceRow 与查询／Parquet 的规范 `volume_shares`、`amount_cny` 均为空。此次不给出单位声明，符合现有源值证据格式，无需新 adapter 或产品修改。

同名格式及 32 字节结构均不能证明真实发行者、永久证券身份、单位、复权、覆盖或历史可得性。来源报告必须继续标明“客户端缓存副本”，不能写成手动导出。

只读指定副本，哈希与合同一致，270,848 字节／8,464 槽。用独立 Node Buffer／BigInt 位级代码遍历全部槽，未复用 `_day` 或根方审计脚本：非法日期、重复日期、逆序日期、OHLC 包含关系失败、金额非有限、金额负值、金额有效小数位超过 18、零数量非零金额计数均为 0。此预检不代替产品全行往返对账、完整 Decimal 范围检查或带假设的量额质量诊断。

## 执行细化与 P2

1. **独立对账须覆盖两类记录。** 用原位期待值核对全部 8,464 个 ordinal、byte locator、标签、六字段源值及 token；查询中的 `rows` 和 `unlocated` 合并按 ordinal 核对，不能只检查可定位窗口。所有产品 NULL 须对上独立数值拒绝原因。质量诊断的 fail／not_evaluated 与假设原样保留，不将条件量额诊断成功晋级为单位验证。
2. **一根一锁，阶段串行。** 显式传新私有绝对 root，不允许 CLI 默认根。每段关闭前一 EvidenceStore／CLI，再开下一段；直接 SQL 仅通过持有操作锁的同一 EvidenceStore。现有锁在 DuckDB 连接前获取，关闭后释放，支持这项约束。原件哈希检查、幂等账本核验及 WAL 状态记录不可通过外部无锁数据库连接完成。
3. **资源观测保持诚实。** 私有包装器监视当前真实 Python 进程，记录 PID／启动身份，禁止用 venv 重定向器替代。100 ms 自监视与 60 秒 watchdog 属观测停止机制，无法证明硬隔离或绝无采样间隔超限；须持久化开始、采样最大值／可用系统峰值、终态和超限原因。若自停或超时，仅保存现场，不恢复后重试已超限输入；旧性能副本保持关闭。

以上 P2 是合同执行细化，不扩大范围。三条窗口采用明确源序号 8462–8464；JSON 与 Parquet 还须核 schema／metadata 中来源身份、未知资格、checks 和 token，不能只比较屏幕数字。两次导入必须保持相同解释与文件字节，并证明新增 attempt 指向原批次／快照。
