# 股票研究工作流：独立反方审查

日期：2026-10-11。审查对象：`docs/plans/2026-10-11-research-workflows.md` 初稿。独立审查只修改本文件，没有实现产品代码。

## 03:04 UTC 最终编码前决定

已逐项复核计划新增“评审答复与接口冻结”中的 R1—R6。**架构、首批日线数学与 HTTP 范围通过编码前审查。** 原阻断项已由明确选择关闭；在对应 `docs/research` 文献/公式文档完成并与本决定一致后，允许切片 1、2 编码。切片 0 已解冻，不受此研究文档先决条件影响。此决定只允许实现和验证，不是算法效果、真实行情兼容或 Windows 运行验收通过。

接受主方选择的具体工程阈值：价格回归 X 样本方差 <=1e-12、训练残差尺度 <=1e-10、收益相关任一方差 <=1e-16 均按相应退化原因处理。它们是明确的数值适用边界，应测试等于阈值和两侧邻近值；低于边界的合法微小变化仍留在原始来源中。收益 beta 的 X 方差门槛应沿用收益方差口径，不能误用 log 价格方差阈值。完美拟合仅使残差标准化不可算，其余可定义统计保留。

接受 N+1 来源日期窗口、ddof=1 波动、非正数的最大回撤比例、正动量广度与 competition ranking。负号口径需贯穿 API/图表说明，不与正数回撤幅度混用。接受首版正价标签与旧固定日期源值观察的零价行为并存，两个 method_id 的定义须分别保留。

实施时还需按既定合同覆盖三个小范围细节：同市场兼容集合应明确是否包含沪/深/北，避免把同一 A 股研究范围机械缩成同一交易所；无法定位日期保留数量及完整覆盖未知标志，不能静默视为干净历史；请求身份随 cutoff、左右角色、参数或集合变化同步失效。它们属于验收实现细节，不引入新分析范围。

拒绝首版追加分钟 Kalman、协整/套利宣称、自动调参、历史行业指数和成本后交易 PnL；这些继续列为后续独立研究。最终发布前仍执行本文数学、HTTP、性能、浏览器与跨平台验收；缺真实数据的验证保持开放。

## 03:03 UTC 修订复审：分范围解冻

已复核计划追加的“反方首轮意见后的参数与边界冻结”第 1—8 条。下文保留原始反方意见以供逐项追踪，不表示已关闭条目仍阻止全部实施。

- **切片 0 允许编码：** POSIX 锁、Windows 专用门控、固定宽度结构核对及 SQL 条件下推。前提是严格保持既有 query/export 身份、NULL/计数/范围语义、原件复核及 owner 生命周期；锁文件不删除。此决定不依赖数学模块尚未冻结的细节。
- **已经接受的研究边界：** 日线首轮、公开固定 Kalman 参数和 Joseph 更新、20 根暖机、EWMA 初始化/滞后标准化、明确 h/重叠剔除、可选显式 test_start 且无切点时仅描述、共同日期区间收益、集合不同证券与同日截止、50 版本/每系列 20,000/总 200,000 行预算、所有结果保留 retrospective 限定。
- **仍需写成确定选择后解冻相应代码：** 首根初始化不重复更新；双股残差分母及近零阈值、相关/beta 当期区间是否计入；集合动量/波动/回撤公式与窗口真实起点；HTTP 具体路径和完整研究身份字段。其余下文测试要求可进入实施验收，不必发展新架构。
- 突破采用完整正 OHLC 校验较仅校验参与字段更严格，但主方已明确选择，接受此首版口径；需输出原因并保留其与现有仅 Close 后续观察的不同。固定正价路径标签不接纳末端零价，也应明确标 invalid，而不改写旧功能的 -100% 行为。
- 本轮可接受有限大请求直接拒绝，旧接口超过 20,000 行历史上下文限制继续记开放项；200,000 总行是安全预算上限，不是响应性能已经通过的结论。

## 结论

**有条件接受方向，初稿尚未达到编码冻结条件。** 单代码库、纯函数分析、保留证据链、紧凑返回和朴素基线均合理。主要风险集中在尚未确定的数学定义、来源记录的时间语义、评价分组和输入预算。下列阻断项必须先在研究文档与决策记录中明确答复，随后可分切片编码；不要求为首版建立全套交易仿真平台。

最强反对意见：将 Kalman、突破统计、双股回归、集合排序同时摆进四个工作区，很容易产出更多看似专业的数字，却没有完成用户最关心的“从当前判断回到历史证据”工作流。最低可接受交付应能完成一条贯通任务：选择来源和截止日期，查看时点一致的趋势/事件，打开该事件定义的历史分布及缺失解释，再比较同一截止的第二来源或明确集合。独立图表数量不能替代此项验收。

## 已核对的事实

- 已读根 `AGENTS.md`、计划全文、既有 `docs/research/020-fixed-date-followup.md`、`023-source-price-gaps.md`、`docs/contracts/WORKBENCH_HTTP.md` 及相关 Store、HTTP、筛选实现。
- `EvidenceStore.query` 仅支持 `mode="retrospective"`。因果计算与历史当时实际可得是不同保证；新算法不能升级来源的可得时点资格。

- `_bounded_query` 当前以整批行数及源序号区间限流；不能直接复用于无限历史递推而声称大批次问题已解决。

## 阻断项与可接受决定

### R1：冻结 Kalman、EWMA 与基线的完整数学合同

“固定公开参数”不足以实现可复算模型。编码前至少冻结：

1. 状态为 `[log_level, slope]`，日线按来源观测步长，`F=[[1,1],[0,1]]`、`H=[1,0]`；写明 `Q`、`R`、`P0` 的具体数值、单位和选择依据。固定默认值可作为工程演示选择，不能宣传为论文验证的 A 股最优参数。
2. 若参数可输入，限制为有限数，`Q` 半正定、`R>0`、`P0` 半正定；首版最简单方案为固定对角 `Q/P0`，不开放任意矩阵。仅检查 `value>0` 不能排除正无穷。JSON 的 NaN/Infinity、布尔值冒充整数、过大窗口均先写拒绝测试。
3. 明确首根处理，例如用首个正 Close 初始化 level、slope 为 0，并将首根创新标为不可计算。用首根初始化后又把它作为独立测量更新一次会重复利用同一信息，除非文档明确采用该模型。
4. 明确先预测再更新；创新 `e_t=y_t-H x^-_t`，预测创新方差 `S_t=H P^-_t H'+R`。若展示标准化创新，使用 `e_t/sqrt(S_t)`，名称应标“模型标准化偏差”，不能称经验证的显著性或涨跌概率。
5. 原始 log 收益波动与上述模型创新分开命名。若用 EWMA 作预先风险尺度，定义 `v_t=lambda*v_(t-1)+(1-lambda)*r_t^2`，当前 `r_t` 的标准化应使用 `v_(t-1)`；当期更新后的波动可另作描述。明确初始化、最少样本、lambda 范围、零方差原因，以及该式是零均值二阶矩估计。
6. 暖机是初始化敏感期，不代表暖机结束便有预测能力。EMA 必须用同一变量、同一首根规则和公开 alpha；不得比较 log Kalman 与不说明尺度的价格 EMA。
7. 对坏值、重复标签采用一个固定恢复规则。建议坏标签组中断，下一唯一正值重启，并返回 `segment_id/reset_reason/warmup`。缺交易日历时无法检测“缺了一个交易日”，不可按自然日相差大于 1 自动重置。
8. 协方差更新需保持有限、对称、非负；至少与独立矩阵参考实现核对。若数值病态，返回原因，不静默把负方差截成 0。

建议首轮只开放日线。分钟序列的隔夜、午休、停牌、缺分钟和时段闭合需要独立合同，现有“按观测柱解释”仍不足以形成可靠分钟择时模块。

### R2：事件标签、分组和评价时点必须可机械复现

1. 突破规则严格使用当前 Close 与前 N 个来源日期组的 High；当前 High 不进入阈值。比较沿用 Decimal。前窗坏值/重复不能删掉再凑 N 个有效样本。文档需明确只要求参与字段合法，避免无关的 amount/volume 阻断 Close/High 研究。
2. `h` 表示后续 h 个来源日期组，不能写成 h 个交易日。选择该目标组后再验证，不删除无效记录后移动终点。明确路径中间坏组是否阻断标签；推荐首版阻断，保持“连续来源跨度”定义，另报未成熟与无效数量。
3. “变化”固定为简单变化 `(C_end-C_event)/C_event` 或 log 变化之一，不能界面与统计混用。建议沿用已有源收盘简单变化。末端零价可按既有 `020` 作为 -100% 的源数学变化；log 特征则需正价。这两个模块可使用不同字段要求，但必须明确。
4. 事件数、进入评价数、被重叠规则排除数、未成熟数、无效数、有效标签数要可对账。未成熟不属于亏损、零值或无事件。
5. 固定显式 `test_start` 日期。若 UI 默认取后 30%，首次生成时必须解析为日期并回显，不能追加数据后静默移动原研究切点。切点前事件的终点达到或越过测试起点时，排除于训练评价。
6. 重叠规则二选一并冻结：全部保留且披露相关性；或按事件时间从早到晚贪心保留，明确边界是否允许 `next_start == prior_end`。不能按事后收益挑一条。基础突破信号始终保留，评价资格作为独立字段，不能去重后让旧信号消失。
7. 基线使用相同测试区间、相同 horizon、相同 Close/路径合法性和成熟条件的全部合格起点。阈值前窗不可计算的日期是否进入基线需明确；建议不进入，以免两组可得信息不同。全部日期基线可能包括事件日期，必须明说；它不构成随机对照或超额收益基准。
8. 与现有统计统一 Type-7 分位数、零/正/负判断、空组和单值组规则。均值可作描述统计，但不生成 iid 置信区间、p 值或“胜率”标签。条件分布差异不自动归因于突破。
9. `signal_as_of` 与 `evaluation_as_of`/标签成熟时点必须分开。追加未来值不改变旧信号；成熟标签和后续统计可以更新。固定评价截止后，整个评价结果也应稳定。

采用一个时间切点与禁用自动调参仍不足以证明样本外有效。人反复换 N、h、股票与起止日也是试验选择。首版声明“历史后段描述性评价”，报告实际参数与区间；待真实数据到来后另冻预注册实验。无需现在实现复杂交叉验证或试验管理平台。

### R3：双股对齐须消除不同收益跨度和伪回归解释

1. 两版本只能同为 1d；来源的复权、单位、币种、市场收盘同步性和历史可得时点必须分别披露。首轮聚焦同市场数据；跨市场同一日标签不保证同时点，应阻止被称为同步关系。
2. 禁止先各自计算收益再按日期 inner join。例如 A 有周一/周三，B 有周一/周二/周三，周三两侧所得变化跨度不同。
3. 可接受的最小方案：先形成共同唯一日期序列，再用相邻共同日期计算两侧同跨度收益，同时保存开始/结束标签和跨度说明。不可跳过某一共同日期的重复/坏值组并继续组成干净窗口。另一可接受方案是联合日期网格，缺任一侧则该段不可计算。两方案不能混搭且不能统称“连续日收益”。
4. 收益 beta 与 log 价格回归系数分字段：前者为收益协方差/基准收益方差，后者为价格弹性；需要明确哪一侧是 Y、哪一侧是 X。换左右证券不应仅改标签。
5. 回归残差用前 W 对价格拟合含截距 OLS，在 t 评价。若用 `sqrt(SSE/(W-2))` 标准化，W 至少 3，分母与拟合窗同一套残差；此值不是预测区间标准误，也不保证近似正态。冻结近零方差/近零残差尺度的数值阈值，不能只检查等于 0。
6. “几乎完美拟合不可计算”应只阻断残差标准化，不应错误阻断合法的 ±1 相关系数或可定义的 beta。常数 X 无法估计 beta；常数 Y 也会令相关系数不可定义，状态分别返回。
7. 相对强弱需选明确共同起点，如 `(A_t/A_base)/(B_t/B_base)-1`，回显基准日期。任意滚动归一化不能暗中回改历史图线。
8. 两个不同 snapshot_id 可能属于同一证券；应展示这一事实，不能算作“两只独立证券”。同一 ID 重复输入拒绝；集合中的同证券多版本需明确去重/拒绝，不能双计广度。

双股偏离不支持套利结论。高相关、漂亮残差或低样本内 SSE 不建立协整；短窗口价格回归可能产生伪关系。首版不添加协整、PCA、机器学习打分或自动选最优配对。

### R4：多股集合的分母与时间窗口需要共同身份

1. `selection_id` 绑定完整所选来源集合、数据版本、截止日期、参数及方法版本。集合变更后应全部使旧结果失效。
2. 每个指标分别报告 `selected/eligible/missing/invalid/short_history` 等可对账计数。动量可算、波动不可算的股票不能被一个全局 eligible 标签隐藏。
3. 排名只在指标可算成员中进行；不可算保留行和原因，不填 0、不自动移到负收益区。并列名次和稳定次序要固定；可用证券标识/版本 ID 作展示 tie-break，不暗加评分。
4. 所有成员要求截止日期唯一来源 Close，不能拿最后可得日代替。动量/回撤若按各自 N 条来源记录，必须回显各自真实起点及跨度；若要称共同期间比较，应要求共同起始日期。上市不足/缺失不能自动缩短窗口。
5. 波动、动量、回撤公式必须先写清：简单或 log、样本分母、窗口是否含当前、回撤为当前离高点幅度还是窗口最大峰谷回撤。二者不可混称。
6. 广度以具体条件的 eligible 为分母，旁列 eligible/selected 覆盖率。空集合/零 eligible 返回 null。当前成员回看使用“所选样本”，不绘制无依据的历史行业指数或称全市场广度。
7. 成员身份无法可靠核对时只能表示“所选数据版本样本”，不承诺唯一股票数。板块名称是用户声明，不能反推出历史成员或指数权重。

### R5：冻结研究 HTTP 身份、错误和资源预算

1. 延用本机同源、Host/Origin/token 规则及 owner 线程；不另开无边界后台服务。GET 与 POST 选型、具体路径、输入模式、返回模式在决策记录中列出。
2. 每份结果绑定方法版本、全部输入版本/查询身份、来源上下文起点、截止、完整参数、有效性与限制；双股两侧角色有序，集合身份可规范排序但展示顺序另保留。仅 `query_id` 不足以区分参数不同的分析。
3. 纯分析模块不要 import Store 获取 hash 函数。若提取 JSON/identity 小工具，序列化须逐字节兼容旧实现，含 Unicode、Decimal、键顺序和 NaN 拒绝测试；不顺便迁移身份算法。
4. 严格请求解析拒绝未知字段、重复键/重复查询参数、空 ID、重复 ID、未知方法、无界窗口和超长字符串。错误用稳定原因码，不能回显原始输入/路径/异常堆栈。
5. **编码前确定数值预算。** 可接受首版示例：单版本上下文最多 20,000 条，总集合最多 40 个唯一来源，总上下文最多 100,000 条；具体值可由主方替换并记录性能依据。限制输入/上下文和输出，不能只限制返回 20,000 行。优先预检超限，不等算完后再拒绝。
6. 对递推模型，截短历史会改变估计。最小安全方案从同版本起点算到截止，超上下文预算直接解释性拒绝；若支持显式起点，则把它计入方法身份并称重初始化研究。不要为本轮赶出持久缓存或序列化状态框架。
7. 原件 hash 继续每次请求校验。一个多分析请求内可以复用已经验证的同一上下文，不能跨请求缓存绕过原件变动检查。集合中某份原件损坏应形成明确失败策略，不能静默丢证券。
8. 旧请求的返回只能命中同请求代次与完整研究身份；切 cutoff、左右交换、增删集合成员、修改参数、失败/空结果之后，图表、说明、tooltip 和导出同步清空。

### R6：跨平台和 SQL 优化需要语义回归

1. POSIX `flock(LOCK_EX|LOCK_NB)` 与 Windows `msvcrt` 保留同一锁文件及范围生命周期；开文件、写初始字节、flush、加锁失败都关闭句柄。重复 close 可安全调用。不要 unlink 锁文件，否则新进程可能锁到另一个 inode。
2. 文档限于已测本地文件系统。同一网络共享目录被 Linux 与 Windows 同时打开并不因二者各自有锁而自动安全；本轮不宣传跨 OS 网络共享互斥。
3. 平台专属进程 API 调用前安全拒绝，导入二进制解析、Store 和 Web 仍可在 Linux 使用。Windows 二进制结构固定宽度字段需用字节偏移/size 核对，不以 Linux `c_ulong` 代替 Windows DWORD。
4. SQL 过滤需保留 selected/unlocated 分离、cutoff 空标签规则、源序号边界、稳定排序、全部 batch counts、selected quality/totals 和旧 query_id。SQL 中 NULL 比较与 Python 原过滤行为不同，必须显式处理。
5. 双进程争用测试、持锁进程异常退出后的重开、导入/备份/恢复共用锁、启动失败清理和真实 HTTP 重启都需测试；同进程两实例不足以证明进程互斥。

## 最小验收集合

### 数学与时间

- 手算三至五根 Kalman 更新，含预测创新；独立 2×2 矩阵参考实现；常数、线性趋势、单点冲击和零方差序列。
- 每一个前缀都与完整序列对应信号一致；改写未来值同样不影响过去。缩小显示窗的重叠输出一致，除非显式采用不同初始化身份。
- 正常 N 窗、重复标签、未定位行、单字段缺值、零/负 Close、近等值 Decimal、NaN/Infinity、极短样本、每种 reset 边界先有用例。
- 突破当日 High 不入前窗；目标 h 恰好成熟、差一条未成熟、内部坏组、终点零价、重叠边界、跨切点标签剔除、固定切点追加未来数据。
- 双股异步缺日示例能证明两侧收益区间完全一致；左右交换、常数单边、完美拟合、近完美拟合、回归当期排除、重复共同日不得静默删行。
- 集合截止缺失、不同起点、指标不同 eligible、同证券多版本、全不可算、并列排名和选择顺序变化，全部数目能对账。

### 性能与产品

- 5,000 与 20,000 条固定输入记录纯算法耗时、HTTP 总耗时、峰值内存/可用代理和 UTF-8 响应字节数；注明 Python、硬件、冷/热状态和样本结构。纯公式基准不能替代 HTTP。
- 20,000 条紧凑单股响应大小原则上不超过 5,000 条的 4.5 倍；不逐行返回 W 条成员。耗时应随 n 接近线性，若实现 O(nW) 必须在最大 W 下报告并说明为何可接受。统计排序 O(n log n) 可接受，不为小规模统计强建框架。
- 最大允许集合场景实测排队影响；请求有界并能及时呈现处理中/失败。快速切换时旧响应无法污染新页面，不借“取消 HTTP 等待”声称停止服务端计算。
- 实际浏览器验证一条贯通任务、空数据、异常字段、原件损坏、快速切换、左右交换、增删集合、窄屏和键盘焦点。未跑浏览器不得用前端单测/构建替代。
- 合成数据显眼标注，默认研究样例不能被误认真实 A 股结果。主体字号、表格密度、数值对齐和图表颜色/文字共同表达状态；不能只靠红绿区别。

## 允许的分阶段范围

1. **切片 0：** 精准补 POSIX 锁、Windows 专用门控和 SQL 范围下推；旧合同等价回归。纯研究函数可与这些修复并行，但需先完成 R1—R4 的文档冻结。
2. **切片 1：** 日线趋势 + 固定突破事件 + 明确后段描述性评价，一条端到端工作流；保留 EMA、全部合格日期基线和失败原因。数据到来前只交付计算能力资格。
3. **切片 2：** 两来源日线关系与有界集合比较，分别完成身份、覆盖及 UI 竞态验收后开放。允许同轮交付，但各自有独立完成状态，不能因有菜单便算实现。
4. **后续保留：** 分钟择时、历史成员、公司行动/复权、协整、PCA、组合权重、执行成本和正式交易收益。拒绝仅为“高级算法”增添这些入口；需每项研究依据、数据与增量实验。

完成声明必须分别回答：算法/接口是否可运行；真实软件导出是否兼容；是否有样本外预测增量。待用户真实数据期间可以完成前一项，后两项保持开放。
