## DA-01 · P1：发布身份、数据授权和零收费仍缺独立资格证据

**定位**：MASTER_PLAN §5、§9（约 63–65、100 行）；ARCHITECTURE SourceContract（约 45 行）、采集步骤 1（约 95 行）。

**具体失败情形**：Financial-API 的 README 自称同花顺官方，服务在 `fuyao.aicubes.cn`；本轮尚无公司自有页面反向背书闭环。GitHub 名称和它链接到同花顺产品页均不能证明运营身份。若连接器据品牌名推荐登录，就把待验证入口变成默认可信。另有明确成本反例：iFinD 的“免费账号”依附已购终端，TdxAiData 后台订阅有费用；MIT 许可不决定行情套餐和再分发权。[身份研究](../research/002-data-access.md#31-financial-api-的身份与日线契约)、[iFinD FAQ](https://quantapi.10jqka.com.cn/gwstatic/static/ds_web/quantapi-web/help-center/faq.html)、[通达信安装文档](https://help.tdx.com.cn/quant/docs/markdown/mindoc-1cfsjkbf8f3is/mindoc-1d00kk3jsibbc.html)。

**建议决策**：SourceContract 加入发布主体、身份背书证据、端点/认证域名、信任状态；将代码许可、个人本地保存权、再分发权、费用/额度分开。Financial-API 暂列“身份待独立核验”；没有证据时不进入 Key 配置。尚未确定免费历史容量属于源资格缺口，不影响继续查证其它来源。

**验收/关闭阶段**：首次带凭据的 G1 请求前，保存可复核的主体背书与端点对应关系；数据源晋级前保存账号/套餐适用条款及零费用路径。身份确认与数据权限确认分别通过，不能互相代替。结果允许为不采用该源。

## DA-02 · P1：全市场范围与基准指数不能共用股票量纲假设

**定位**：MASTER_PLAN F03/F09、§9（约 27、33、100 行）；ARCHITECTURE §3 证券身份（约 46、52–54 行）、§5 数值（约 77–83 行）；现有 AGENTS.md “成交量统一为整数股”。

**具体失败情形**：BaoStock 股票参数文档只列 `sh/sz`，尚未证明北交所、转板及退市完整覆盖；把其接口名称中的“所有股票”理解为沪深京全覆盖会漏证券。当前代码表也无法还原历史证券池。基准指数价格为点，源量可能是特定成分/市场汇总；套用股票手数倍率或 `金额/量=指数 VWAP` 会产生表面合理的错误。[BaoStock 股票契约](https://www.baostock.com/helpDocsHome?file=stockKData.md)；指数均价问题来自量纲推导，具体指数来源仍待实测。

**建议决策**：冻结首期采集宇宙定义为明确交易所/资产类型/日期下的 A 股股票集合，并单列必需基准指数。证券主数据加入 `instrument_type`、价格单位、量单位及量的统计对象；股票按股规范化，指数保留源定义并限制不适用指标。同步修订 AGENTS 的股票适用范围。历史全市场研究另要求退市与历史身份/成分；暂时缺失时保留缺口，不改称全面覆盖。

**验收/关闭阶段**：G1 源晋级前按交易所与官方证券清单对账，并给每个缺项原因；含沪/深/京、上市边界及所选基准指数。G2 指标上线前证明股票/指数不会因数字代码相同混用，指数不会被套入股数倍率与未定义 VWAP。G4 市场级研究前验证退市/历史证券池。

## DA-03 · P1：盘后分钟下载尚不能承诺当天分钟择时

**定位**：MASTER_PLAN 用户优先级与 G1–G3（约 7、88–90 行）；ARCHITECTURE SourceContract（约 45 行）、首批工作流（约 130 行）。

**具体失败情形**：通达信 `refresh_kline` 官方说明盘中下载 1m/5m 只能到上个交易日；BaoStock 分钟说明约当日 20:00 入库；Financial-API 文档公开方式不提供分钟。程序每分钟成功执行一次读取，仍可能一直显示昨天的数据。[通达信刷新规则](https://help.tdx.com.cn/quant/docs/markdown/ctx.stock.md/mindoc-1h10fh9m6recg.html)、[BaoStock 更新时间](https://www.baostock.com/helpDocsHome?file=home.md)。

**建议决策**：将源能力拆成历史分钟回补、盘后当日分钟、盘中已闭合分钟三个独立资格。先推进可验证的日线/分钟复盘；当天择时需求继续保留，资格不足时功能不可用。SourceContract 需写明实际数据水位、末根是否临时、发布延迟证据和订阅/轮询方式。

**验收/关闭阶段**：G1 核对首/末可取时间、请求时间与源内时间，区分交易日和休市日；盘口/盘中连接器启用前跨完整交易日证明新分钟到达、闭合确认、午休/竞价行为、断线回补和修订。只读到历史数据不能关闭盘中资格。

## DA-04 · P1：单位与复权原则正确，但实际转换凭据尚未建立

**定位**：ARCHITECTURE SourceContract（约 45 行）、§5（约 76–83 行）、§6（约 91 行）；MASTER_PLAN G1。

**具体失败情形**：通达信旧官方 TQ 示例写量为手，当前 `get_market_data` 写最小单位；金额为万元。若依样例文本定倍率，会出现 100 倍错误。该官方 FAQ 还指出局部窗口前复权与客户端全历史展示可能不同。Financial-API 公司行动 REST 字段表缺配股参数，无法仅靠它兑现全部复权事件。[当前契约](https://help.tdx.com.cn/quant/docs/markdown/mindoc-1ctuhthaq5qmg/mindoc-1h10g60jt68sc.html)、[旧示例](https://help.tdx.com.cn/quant/docs/markdown/gzh0122inweixinwenz/)、[FAQ](https://help.tdx.com.cn/quant/docs/markdown/mindoc-tdxpy.html)、[公司行动字段](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/a-share/corporate-actions-adjustment-factors.md)。

**建议决策**：保留架构现有“已验证契约才转换”的原则，并要求每个倍率附真实版本证据；原始未复权价作为首个合格输入。派生复权须具备事件字段完备性、算法、锚点、计算区间和供应商版本，不能只存 qfq/hfq 字符串。无法核验时该字段或派生视图不晋级。

**验收/关闭阶段**：G1 逐列对账至少含普通日、除权日前后及分钟区间；用实际 `.day`/文本与接口独立核对量额倍率，金额容差由文本/float32 分辨率推导。复权模块启用前做完整窗口与切片请求差异测试，并有配股缺项阻断用例。

## DA-05 · P1：一个“成功水位”不足以证明全市场及自选池覆盖

**定位**：ARCHITECTURE §7 步骤 2/7（约 96、101 行）、DatasetSnapshot（约 48 行）、§8（约 110 行）。

**具体失败情形**：全市场作业中一部分证券成功到当天，另一部分断网；按最高日期推进水位会永久漏掉失败分片。新纳入自选池的证券也可能被当作已经历史补齐。近 10 日增量包无法补跨越其范围的断档；仅回查尾部又无法发现更早纠错。停牌、新上市、接口不支持和网络空返回需要不同处理。[Market Dumps 范围](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/market-dumps.md)。

**建议决策**：把“已完成作业”和“已覆盖数据”分开：清单明确证券集合版本、源/周期/请求分片、预期范围、实际范围、失败与无数据原因。维护每条采集流的覆盖区间；加入自选池时显式请求历史窗口。源特定重叠窗口只代表已检查区间，定期全量/分层审计另行记录。

**验收/关闭阶段**：G2 自动更新上线前，对部分证券失败、分页中断、新入池、长期离线、源修订做恢复验收；重跑无漏数/重复，未覆盖部分在 UI 可见。不得因为行情其余部分成功就发布“全市场已更新”。

## DA-06 · P1：可信时点数据与显式时点假设需分开标识

**定位**：ARCHITECTURE §4“时点研究”（约 70 行）、ReferenceEvent/DatasetSnapshot（约 47–48 行）、§9（约 122 行）。

**具体失败情形**：同一句先要求“可证明在 known_at 前可得”，随后允许未知时间采用假设。若只有一个“时点研究”状态，今天下载且被修订过的数据可能在界面上和历史原始发布版同级。交易日零点、最新一根上游时间、除权生效日都不能填充历史首次发布时刻。[Financial-API 时间定义](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/a-share/prices.md)、[公司行动字段](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/a-share/corporate-actions-adjustment-factors.md)。

**建议决策**：保留复盘、经证实时点、假设时点三个资格标识；没有历史发布证据的字段允许条件研究，但结论与经证实样本分开。假设必须落到字段/版本，记录延迟与修订假设，禁止用全局 `known_at` 掩盖逐行版本缺口。低证据历史可以开始描述研究，不能自动获得实时或可交易性证明。

**验收/关闭阶段**：G3/G4 相应研究入口前，构造同一经济时间的先后修订版本、缺失发布时点和跨除权窗口，分别验证排除或假设标记；输出中的研究资格、纳入数据与对应证据一致。

## DA-07 · P1：原始行情证据与认证控制响应需要分界

**定位**：ARCHITECTURE RawObject（约 44 行）、§7 步骤 2/3（约 96–97 行）、§11 发布（约 138 行）。

**具体失败情形**：若“原始响应一律不可变归档”覆盖获取下载地址的响应，将把 Market Dumps 预签名 URL 存入 RawObject/日志；项目文档明确该 URL 属短期凭据。私有存储与不提交 Git 都不能替代不记录凭据。通达信本地同一 HTTP 服务还提供交易方法，仅说明“不自动下单”缺少调用面的限制。[Market Dumps 凭据说明](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/market-dumps.md)、[通达信本地 HTTP](https://help.tdx.com.cn/quant/docs/markdown/mindoc-1hdhbmi50d038.html)。

**建议决策**：认证头、Cookie、登录响应及签名 URL 走短期内存；下载的行情文件才进入不可变原始证据。清单记录非敏感数据版本/对象标识与哈希。通达信连接器只允许明确列出的行情方法，前端不能传任意 `method`。

**验收/关闭阶段**：对应连接器首次接入前，验证日志、RawObject、错误报告和前端响应均无凭据；未知/交易/账户方法不能通过该行情适配器转发。文件哈希仍能独立追溯实际下载内容。

## DA-08 · P2：真实文件样本通过只覆盖有限证据层

**定位**：MASTER_PLAN §11（约 121 行）；ARCHITECTURE §11（约 136 行）。

**具体失败情形**：通达信第三方公开历史原文件可证明解析器兼容那份字节，无法证明用户当前客户端接口启用、单位一致、长期更新稳定或上游行情事实无误。接口和客户端导出也可能共享相同上游错误；一致性不足以证明市场真值。

**建议决策**：保留架构已有的三种样本分级，再在报告中独立列出格式、同源语义、跨源差异、连续更新、策略资格。当前公开文件不得删除；记录其负面差异。对当前客户端的对账仍是未完成项。

**验收/关闭阶段**：G1 报告引用实际样本哈希/版本，逐项说明证明边界；G2 自动更新报告需要多次真实盘后作业及故障恢复证据。002 已更正“本轮尚未对账”的适用范围，本项仍需最终文档与界面保持一致。

### 新调整与一致性检查

单一 DuckDB 事务统一规范批次、目录、覆盖与作业，原始对象先按哈希发布、Parquet 仅导出，保留了所需来源与修订证据，也缩小了一期发布一致性问题的范围。未发现该简化引入新的数据接入 P0；事务恢复、原始对象损坏、备份一致性仍按 T10/T11 实测，不能由设计推定通过。

研究 002 §6 的“留本地”是对外发布边界描述；执行时须遵守 ARCHITECTURE §7 的更具体约束：短期签名 URL、认证控制响应不归档，行情数据字节才进入 RawObject。股票整数股要求已有明确品类范围，不能扩展到指数。

### 最终结论与 G1 边界
