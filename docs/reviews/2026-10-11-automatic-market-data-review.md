## 2. 可保留的决定

1. 原始 HTTP 实体与规范封套各有独立哈希；封套不是线路字节或发布者签名。抓取 UTC、HTTP Date、run_id 不进入确定性封套。
2. 固定 HTTPS 地址、精确重建 URL、拒绝重定向、无任意 callback、严格 JSON/重复键/编码检查；新浪注释里的 script 仅为固定字节标记，不能执行。
3. 请求身份、源响应身份、永久证券身份、复权请求和复权证据分开。新浪不回显证券及周期，不能填成已验证源字段。
4. 新来源所有 source_volume、标准股/元均留 NULL，合法源量经 Decimal 校验并保留 token；不调用 BIGINT 校验再删除错误。不更改旧格式默认数量路径或全局 schema。
5. 单一 EvidenceStore 写入者、整次有界采集持同一数据根锁、原件及快照不可变；提交账本决定最终提交结果。
6. 不根据 HTTP 200、非空或最大日期到达目标声明区间完整，不自动补柱、去重、跨源拼接或推进覆盖水位。未知历史 known_at 仍未知。
7. 401/403/429、验证码及封禁停止；首版无自动重试、无账号、无全市场发现或持续调度。

## 3. 编码前阻断项与反例

### R1：捕获格式与最新有界批次不兼容

原稿只允许腾讯不跨年、31 自然日/count=64，以及新浪 count≤240。下载作者已确认首批采用：

- 腾讯每股两段周年窗口：2024-10-11～2025-10-10、2025-10-11～2026-10-09，分别 365/364 自然日，count=640；callback 取起始年，窗口跨公历年。
- 新浪 1m/5m 请求 datalen=1970。

**反例：** 有效响应和全部哈希均正确，却因为 year boundary、count 或 datalen 被新格式拒绝。以旧小块计划重新抓取会额外消耗请求，也不能再取得完全相同的滚动分钟原件。

**必须修订：** 分开“捕获格式允许解释的有界请求”和“产品命令默认网络预算”。腾讯捕获至少接纳已观察的跨年周年请求、count 为受限正整数字符串且≤640、callback 精确等于起始年；不得把 640 说成已验证源最大值。新浪捕获允许本批使用的 count≤1970。兼容资格仍由真实请求结果授予，扩大上限本身不构成源支持证明。CLI 可以继续保守，但必须能导入本批实际捕获，无重写源请求或重新下载才能使用的前提。31 日/64 与大窗口/640两种策略应明确命名，不能混写。请求时间范围上界与用户两年目标视图范围须分别冻结，不能让CLI输入与格式边界互相矛盾。

**门槛：** 先用合成形状覆盖跨年、闰年、冻结的请求时间范围上界、count及datalen边界；真实周年和1970请求成功后核对实际行数、日期范围及字节上限。真实失败仍记录失败，不用离线数据替代。年块不声称交易日完整。

**04:06新证据及决定：** 同一腾讯请求 sh601398、start=2024-10-11、end=2025-10-10、count=640，实际返回640行，从2023-02-20到2025-10-10；243行在请求区间、397行早于start、0行晚于end。诊断原件SHA-256为`6e2bbf04cf9c982f6346589b3926f53f6f6c909f0e6bf82dab66321ce30a6f9d`。这支持“该次接口没有按start裁掉更早上下文”的观察，尚不支持一般接口保证。父任务已批准完整保留原件及全部源行，以显式目标视图筛选并记录排除数/原件定位。故原稿“任何start外行拒绝”须撤销：早于start仅记request_range_mismatch和实际范围，晚于end仍拒绝。恰count只能报告count_saturated/truncated_possible，不能单凭它断言目标两年缺失。若一个最新640行原件足以覆盖目标起止标签，可直接使用一个快照，仍不声称无缺交易日。不得静默裁剪后伪装原响应。

### R2：采集日检查破坏确定性

原稿要求新浪未来于“采集解释日”的标签阻断合格声明，同时将所有采集时刻排除在封套外。腾讯 request.end≤启动当日也必须与离线格式校验分开。

**反例：** 相同新浪封套在 D 日与 D+1 日导入；其中有 D+1 标签。若 decode 读取当前时钟，完全相同 raw/解释/版本会出现不同检查或接受结果。resume 恰好跨午夜也改变判断。腾讯离线导入若重新检查“今天”，也存在相同问题。

**必须修订：** 纯封套解码不读系统时钟。日期合法性、腾讯end上界及身份核对是确定性解码；相对于采集时钟的检查仅在 journal 使用首次冻结的观察参考日/时区假设评估，resume 不更新参考。若该诊断需要阻止联网运行发布，必须在 import 前保留明确状态；离线导入标明没有可验证采集时钟，不能制造“未来日期已通过”。不要把抓取日偷偷加入解释使同原件每次变新快照。

**门槛：** 同原件跨模拟午夜解码结果、批次身份和查询完全相同；网络诊断始终引用原始冻结参考。明确定义观察日与源标签时区尚未核实的关系，不能据此授予源时区或历史可得资格。

### R3：恢复必须绑定具体计划项及解释版本

原稿写了校验所有封套哈希，但哈希正确只说明字节未变；未充分约束封套与当前块的一对一对应。plan 尚未冻结完整 interpretation 和会影响批次身份的版本。

**反例 A：** 把另一只证券或相邻日期块的合法封套放到当前块的记录下，并同步写入它的正确哈希。封套自身合法，单独哈希校验通过，当前块却可能被误标 committed。

**反例 B：** 捕获后升级软件，默认 interpretation 或 contract/version 改变。resume 重新解释同原件并发布新批次，然后把旧项视为重用。

**必须修订：** plan 冻结每块规范 request 及其哈希、format_id、完整 interpretation、影响身份的合同/解码版本和确定性块 ID。恢复逐项校验 source、请求参数、请求 URL、响应 URL、period/adjustment、封套原件哈希与该块一致；账本还必须对应相同 raw、解释、版本、batch/snapshot，不能仅“查到一个已提交快照”即可。版本不兼容先停止并报告，不自动改变旧计划。plan_sha256 的输入须明确排除 hash 字段自身。离线封套的自报来源不能被提升为网络真实性证明。

**门槛：** 在两个合法封套之间交换日志指针、给相邻块复用封套、改 interpretation、升级合同版本、改 plan/journal 的字段类型或重复键，都不能跳过原块或错误提交。旧四格式的现有合同、全局版本及既有快照身份不得因新增格式无故改变。

### R4：崩溃间隙、持久预算与路径边界须闭合

原顺序为“发送预记账 → 保存封套 → import → 日志记提交”，没有明确已落盘封套尚未写入 journal 指针时的恢复规则。

**反例 A：** 封套文件已经落盘，进程在 journal 更新前退出。resume 看见 requested/无引用后重发；新浪滚动窗口已变化，先前捕获可能丢失，已消耗请求被额外重复。

**反例 B：** 文件 fsync、rename 后，没有持久化父目录；系统断电丢失预发送日志的新目录项，重启后预算回退。仅原子替换不等于断电持久。首版若只承诺进程崩溃，必须明确缩小承诺并在不能重建预算时停止。

**反例 C：** run_id 是合法 hex，但 public_acquisition 或 run 目录为指向根外的 symlink；合法名称仍可能造成根外读写。正确总发送数也不能替代 attempt 历史一致性。

**必须修订：**
- 明确捕获文件与 attempt 的可恢复绑定。例如使用已冻结块/attempt 的固定槽位，槽位记录封套哈希并在恢复时重新验证；或扫描该 run 中候选封套，只有唯一匹配被冻结请求时接管，多义或损坏即停。未引用的封套不能静默忽略并重抓。无需引入通用垃圾收集。
- 在发送前持久化 attempt/requested 和累计预算；恢复按全部历史 attempt 复算发送次数，与计数不一致即停。崩溃后未知是否发出仍占预算。预算耗尽有明确终态；剩余 pending 不继续发请求。失败/阻断后 run 如何汇总为 partial/blocked/failed 必须形成状态表。
- plan、journal、捕获及临时文件使用同卷安全发布，路径解析限制在本数据根并拒绝 symlink 逃逸；读取前限制文件大小，严格字段和类型校验，不接受 journal 提供的任意绝对路径。
- 支持的平台上完成目录持久化步骤；Windows 原生行为未经验证仍标未验证。若不能满足强断电预算保证，文档必须清楚声明范围，预算状态缺失时 fail closed。
- 已提交项先验证账本和 raw 完整性再跳过；captured 项不下载；store 返回 outcome unavailable 时不自行宣布失败后重发。Ctrl+C 遵循 store 提交临界段的既有最终状态。

**门槛：** 添加发送预记账前后、封套落盘但 journal 未引用、captured journal之后、raw发布后、事务内、COMMIT后ACK前的独立崩溃点；同时测预算篡改、源原件损坏、plan缺失、磁盘满、symlink逃逸及第二写入者。所有保存历史可复查，未证明已提交不能推进。

### R5：网络预算需要可执行的边界

“15秒等待/180秒墙钟”是正确目标，但单个 socket timeout 无法自动覆盖 DNS、不断有少量字节的慢响应或每个分段重新计时；第三方库默认 proxy、cookie、认证或解压行为也可能违背捕获声明。

**反例：** 服务每14秒发一个字节，始终不触发15秒无数据超时；DNS解析挂起；库跟随302到内网或携带环境代理认证；自动解压后保存的 body 被当成原实体。错误对象的 repr 可能把响应头或代理密码写入日志。

**必须修订：** 冻结一条明确受控的运输路径；禁用任意重定向、继承的 cookies/netrc/认证以及未经授权的代理配置，不采用全局可变会话。request 只记录应用设置的白名单头；库自动产生的 Host 等不冒称完整线路头。使用单调时钟的总截止并在读取各阶段检查，保证 DNS/连接/读与整次网络活动有可兑现的上界；取消后不能遗留继续发送的后台线程/请求。不能安全保证“数据库提交也在180秒内结束”时，将该值明确为采集网络预算，已入 store 提交临界段仍按提交结果收尾。

网络发送前即记预算，重定向响应也消耗一次。实体流式读取 hard cap，超过上限立即停止，不能先无界 read 后检查；HTTP头有明确有限预算并拒绝重复关键头、矛盾长度或异常传输。identity 是请求要求，收到非identity仍拒绝；不能采用自动解压后的伪原件。日志只存白名单安全字段/错误码/长度/哈希；Retry-After按有界值解析，不原样复制任意头或异常字符串。

**门槛：** 注入超时/慢滴/DNS阻塞/超大或无限正文、恶意302、环境代理含凭据、重复Content-Type/Encoding、gzip实体、异常长度及恶意错误头；不发生额外请求、泄密或超预算持锁。这里允许本地假运输与时钟测试，不要求真实站点制造错误。

### R6：证券类别及身份声明不可凭正则晋级

原稿宣称不含指数/ETF，同时通用入口接受任意六位.SH/SZ。该正则会接受指数 000001.SH 和 ETF 510300.SH，也无法证明代码未改名、永久证券身份或历史身份。

**必须修订：** 明确二选一：首轮限制在已核实的股票清单；或接受“未验证沪深证券请求代码”，将资产类别/股票属性保留 unknown 或显式 assumed，产品能力不宣称已排除所有非股票。不靠前缀猜资产类别。对新批次明确提供当前成员清单及选择依据，它只支持当前池回顾。

新浪的 request-only metadata 不得在通用 decode、展示 interpretation 或研究分组中被悄悄升级为 source_code/response_identity。腾讯源证券键与 CLI 的 .SH/.SZ 表示需要明确映射，例如 sh601577 与601577.SH是经固定规则对应，不能因两串外观不同制造 declared_instrument 失败，也不能用映射证明永久身份。请求空调整项仅支持未复权请求与day分支，不授予已核实复权语义。

**门槛：** 指数/ETF反例、合法证券响应换符号、无源身份回显、请求与展示声明冲突、错误qfq/hfq分支分别测试；“assumed”始终可见，不能显示已核验身份/单位/历史可得时间。

## 4. 实现必须满足的补充验收门槛

### A. 封套与纯解析

- 对顶层及全部固定子对象验证键集合和精确类型；bool不能当int；重复键拒绝适用于嵌套JSON。
- Canonical JSON规则应约束新格式导入的原件字节，或明确只约束采集器输出；若接受非规范离线封套，不得声称语义相同但字节不同会复用同一raw身份。推荐新格式直接要求规范封套字节相等，不暗中改原件。
- Base64严格解码/再编码相等；sha都是64位小写十六进制；请求URL含重复query、改编码、userinfo、片段、转义绕过或多余参数全部拒绝。
- Content-Type的charset解释明确且唯一。畸形编码、BOM、孤立surrogate、过深JSON、NaN/Infinity和超限字符串应返回稳定错误，不产生内部异常或执行任何来源内容。
- 源无关HTML、身份不符或无法识别的控制正文不能进入raw/捕获目录。已识别行情的数值错误与普通非行情响应分开，前者原件可以保留且失败原因可查。空行情捕获可以保留，但不能发布空快照。

### B. 源量与既有兼容

- 使用合成小数token（例如123.45）、整数外观token、空白、非法数、负值、超范围/精度和非有限值。合法小数源量保留逐字token，source_quantity_decimal=pass；source_volume/volume_shares/amount_cny为NULL，无integer_fraction。
- decimal_value本身不检查非负，调用处必须显式检查；负源量不能被quantity未规范化掩盖。合法、缺失、非法/负值采用不同源量检查原因。源额维持原尺度，不显示标准CNY。
- price-only研究继续使用有效OHLC；量能/VWAP入口明确无法评价，不能NULL→0。测试实际query/export/API，不只测试_row对象。
- 新行为只作用两个新format_id。旧四格式、既有精度/条件诊断、NULL/计数/源序/query_id和不可变旧快照语义保持不变；无需全局版本或schema迁移。

### C. 状态、截断与覆盖

- 腾讯条数达到请求count标count_saturated/truncated_possible，仍少于count也不证明完整；较早上下文可能使总行数超过请求自然日数，不能再用该计数推导重复或结构坏数。分别报告实际范围、范围内/早于start行数、重复标签及源序，晚于end拒绝。
- 新浪恰好返回datalen通常是正常最近窗口，只能说count_saturated/recent_window；两来源均不能仅因恰好达到count拒绝合法原件提交。无论哪一源，committed只代表存储提交，coverage始终unverified。
- empty_result、source_error、row_limit、timeout、blocked、budget_exhausted、corrupt_capture和无法核验的commit具有不同原因。日志里有失败但其余块pending时，run必须停止并给出明确可恢复性，不能显示一直运行或全部完成。
- 相同请求/实体/头/解释/版本才满足原件幂等。只改qt也生成新原件/快照；日志应区分市场单元格变化与附属字段变化。相同实体但头字符串改变也可能形成新封套，不能承诺所有“同样历史价格”都会复用。
- 源限制按来源保留，blocked run不能通过自动新run/换root/换IP继续；新显式观察不意味着可以绕过仍有效的429/封禁。首版不实现自动解除未知时长的限制。

### D. 多块上下文边界
