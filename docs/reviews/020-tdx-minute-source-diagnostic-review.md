## P1：HTTP 截止格式仍属候选

安装 SDK 第 108–132 行接受 8／14 位公开时间字符串，转换为 `YYYY-MM-DD HH:MM:SS`。第 1173–1196 行把这一 19 位字符串传给底层调用，第 1234–1246 行将其置于 DLL 请求。该静态证据无法证明原 HTTP 入口对 `end_time='20260930150000'` 执行相同规范化。

合同需显式声明：固定 14 位 HTTP 输入是本轮待验证候选；业务成功码／空数据不证明截止参数被采用。禁止将空返回单独归因于分钟缓存不足。后续单证券刷新可检验缓存路线，但仍不能解决截止格式歧义；同一输入前后变化也只能作有限观察。

若收到记录，必须核原始 Date／Time 与候选解析；超出截止、格式歧义或缺少可解析时间时仅保存失败／未决证据，不宣称取得指定历史三分钟。不现场改成 19 位重试、不转 SDK、不扩大三 POST 上限。完整三 POST 范围须把上述边界写入合同并复核。

本轮尝试读取合同所引行情、HTTP 和刷新官方页面，均返回网络超时；这是获取失败，不能推定文档未提供或 HTTP 不支持。先前已核刷新说明与安装 SDK 仅支持“按证券／周期下载，无日期／条数预算”的有限事实。

## P2 与执行细化

1. **空形状闸门。** 只允许 `result.Value['000001.SZ']` 为对象、外层与证券层 `ErrorId` 精确为字符串 `0`、证券层 `Value` 精确为 `[]` 时进入一次刷新。缺失证券、空对象、Date 空数组、其他股票或未知嵌套形状都不能替代该闸门。首次记录非空时不刷新；明确失败、解析未知或超限均停止。
2. **时间展示与柱语义分开。** SDK 第 1340–1350 行把非零 Time 整数补至六位并按 HHMMSS 解析，这是 SDK 行为，不能直接当原 HTTP 协议。保留 Date／Time 原 token；观测到形状可以提出解析候选，仍需格式依据和缓存对照。禁止自动补秒、猜四位 HHMM、猜日期偏移或把零 Time 当已确认午夜。时区、标签开闭端、柱完成状态及集合竞价归属继续未决。
3. **全部 float32 位型与表示资格。** `<HH5f2I` 仅是 32 字节候选。保存原日期／时间字段、五个浮点位型、数量整数及尾字节，禁止把两位显示小数当作缓存真值。每个 finite binary32 应独立求精确有理数／Decimal，再检金额和各报价是否落入 DECIMAL(38,18) 的幅度及有效 scale≤18；非有限或不可表示值保留原位并报告。二进制价格近似也不能凭“两位 A 股报价”自动取整到分。
4. **限额含义。** 10／45／10 秒、1 MiB、16 MiB 副本上限只约束本方请求／保存；客户端单证券完整分钟历史及内部任务仍无固定预算。大文件流式哈希须记录读取前后身份、大小／mtime，变化记不稳定观察，不作候选对账。HTTP 超时后不能再次刷新、停止用户客户端或宣称后台已取消。

日线 Volume 已出现 binary32 量化；分钟 HTTP／缓存仍须逐位独立对照，禁止自动混源或反推交易所真值。本评审不放行分钟产品导入、指标、实时数据、交易操作或完整兼容。
