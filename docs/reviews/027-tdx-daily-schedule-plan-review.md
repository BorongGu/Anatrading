## 结论

**方向可接受，v0.1 两项 P1 未闭合，尚不批准实现或注册。** Windows Task Scheduler + 单次有限 CLI 能减少每日输入日期和点击下载，复用已验采集／发布边界。7日计划可作为首轮系统触发资格；长期免日常操作仍需连续更新、日历维护、缺口恢复与应用生命周期资格，不能反复手工创建7日计划后声称长期目标完成。

## 必修 P1

### P1-1：派发未知需要同客户端所有采集入口可见

方案允许独立派发日志后保守 `dispatch_unknown`，但现有 `acquire()` 只检查同客户端 `acquisition/current.json`。若“槽已可能执行”已落盘而调用 `acquire()` 创建 journal 前崩溃，手工 `acquire-tdx` 看不到该调度未知；现有终态或无 current 时仍可发 refresh。单个系统任务、IgnoreNew、计划状态锁都不能填补此跨入口窗口。

修订必须定案：同客户端的派发保留先进入**所有 acquisition 入口都会检查的持久状态**，绑定计划哈希／槽／run_id；其创建、所有者核验和 acquisition journal 关联都由同客户端锁保护。未关联的保留按未知阻止新请求，换计划、换 root、手工命令均不能绕过。实现合同可选共用 current journal 或所有入口必查的单个客户端派发保留，避免重复维护两套行情账本；独立调度日志单独阻断调度入口不足。写明原子替换边界与每个中止点的保守恢复，不许用日期／mtime关联。

验收需覆盖：派发保留后、acquisition journal 前中止，释放进程锁后从手工 CLI／新计划／另一 root 调用，全部零新增 refresh；丢失、损坏、身份不符的保留同样停止。只验证同槽调度重入还不够。

### P1-2：旧发布恢复不能算作新槽执行成功

实际 `acquire()` 在现有 `publication_unknown` 时按旧 journal 核账，返回旧 record；它不会用本次 `symbol/target_date` 新建采集。方案“选择最早未派发槽再调用一次 acquire”若直接拿 returned committed 落新槽结果，会把前一日的恢复计入另一目标槽；反过来，派发前提前消耗新槽还可能让未发 refresh 的新日期永久失去机会。

修订必须明确：触发先恢复／核定旧关联运行，恢复调用归属**原槽**，本次最多做恢复，不派发新槽；未关联的旧手工运行也只阻断或恢复自身。新槽派发要求无未终结客户端运行。每个 returned record 的 run_id、计划槽关联、root、symbol、target_date 必须与派发身份全部吻合，否则记录关联未知，不写该槽成功。恢复和新采集的预算分别列明，不让一次触发先恢复后再额外 refresh。

验收需有旧日期 publication_unknown + 新日期 due：恢复 committed 后旧槽终结、新槽保持 pending，零新 refresh/import；返回旧 run_id／不同目标日期的故障注入不得产生新槽成功。

## 需在实现合同闭合的 P2

1. **日期与钟表**：日历原文／哈希及显式 SH 日期名单仍未形成具体实现输入；保留停止越界的设计。使用带明确 +08:00 的 due_at／end_at，并定义注入时钟、前次观测时刻及回拨判据。仅读取“当前日期”不能证明检测了回拨。主机时区检查和上海目标日期计算需分别定义，不能依赖本机默认时区猜测。
2. **外层预算**：按现有正常路径上限粗算，4次身份探测×8秒、5次GET×15秒、refresh45秒、import15秒，已有167秒，另有稳定读取、哈希、解码与磁盘写入。PT3M只能作为强制停止线；需给总预算与可中止剩余阶段，真实验证系统终止实际 Python 进程后留下可读未知状态。不要拿常见7秒实测代替最坏预算证明。禁止杀通达信／工作台。
3. **结束与积压**：最早 overdue、每触发一槽和结束后停请求能保持有限性，但不保证追上每日新增目标。验收固定完整分母，分别报告 committed、closed_no_target、not_covered、dependency_unavailable、dispatch_unknown、pending_overdue，记录到期欠缺。有限计划之后的长期计划续期和追赶另列明确里程碑，保留用户只配置一次的最终目标。

## 范围与简化判断

- 保留工作台一次手动启动约束，首版不加 supervisor 或第二个系统任务，属于合理阶段边界。输出需准确说明依赖；自动登录券商／交易权限不在此数据功能范围。
- 只实现 Task Scheduler 入口。守护模式留为未实现备选，不同时开发。调度状态只存槽和运行关联，原件／请求／发布证据继续复用现有 acquisition。
- 18:00 是工程选择；主站分钟拒绝及日线当日是否已闭合都不能从时钟推定。日线 target observed 与源新鲜度／完整性／单位仍分开。
- 未必要本阶段实现永久全市场调度，必须使阶段明确服务长期目标，随后有日历扩展、连续覆盖及生命周期合同；本轮不能因分钟受限而永久缩掉分钟复盘。
