## 2. 三个直接改变采集设计的反例

**修订可以远早于补取窗口。** 官方记录：2019-03-14 补入 `sh.600455` 在 2018-08-16 缺失的分钟数据；2020-04-21 删除部分 2015 年非交易日日线，并列出 `query_all_stock` 也受影响。另有停牌 OHLC、交易状态、量额修正。由此只能提出“检测本次重取范围内的返回变化”；固定最近 N 日无法保证全历史同步。旧区间重采须保留入口，修订公告可触发显式修复任务，公告完整性仍未知。[官方调整记录](https://www.baostock.com/mainContent?file=modifyRecord.md)

**有历史日期参数仍可能得到当前维护的历史版本。** `query_all_stock(day)` 的日期明确了所描述的交易日；接口未承诺重现过去首次发布版本。当前自选列表也只定义今天选择的回顾样本，不能充当过去全市场或过去自选集合。保存名单内容、来源、选定时间和适用研究范围，后续更换名单生成新任务；不悄悄改变覆盖分母。[证券元信息](https://www.baostock.com/mainContent?file=StockBasicInfoAPI.md)

**同源守恒是局部一致性证据。** 已有 BaoStock 两个交易日的日量等于 48 条分钟量合计，分钟额减日额分别为 **+1.01、−0.15 元**；仅此两日。日／分钟总量相同仍允许分钟间错分，日 OHLC 相同仍允许局部 O/H/L 定义不同。严格记录差异；“每分钟额舍入到整元”的解释未证实，不采用其 24.005 元界作为通过阈值。[已有独立审计 §6–8](../qualification/baostock-samples.md)

## 4. 时间与空结果怎样记录

### 四种时间不可互填

| 时间 | 能表达的事实 | 禁止推导 |
|---|---|---|
| `source_date/source_label` | 返回记录指向的交易日／源标签 | 标签就是收盘或可用时点；当前分钟边界未知仍应未知 |
| `observed_at` | 本系统完整收到这一响应的 UTC 时间，另保留请求开始时间及钟表异常 | 今天取得的 2021 年数据在 2021 年即可获得 |
| `imported_at/committed_at` | 本地解析／发布进度 | 供应商发布时间、交易发生时间 |
| `available_at/known_at` | 仅在有来源、定义与时点证据时填写 | 用抓取时间、文档入库时刻或标签日期补历史首次发布时间 |

连续两次观察由旧值变成新值，只能定位**本系统两次观察间出现了差异**；跨节点、缓存、请求窗口和非原子读取均可能参与。没有供应商版本和时钟证据时，不能宣称精确修订时刻，或把后一次值判作交易所“最终真值”。固定快照内的前缀不变性须继续通过；更换快照引起的变化明确标为数据版本变化。[WP99-4 §II](https://www.philadelphiafed.org/-/media/frbp/assets/working-papers/1999/wp99-4.pdf)、[FRED 版本维度](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)

### 空结果判定表

| 已有证据 | 可以记录 | 不可做 |
|---|---|---|
| 有版本及覆盖范围的日历确认目标为休市日 | “该日无采集目标／跳过”，保存原因；不计为行情更新了一个交易日 | 仅根据星期或空行情判断休市 |
| 日期落在已核上市区间外，身份及边界有证据 | “该证券该日不适用”，与成功取得行情分开统计 | 依靠当前上市 status 排除过去退市证券；默认退市日整日不交易 |
| 该日状态证据确认停牌，返回文档所述零量日柱 | 保留源柱与停牌／源补值资格；可核查该日日线表示已取得 | 将填入的 OHLC 当成当日实际成交价；将停牌等同普通真实零成交 |
| 该日状态确认停牌，但分钟为空 | 记录状态证据及空返回；分钟覆盖仍待其省略规则证明 | 自行生成 48 条零量柱，或仅凭日线状态就宣布分钟覆盖通过 |
| API 成功码但列表／行情为空，状态或覆盖规则不足 | “空结果原因未明／待补取”，保留请求与时间 | 把空解释为证券不存在、无成交、全部同步或旧数据应删除 |
| 有非空返回但目标日缺失、块／页中断、名单部分失败 | 部分取得；展示具体未覆盖项 | 用行数、最大日期或完成百分比掩盖缺口 |

集合竞价、午休、临时停牌与盘后阶段须由版本化源合同分别约定；本轮无新真实样本。固定 48 根仅是已审两日的观测，不成为全市场完整性规则。

## 5. 同源日／分钟对账的启用前提

对账前固定同证券、同交易日、同复权、量额单位及累计域；分钟边界、阶段与成交类型覆盖应有证据。保存两次抓取各自的时间／哈希；同一次采集任务内先后返回的日线与分钟不保证来自供应商的同一原子版本。

满足覆盖前提时，精确计算 `ΔV = ΣV_5m − V_d`、`ΔA = ΣA_5m − A_d`，以及首 O、最大 H、最小 L、末 C 与日线的差异。若字段成交集合或柱定义未知，则输出条件诊断，不能以其不相等直接宣布任一数据错误。舍入解释需独立源证据，保留严格差值；不得回写金额使其守恒。数量加总相同也不能证明每个时间槽正确，因而不能直接开放分钟 RVOL、局部形态或实际 VWAP。[003](003-volume-microstructure.md)、[BaoStock 实测](../qualification/baostock-samples.md)

供应商可以为不同字段筛选不同成交类型，已有其他市场官方实现说明这一点；在 BaoStock 端仍待验证。`A/V` 是否为同覆盖集合的实际成交均价，与返回成功及 Decimal 无损保存分别验收。[Alpaca 作者实施说明](https://alpaca.markets/learn/stock-minute-bars)

## 6. 什么时候允许显示“更新成功”

建议分别显示 **已提交的源观测、目标范围覆盖、重叠区变化、分析资格**；任何单项不得替代其余项。“更新成功”必须限定名单、频率、日期范围及本次版本，且以下证据齐备：

1. **任务分母确定**：请求前固定名单和日期；每个证券×频率×目标日均有结果，不因失败、停牌或中途改名单减少分母。合法不适用项单列，不计作取得行情。
2. **响应确已完成**：身份／请求回显、业务码、字段、逐块读取结束和数值检查符合版本合同；完整响应已按提交账本发布，取消或提交结果不明不能标成功。
3. **覆盖可解释**：有相应日历、证券状态、源省略规则及标签范围证据；应有记录均存在，重复／缺口明确处理。未验证的分钟槽规则只允许显示“覆盖待验”，不能用正好 48 条替代。
4. **目标日确有结论**：区别目标数据已取得、休市无任务、停牌源表示、尚未入库和失败。只有较早日期的非空返回不满足目标。日历／状态证据本身也须记录版本和获取时间。
5. **变化及限制可见**：重叠比较完成，变化、未返回记录、未对账或未解释差异均明示；必要证据不足的项阻断对应资格。对账覆盖已证实时，未解释的应守恒冲突阻断“覆盖核验通过”。一般源定义未知可保存观测，但不能宣称交易数据完整。

即使五项通过，状态文案也仅说明**这个任务的源合同范围内**完成，不保证历史不再修订、所有交易均被供应商覆盖或当时可得。当前 G1 的两个交易日尚未覆盖停牌、元数据、连续更新和全部分钟语义，因此现阶段宜允许“已提交 N 行，覆盖待验”，保留严格成功门槛。[已有 G1 尚缺证据](../qualification/baostock-samples.md)

| ACQ06 | 先观测旧历史后取得修订值，期间改变名单或源文档版本 | 两次时点、名单、合同分别可还原；历史 `known_at` 保持未知；固定快照查询不变。超出 K 的修订不得冒充已检出 |
| ACQ07 | 请求中断、接受取消、响应已保存但提交返回中断、再次启动 | 尝试／原件／快照状态一致；按账本确认结果，无半完成水位。既有存储测试不能替代新增采集路径的故障测试 |

**停止条件**：源身份、空结果原因、分钟覆盖或精度无法核实时，保留原证据及“未知／部分”；停止该项资格晋级。所有必需任务闭合前不扩大为后台全市场采集，不开放历史时点回测，不宣称投资有效性。定案应先选择一个可实际验收的最小范围，再审查采集合同及新增元数据边界。
