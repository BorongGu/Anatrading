# 010 · 长城证券程序化交易接入

2026-10-08。用户为新开户个人客户，券商是长城证券，尚未开通自动化接口，希望自编程序通过接口自动下单。本文仅做接口研究和接入选型，不改变既有研究系统门槛，也不发送账户、下单或撤单请求。

## 当前结论

本机 64 位通达信及 TQ 服务已就绪到文件／监听层。实盘自动委托还需券商对应的权限和软件版本。长城官方 GWT 提供客户端内自编 Python 策略的证据；独立 Anatrading 进程直接调用的交易 API 尚未确认。内置策略与独立进程是两个不同的验收目标，不能以其中一条成功代替另一条。

| 路线 | 已核一级证据 | 尚缺的证据 |
|---|---|---|
| 通达信 TQ | 官方交易函数说明：实盘通常提示人工确认，自动委托须联系开户券商开通并使用对应支持 TQ 的版本 | 长城是否提供对应版本；该新账户资格；真实接口契约 |
| 长城 GWT | 官网及 Python_API 手册提供客户端内 Python 模型、`init`／`handlebar`、委托及状态查询功能 | 该客户测试／正式权限；实际安装版本；独立进程接口；环境内允许的第三方库 |
| QMT／MiniQMT／PTrade | 本轮在长城证券一级资料中没有找到可确认的开放说明 | 不能据搜索无结果宣称券商不支持，也不能借用其他券商的门槛 |
| 外部委托程序设置 | 尚未实际查看该界面；本机原生 UI helper 连接失败 | 程序路径设置本身不能作为自动委托权限或 API 契约的验收证据 |

## 当前接入决定

1. TQ 保留为只读行情候选，继续真实导出逐字段验收；交易方法不进入行情入口的转发白名单。
2. 先向长城核实 GWT 测试账号及客户端外 Python API。这里只准备询问内容，由用户联系营业部／官方客服；不代申请、绑定资金账号、接受协议、转换柜台或购买服务。
3. 若仅允许客户端内策略，将其保留为待用户选择的候选。首个模拟模型采用 GWT 自身行情，以减少跨源时间、单位与复权差异；模拟订单需形成闭环。
4. 若长城提供独立接口，先固定对应官方 SDK／文档／测试环境，再写该通道的具体合同与反方评审。没有确认接口之前不编造交易 adapter。

模拟闭环最低证据包括：可追溯的自编逻辑触发、委托意图、模拟受理或拒绝、最终状态、重复触发不重复委托，以及明确的测试环境身份。单次函数返回、日志打印和回测收益各自不能证明这个闭环。模拟通过后，实盘权限与实施仍另行验证。
