# 002 · 自动取数、软件兼容与数据授权

调研日期：2026-10-03。范围：A 股个人研究；全市场日线、自选股分钟，个人 Windows 本地优先；日线判断波段，分钟线择时与复盘。本文只做接口选型、数据契约与验收设计，业务编码须等待总方案及反方审查定案。

2026-10-04 进展：总体设计已通过 G0，BaoStock 五组匿名小样本请求成功，结果及 SDK 边界见 [G1 实测报告](../qualification/baostock-probe.md)。下文保留 10-03 的资料调研状态；当前客户端兼容、全市场覆盖和连续更新仍未通过。

**结论：有机会省下日常手动导出。优先实测通达信官方本地 TQ 接口；无客户端路径可先验证 BaoStock 的盘后日线与 5 分钟研究能力。Financial-API 自称同花顺官方服务，独立身份背书尚未核实；其文档也不能支持公开分钟取数。** 免费长期可用、沪深京全市场完整覆盖、完整分钟历史、当前真实软件逐字段一致，目前均未获得实测证明。

- **已验证的资料**：通达信官方 TdxQuant 文档、Financial-API 项目仓库与同花顺 iFinD 官方文档、BaoStock 当前官网文档和 PyPI 发行信息、AKShare/mootdx/pytdx 主仓文档及部分源码。Financial-API 的公司身份验证状态见 3.1。
- **实际访问**：本轮成功读取公开文档/源码。BaoStock 官网由网页调用的公开文档接口读取，包括 `home.md`、`stockKData.md`、`DailyUpdates.md`；网站免责声明也已读取。部分网页正文需要 JavaScript，搜索摘要与当前直读内容有差异时采用当前直读内容。
- **尚未完成**：客户端版本/权限确认、真实行情请求成功、覆盖范围抽测、连续多日同步、实际导出对账。本轮未使用账号、Key、付费套餐或交易接口，未下载全市场行情、连接非官方报价服务器或提交原始行情。
- **取数成功标准**：来源授权适用；真实请求返回成功且数据非空；单位/时间/复权含义确定；与同版本真实软件样本逐字段核对；增量重跑不产生冲突；缺失、修订和过期可见。仅能联网或 HTTP 200 不计成功。

## 3. 同花顺：三个产品必须分开

### 3.1 Financial-API 的身份与日线契约

**身份核验未闭环**：README/服务站点均自称同花顺官方，仓库链接到 `fuyao.aicubes.cn` 和 `lumi.10jqka.com.cn`，但这种单向链接不能证明运营主体。本轮针对 `10jqka.com.cn` 搜索仓库名/服务域名，并读取同花顺 AI 产品首页及其公开脚本，未找到反向指向该仓库或服务域名的背书；GitHub `HiThink-Tech` 页面显示为个人账户，未见公司域名认证。[H1][H9]

因此，以下内容仅认定为**该项目公开的接口契约**。这不足以认定其身份虚假，也不足以将 Key 登录入口设为默认可信。启用前须获得公司自有页面反向链接、可核对的官方渠道说明或明确服务主体/授权合同；本轮不登录、不签发 Key。

公开入口包括 REST、MCP、CLI、Python。单股历史为 `GET /api/a-share/prices/historical`，当前仅 `interval=1d`，单请求一只证券且窗口不超过 10 年；复权取值为 `none/forward/backward`，默认前复权。A 股价格/成交额为 CNY、成交量为股；原始层应显式指定 `none`。响应还要检查业务 `code`。[H1][H2]

仓库另提供 Market Dumps：文档声明未复权全市场约 10 年日线、近 10 交易日增量、公司行动事件的 Parquet 下载。身份和权限核验通过后，可评估该批量入口减少逐股请求；单股验收阶段无需下载全量。原始文件类型、字段精度、北交所与退市覆盖应以实际 Parquet schema/行范围为准。[H4]

**契约缺口**：单股 `corporate-actions/adjustment-factors` 文档介绍包括配股，字段表仅明确现金分红和送股，缺少配股率/配股价；Market Dumps schema 列出这两项。该 REST 字段还没有公告时间/首次可用时间。不能据此默认重建完整公司行动，或证明历史决策时已知这些事件。[H4][H5]

`high-frequency` 文档标记端内专用，返回的是高频动向等指标；公开 Key 不赋予端内取数权限。不能把这个页面当作外部分钟 OHLCV 接口。[H3]

**费用/授权**：MIT 只覆盖仓库软件和文档。README 的累计调用数政策不构成零价格、无限并发或数据再分发授权。官网及账号权限须在选定后留档；当前不声称免费套餐已开通，也不以第三方转载的“永久免费”作证。[H1][H8]

### 3.2 iFinD 的免费口径不同

官方 FAQ 明确“免费账号”附属于已购终端；分钟可能由快照合成，终端与接口连接不同数据源会有细微差异。FAQ 同页分别给出一般收盘后 1～2 小时入库、A 股日行情约 15:07 更新的描述，不能据此给所有字段统一可用时点；应按端点和实测记录。逐笔需要另一个产品。[H6]

### 3.3 普通客户端接入仍待实证

用户已有普通客户端时，先记录产品全名、版本、数据站点、导出菜单和本地数据目录。不能把客户端登录状态当成 Financial-API/iFinD 的登录状态。当前最可审查的普通客户端兼容证据仍是一份真实导出加对应界面/字段说明。

## 4. 通达信：官方本地接口有望省掉重复导出

官方文档给出 `POST http://127.0.0.1:17709/`，请求体由 `method` 与 `params` 指定方法及参数，示例是 `get_market_data`。需要支持 TQ 的客户端先启动。Python 也可加载客户端 `PYPlugins/user` 下的 `tqcenter`；本地模式和付费后台模式须区分。[T1][T2][T5]

### 4.1 入库前必须处理的兼容细节

- **金额**：当前 `get_market_data` 文档写万元，内部转元需要乘 10,000；保留原字符串及显示精度。若返回仅有两位万元小数，其分辨率已经是 100 元，Decimal 无法恢复被舍入的分币数据。
- **数量**：当前契约写“量的最小单位”，旧官方示例写“手”，存在资料冲突。须按实际客户端/接口版本与 `.day` 原始量和真实导出对账；不能只凭“通达信”品牌默认乘 100。
- **填充**：`fill_data` 默认 `True`；研究请求应显式 `False`，并验证 HTTP 路径确实遵守它。服务方提供的停牌记录须带原始状态，与项目自行填充区分。
- **截断**：文档称一次最多 24,000 条；区间/`count` 的优先级需要核对。分页必须验证首尾时间、连续性和重复，不能把返回非空当作区间完整。
- **复权**：官方 FAQ 提示取全部 K 线才能对齐客户端全历史前复权展示。局部窗口、查询日期、公司行动版本和锚点都应进入来源记录。

上述接口参数及单位见 [T3]；数量冲突见 [T6]；复权范围问题见 [T7]。部分版本更新还修复过最后一根 K 线成交量、因子等问题，故接口兼容报告必须带客户端版本。[T8]

### 4.2 更新与盘中限制

`refresh_kline` 可以定向下载 `1d/1m/5m`；其他周期由这些基础周期生成。官方说明盘中下载 1m/5m 只能获得截至前一交易日的数据，且刷新会在客户端显示加载界面、完成后返回。它能减少数据下载操作，不能单独证明当日盘中分钟持续更新。[T4]

如果目标是当天分钟择时，还需独立验证实时订阅/快照的采样频率、断线补数、分钟闭合与修正；达到这一验收前仅提供历史复盘。`tqserver` 文档里的“分笔”也不能直接提升为交易所逐笔成交/委托完整流。[T5]

### 4.3 原生文件降级

公开解析源码显示：A 股 `.day` 每条 32 字节、`<IIIIIfII`，整数价格按品类缩放，金额为 float32；pytdx A 股 DataFrame 路径会把原始量乘 0.01，需避开显示手数与原始股数混淆。`.lc1/.lc5` 示例格式是 `<HHfffffII`，价格和金额为 float32，量为整数股。[L1][L2]

这属于第三方格式证据，仍需验证用户真实版本。先复制已完成写入的文件到私有快照，再记录大小/哈希并解析；校验记录长度、日期、证券、单位和末条完整性。自动扫描已下载文件可省重复导出；补历史仍依赖客户端实际下载能力。不要在客户端原数据文件上写入或修复。

## 5. 免费替代路径的能力与限制

### 5.1 BaoStock：盘后日线和分钟候选

官网当前声明无需注册、基础服务免费。2026-09-21 发布的 0.9.4 新增 VIP Key 节点；免费基础服务与 VIP 的权限、费用不得混为一谈。当前官方数据范围写股票日线从 1990-12-19 起，分钟写“近 5 年：2020-01-03 至今”，两种表述在本调研日期并不一致，最早可取日期须抽测。[B1][B4]

`query_history_k_data_plus` 支持 `d/w/m/5/15/30/60`，复权标记 `3/2/1` 分别是不复权/前复权/后复权。股票 OHLC/成交额单位为元，量为股；分钟 `time` 格式为 `YYYYMMDDHHMMSSsss`，量额表示所选区间累计。停牌日可能有前收平铺、零量零额的服务方记录，并有日线 `tradestatus`。BaoStock 使用涨跌幅复权算法，官方明确与通达信/同花顺可能不同。其公开股票代码参数只列 `sh/sz`，本轮未确认北交所、转板与完整退市历史覆盖，不能称作已满足用户“全市场”需求。[B2]

官网给出日线约 17:30、因子约 18:00、分钟约 20:00 入库；这些是资料中的更新时间，尚未测得实际到达延迟。适合当晚复盘，无法据此承诺当天盘中择时。新版另有按交易日获取全市场日线与当日复权因子的接口，可作为后续增量入口。[B1][B3]

### 5.2 AKShare：按端点确定语义

AKShare 是数据接口集合；每个端点继承各自上游的覆盖和限制。东财日线 `stock_zh_a_hist` 的量为手、额为元；`stock_zh_a_hist_min_em` 1 分钟仅近期 5 个交易日且不复权，文档特别指出只有最近交易日有开盘价，其他日期开盘价为 0。5/15/30/60 分钟仅承诺近期数据，不能依据一个很早的 `start_date` 推断服务器保留多年历史。[A2]

源码确认 1 分钟分支取 `trends2` 的 5 日窗口后再本地裁剪日期；其他分钟同样先获取上游窗口再裁剪。库还会转换数值为 Pandas 数字类型。若要求审计原始十进制文本，不能只保留最终浮点 DataFrame。缺失开盘价必须保留缺失语义并阻止相应 K 线分析，不用前收或其他值伪造。[A3]

本轮不使用未核验授权的上游接口作真实请求探测；不通过更换 IP、抓 Cookie 或绕过限制提高可用性。

## 7. 建议的两条实施方案

### 方案 A：通达信官方本地接入，原生文件兜底

**适用条件**：用户可运行支持 TQ 的客户端，目标权限和数据历史满足要求。

1. 对一个证券、少量已结束交易日，分别核验本地 HTTP 与真实客户端导出；初始取未复权、关闭填充。验证业务错误、字段单位、时间边界与数据量。
2. 验收通过后，盘后定向刷新并获取日线/1m/5m；保存原始响应私有快照与逐次清单。连续多日重跑后才称为可持续同步。
3. HTTP 不可用时读取用户已有 `.day/.lc*` 的私有快照；仍不兼容时回到一次真实 CSV 导出。终端未下载的数据显式缺失。
4. 当日盘中分钟另立验收，不由盘后刷新能力推定。此方案只接行情方法，Anatrading 后端只允许明确列出的读取操作，避免把通用 `method` 转发器暴露给前端。

**代价**：客户端需运行，更新可能出现加载界面；版本变化和历史容量需持续抽验。**停止条件**：数量单位冲突未解、权限不符、当日柱状态无法确认、同源对账存在无法解释差异。

### 方案 B：独立 API 完成盘后研究

**无 Key 起点**：BaoStock 基础服务做未复权日线和 5 分钟盘后研究；不显示“1 分钟实时择时可用”。先实测少量证券与指定日期，确认数据范围及现行条款。

**Financial-API 日线选项**：先完成身份核验，再由用户取得 Key 并确认费用/权限，随后才可采用该日线来源。全市场阶段评估 Market Dumps；不提前接入付费 iFinD。BaoStock 分钟与其他来源日线须各自保留来源，跨源聚合一致性通过后再用于同一实验。

**代价**：不同供应商复权算法、金额精度与交易时段可能不同。**停止条件**：把盘后数据当盘中可得、以补齐日期为由填假柱、用不同源在同一序列里静默补缺，或将前复权局部增量直接接到旧锚点历史。

AKShare 先用于指定端点的研究对照；mootdx/pytdx 远程协议、iFinD、TdxAiData 不作为上述方案的隐形依赖。

## 8. 总体数据架构必须固定的事实与约束

| 对象 | 最少需要保留的语义 | 禁止的推断 |
|---|---|---|
| 原始快照 | 来源/端点/客户端或 SDK 版本、证券完整代码、请求窗口与参数、抓取时间、文件哈希、原始单位/编码 | 同品牌接口单位完全一致 |
| 标准 K 线 | 未复权 OHLC、股数、元金额、周期、原始时间标签、时区、交易日、柱是否完成、质量状态 | 日期零点等于数据可用时间；空值等于零 |
| 时间记录 | 柱区间/标签规则、服务端时间含义、本机 `observed_at`；未知服务时点保持未知 | 历史 OHLCV 下载时间能证明历史发布延迟 |
| 公司行动 | 事件类型、除权日、公告/生效/已知时间（若有）、因子方法、锚点、版本 | 单一除权日足以构成 point-in-time 数据 |
| 增量与修订 | 每次请求范围、重叠区、旧新版本和差异原因；同键冲突隔离 | 最近数据包不会修订历史；前复权可永久只追加 |
| 来源切换 | 切换原因、覆盖差异、单位/时段/复权对账结果 | 多源补齐后的连续序列天然可比较 |

**品类边界**：股票研究还需要基准指数。证券主数据必须区分股票与指数，指数报价的“点”和股票的“元/股”分开。指数源的量、额应保留其聚合范围和原单位，不能统一乘股票手股倍率；`指数成交额/指数成交量` 即使数值可算，也不能直接解释成指数点位上的成交均价。对指数禁用未定义的股票 VWAP/换手口径。此项为量纲与品类语义推论，具体指数源字段仍需逐项验收。

这些是本项目设计要求。建议从单机私有文件与简单清单开始；是否引入数据库及列式文件应由总方案的数据规模、查询方式和复现需求决定，无需在接入研究阶段建立复杂基础设施。

**软件无法补足的数据**：多年缺失分钟、完整逐笔成交/委托、买卖方向真值、队列位置、真实持仓成本分布、历史首次披露版本、退市/历史证券池完整性，都需要对应真实数据及授权。日线或 5 分钟柱无法唯一重建这些对象。当前资料也未证明任何免费单源同时覆盖它们。

“前缀不变性”应限定在固定来源快照、固定事件/锚点和固定算法版本下。供应商纠错与前复权重算需要生成新数据版本，不能悄悄覆盖后再要求旧结果不变。

## 9. 真实导出逐字段验收

### 样本与证据

首轮至少选择沪深各一只普通股票，并加入一段除权、停牌/复牌或新上市边界。分钟样本覆盖开盘、午间边界、收盘集合竞价以及有零量/缺口的情形；不能预设每家数据一定有 240 根。

每个样本保留客户端产品/版本、数据站点、导出时间、证券、周期、未复权/复权选项、单位显示、实际原文件 SHA-256。文件和界面证据只放私有验收目录；仓库只记录样本类别、对账方法、差异数量及通过状态。

| 字段/行为 | 对账方式与通过条件 |
|---|---|
| 证券 | 代码和市场完全一致；指数、股票、ETF不依相同数字代码混用 |
| 时间 | 逐行匹配日期/时间；确定开始/结束标签、Asia/Shanghai、集合竞价归属及午休规则 |
| O/H/L/C | 同源同口径与导出逐字段比较；原生文件另用独立解码核验；未经解释的 0 开盘不通过完整 OHLC 验收 |
| 成交量 | 先保留源单位，再转换为整数股；证明换算倍率；手数若被舍入必须标精度损失 |
| 成交额 | 证明元/万元；按源文本分辨率或 float32 编码误差设定容差并记录推导，拒绝通用“误差小于一分钱” |
| 复权 | 先核原始价，再核事件、因子、锚点及查询范围；不同算法不强行逐价相等 |
| 前收 | 分别保存前一条实际收盘与供应商 `preclose`；除权日两者可能有不同含义 [B2] |
| 缺失/停牌 | 缺行、空值、零量、服务方停牌平铺分别标注；验证项目未自动填充 |
| 分钟聚合 | 仅在交易范围及统计口径一致时，检查量额和、首开末收及高低极值与日线对应；差异查明前不自动修正 |
| 增量/故障 | 同请求重跑幂等；中断重试不漏页；重叠区冲突报告；空结果/过期结果不能伪装成功 |
| 因果时点 | 盘后下载不能用于当日盘中决策；未完成柱禁入收盘信号；固定数据版本下追加未来柱不改变历史计算 |

**当前验收状态：以上为当前客户端/API 的待执行协议。主线已取得通达信第三方公开历史原始文本等样本，它们仅证明所测样本的格式兼容；本轮接口及同花顺当前客户端仍未完成真实取数/导出对账。**
