# 049 行内变化差异：编码前限定方案

2026-10-13 UTC；基准 main `1b30882`。**待独立设计审查，未批准实现，未运行产品测试。** 本方案只补充已有候选行的源事实回查，不恢复全窗删留扫描。

## 1. 值得做的最小问题与公平基线

固定用户已选的目标、同伴、截止与049完整121日期网格，回答“这个60区间窗中，双方相邻源收盘变化差多少，哪些区间差得较大，如何打开双方原版本核对？”现有 `PeerNeighborResults.tsx` 显示全部原价与同跌符号，未直接显示这组匹配窗口的幅度差。用户可以手算，但需要重复读取相邻四个价格再比较；本补充将该确定运算就地列出。仅此可见操作缺口足以支持小型便利功能，实际省时、判断改善和市场增量仍未验证。

旧通用pair后端已有float64对数变化，不能宣称整个产品没有逐区间变化；其pair交集、变换和来源资格不等价于049的完整组简单变化。不得改用旧API来拼接本表。

前置固定合成见证中，简单幅度/交叉贡献候选U0漏掉一次首位翻转，而加入双方最大绝对变化差的全部并列后U1已覆盖它。该见证的独立核对结果由本轮负责方确认，故新增全60删留扫描的增量门槛失败，保留STOP。本方案不复跑或扩样，也不推论最大差一般能定位排名原因。变化差无须Pearson可定义，常量源价仍有明确答案。

本次实际阅读TradingView官方资料：

- [Pine跨标的数据说明](https://www.tradingview.com/pine-script-docs/concepts/other-timeframes-and-data/)包含60bar简单收盘变化的跨标的相关示例，使用 `request.security` 与 `ta.correlation`。首次直接抓取失败，后通过官方域名搜索返回的完整示例核对；未运行Pine。
- [Compare](https://www.tradingview.com/support/solutions/43000543053-compare-see-how-symbols-perform-side-by-side/)支持多标的同百分比刻度、独立价格刻度或分窗；百分比基准随可见起点变化。
- [CC](https://www.tradingview.com/support/solutions/43000502022-correlation-coefficient-cc/)默认close。默认价格水平CC不能充当唯一竞争基线。

正式比较的假设必须是相同数据版本、日期/缺失规则、调整语义、相邻简单变化和60窗；允许对照用合理Pine脚本计算同样差值。外部行情不能确认一致时，不做数值优劣比较。当前仅比较本仓库旧屏幕与新增便利操作；没有TradingView实时操作或真人对照，不能称TradingView做不到或已超越。

## 2. 冻结范围和界面

每个现有候选的“来源与回查”单元格增加默认关闭的“变化差异”，保留既有候选顺序、相关/名次/并列、失败原因、同跌明细、来源表及全部成员。打开后给固定说明，再给默认关闭的“前60区间”“当前60区间”两个窗口；明确显示日期边界。

打开某窗才显示该窗完整60行，按精确绝对差降序，绝对差相等时按结束日期升序，仅确定显示顺序。无top-k、阈值、过滤、自动推荐、排名徽章；即使60项全并列也全保留。不默认选某个最大日期，不把该排序并入候选相关排行。

每行列：前日期→结束日期；目标简单变化（%）；同伴简单变化（%）；目标减同伴（百分点）；双方回查按钮。变化/差以4位小数显示、明确为舍入值；每个非零量保留精确正负说明，舍入为零标“正/负，显示未分辨”，精确零标“精确为零”。所有行均可展开“精确计算”查看双方四个规范源价及三项精确分数表达式；有限小数不会冒充精确值。差异单位为百分点，例如目标+1%、同伴+3%，差为−2个百分点。

入口说明：“按同期源收盘价变化对比，差值为目标减同伴。差异大小不表示排名原因。”打开窗口后补一句：“按绝对差从大到小列出全部60区间，同值按日期排列；显示值已舍入，精确值可展开核对。”百分比/百分点直接标在列名，原有经济收益、PIT、公司行动、复权与来源限制继续展示。相关贡献、异常、错价或预测等解释不属于本计算，其技术边界留在设计记录，不在每个候选重复长串警告。

两按钮仍调用 `onOpen(snapshot_id, date)`，分别为原目标/原同伴数据版本及该区间结束日期。前日期可见，打开的是该版本截至结束日期的前缀；不自动聚焦源序号。展开、切窗、排序本身无HTTP；点击回查允许既有回查流程原本的请求，不添加新请求类型。

## 3. 输入、精确运算和界限

仅接收已经通过现有DTO与身份核对的不可变报告。沿用完整组来源关闭规则；不重新认证来源，不按pair重新取交集。目标/同伴都必须完整通过121端点核对，任何一个坏点关闭该pair的两窗，包括坏点落在尚未打开的另一窗。其他成员不合格使整组关闭。无缺失填充、缩分母、前移截止、猜测单位或来源修复。

复用 `peer-decline-details.ts` 的三层核对规则：整组来源标志/原因与成员资格；目标/同伴身份/角色/唯一性；121日期严格增序且末日为cutoff、精确对应端点、正安全整数且不重复的源序号、空异常原因、规范正Decimal文本。现DTO负责全部成员/完整报告格式约定；新helper不把部分对象认证为完整来源。相关null/常量原因不构成源价计算的拒绝条件。

正Decimal(38,18)沿用现helper的规范表达：最多20位整数、18位小数、总长度最多39，拒绝指数、负/零、前导零、尾随小数零和超长。先检查字符串，再定标18位BigInt，得到 `1 ≤ P < 10^38`。不得使用Number/parseFloat/浮点中间值。

对每条边，目标前后整数为a,b，同伴为c,d，全部为正：

- 目标简单变化 `x=(b−a)/a`；同伴 `y=(d−c)/c`。
- 有符号差 `δ=x−y=(b*c−d*a)/(a*c)`；分母严格为正。
- 百分比显示为 `100*x`、`100*y`；百分点显示为 `100*δ`，不二次减已舍入显示。
- 差分子绝对值 `<10^76`，分母 `<10^76`；比较两行绝对差用交叉乘积，绝对值 `<10^152`（至多505bit）。每次仅单条比值运算，无累乘、LCM或窗口总分母增长；输入先验界限足以限制BigInt。
- 显示以绝对分子乘 `100*10^4` 作整数商余数，half-even到4位小数，再按原分子恢复符号。最大差中间值 `<10^82`；零/符号始终看原分子。精确分数无需约分即可正确展示，避免新增通用有理数框架。
- 前窗边为(0,1)…(59,60)，当前为(60,61)…(119,120)。共享一个价格端点，不重复变化。每窗排序只依赖自己的60条变化；完整121端点资格仍是两窗共用核对规则。

直接整数代数支撑公式与界限，不新增统计估计或市场假设。界限异常、无法核对输入或算术不变量失败时显示不可用，不降级到float或显示部分排序。

## 4. 最小实现形态与旧行为保护

拟新增一个049专用源价pair校验模块，将现有正价解析、源端点验证及外层核对规则原样抽取，返回已验证日期和双方BigInt价列或现有三个失败原因。`peerDeclineDetails` 只替换校验调用，计数、返回结构、失败优先级均不变。新变化helper复用该核对规则；不改DTO、API、analysis_id、后端、Store、依赖或权限。若无法等价抽取，先停下复核，禁止顺便放宽或“修复”旧约定。

显示复用现有 `groupPercent` 的有界BigInt、half-even四位和舍入零符号语义。优先提取一个很小的整数比值显示函数，明确接受 `%` / `百分点` 单位；保留 `groupPercent` 包装器所有旧文本逐字不变。不得对已格式化字符串做含糊的百分号替换，不改现有ExactRatio DTO。新增表在旁边补充精确零/正负说明。共享formatter仅显示已经由各自调用方核对的整数，不承担来源认证；旧groupPercent继续接收既有合法分子/分母各至4096字符的完整输入域，不得套用新pair的76位上限。76位分子/分母限制仅来自新的源价计算；提取显示函数不能缩窄旧完整组均值等分数的约定。抽取扩大到所有既有groupPercent调用的回归验收，禁止顺带重构通用数字系统。

UI用独立子组件包住新增交互，保留当前无hooks的 `PeerNeighborResults` 顶层形态及既有直接树遍历测试。采用普通React state与原生details的 `onToggle`，从 `event.currentTarget.open` 同步状态；按open条件挂载内容，不能只用CSS/details视觉隐藏。嵌套toggle须核对事件来自自身，避免子窗事件改变父入口状态。

外入口关闭时不调用新源价校验/差异计算、不创建变化行DOM。外入口打开才挂载pair内容并验证完整121点；窗口打开才挂载对应60条计算/表格。关闭卸载内容，重新打开允许重算；不做全局缓存/任务队列。按报告 `analysis_id` 与peer身份key只重置身份已变化的子组件。相同ID的新report对象不保证关闭展开项：允许保持展开，但源价验证、窗口派生值与回查回调均使用当前props重新计算/构造，不在state中保存旧报告、旧结果或旧回调，不按ID跨报告缓存。无需增加效果同步或对象版本机制；父层仍遵循现有报告不可变替换约定。

这只避免新增功能首次渲染时49×120计算与行DOM。既有原价/同跌明细仍为现状；用户逐个打开全部pair和两窗仍可达到49×120行，无未测的流畅性承诺。静读能证明挂载条件与有限算术，不能证明真实布局、键盘操作、焦点、原生toggle时序或浏览器性能。

## 5. 冻结验收与停止条件

实现前先由独立反方审查本方案并逐项答复。以下为后续验收要求，本轮只写设计，均未执行：

1. 独立整数/有理数参考核对手算例、混合尺度、正/负/零、双方同涨或同跌但幅度不同、最小正价与Decimal最大价；包括极端巨大比例及显示为零但精确正/负。百分比/百分点、half-even两种平局舍入正确。
2. 固定60窗，包含最大值多并列、相反符号而绝对差相等、显示相同但精确顺序不同、全部为零60并列；完整保留每条边。不能用舍入值排序或截断并列。
3. 121点核对规则与现同跌非法输入矩阵对齐，含坏点在未打开窗、缺失/额外日期、重复/无效序号、身份错误、整组另一成员关闭。常量相关无定义仍列源变化；不可用无零值替身。
4. 抽取前后旧同跌helper全部返回值一致、原测试期待不变；既有groupPercent在全部调用场景的文本保持一致，包括null、负值及非零舍入零；补充既有校验允许的4096字符大分子/大分母（含分母显著超过76位）回归，核对旧包装器文本逐字一致；新视图移除后既有报告SSR内容与回查行为一致。保留失败行/候选顺序及DTO、API、analysis_id。
5. 用既有合成报告和独立参考核验60+60分割；改变当前窗内部价格且保持完整合法时，前窗值/顺序不变。共享端点改变可合法影响两窗，不误称独立。报告不能接入截止后的端点。分别覆盖不同analysis_id/peer的key重置与同ID新report对象替换：同ID可保留展开状态，但必须重新使用当前props派生值/回调，不能显示旧结果。后者用同ID、不同合法源端点的合成报告，在纯计算/内容SSR层核对输出来自第二个对象，并静读确认挂载组件无跨对象缓存或旧闭包；此隔离替换用例不冒称已通过DTO身份认证，也不代替真实React重渲染测试。
6. 初始SSR无新变化行；独立纯内容组件SSR核对完整60行与精确表达式、日期及原version+结束日回调。以无请求spy核对派生/渲染/展开处理不额外请求。现有Node工具能直接检查事件处理与受控内容构造，但不得把静态SSR或手工调用回调称为真实React交互验收。
7. 代码审查验证挂载边界、hooks规则、report/peer更换（含同ID新对象）、打开→关闭→重开、双窗交替、重复toggle、嵌套事件及父组件重渲染。浏览器真实交互本轮范围外，未验证必须列明；不新增测试依赖来掩盖此缺口。
8. 实现获准后才运行全Node与TypeScript/Vite，按最终版本重跑；后端/锁依赖hash核对不变。保留任何首轮失败和修复记录，测试数量不作为产品增量证据。

停止：任一来源/精确性/旧行为无法保持则暂停，不能靠扩大API或变换绕过；独审否定本操作缺口则停止本补充。产品实现及测试、Store/真实行情、浏览器、Windows、性能benchmark、真人效率和预测/交易验证均未在本设计任务执行。没有相关证据就不作对应完成声明。
