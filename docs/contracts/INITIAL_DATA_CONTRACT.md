## 1. 首个完整操作链与范围

用户将一份本地历史导出导入私有目录，查看原值、字段错误和质量差异，在固定快照内按源时间标签截断查看，导出相同记录，并可备份恢复。首批为源值证据与历史展示；标准单位、交易区间或历史可得性没有证据的字段保持未知。

目前可作为回归依据的是 G1 已核的通达信文本、`.day` 文件和 BaoStock 0.9.4 行情解码响应。每种格式的能力按版本登记；当前同花顺/通达信客户端兼容、全市场覆盖、盘中取数仍未通过。源值展示不能自动启用蜡烛形态、实际 VWAP、策略回测或经证实 PIT。

首个实现先完成 Python 本地导入/查询/导出/恢复链，随后同一应用层接工作台界面。保持原目标 F01–F17 及全部后续任务；这一切片不构成完整目标完成。不开启后台全市场下载、持久特征缓存或第二套存储。

首批不解析未合格 `.lc1/.lc5` 为正式行情。它们仍是数值表示与拒绝行为的负例。通用 CSV、同花顺新格式按各自真实样本另建合同，不通过猜列名/猜倍率冒充兼容。

`source_contract_id` 对应不可变合同内容及版本，写入每批清单。调用方只声明格式、证券、市场、品类与单位等输入解释；程序保留声明及证据等级，不提供“用户勾选即可通过资格”的开关。已知样本指纹用于回归，不能由同扩展名推广信任。

来源记录另含 `raw_kind`（原文件 / SDK解码文本）、原件哈希与记录定位。单位、量额累计域、复权、柱标签及定义分别保存 `known / assumed / unknown` 与证据引用；不使用单一全局 qualified 掩盖字段差异。调用方声明只能成为 assumed，不能替换合同已有证据或晋级来源资格。

首批证据主键为 `batch_id + source_record_locator`。保留源证券字段、声明身份和两者冲突；代码/文件名不充当跨市场永久证券 ID。未获主数据核验时规范 `instrument_id` 为空，禁止跨批自动拼接为同一证券历史。同标签重复保留并报告，禁止静默去重或覆盖。

保存 `source_date/source_time/source_label` 原值及可无损解析的排序标签。未知 `period_start/period_end`、闭合状态、交易阶段、首次发布时间保持空并给出原因。日线日期不能补造为零点或收盘时刻。导入工具记录本次 `imported_at`（UTC）；文件提供的采集时点另列为来源声明，不能冒充历史首次可得证据。

当前查询仅允许 `retrospective`，必须指定 `snapshot_id`，按本批已解析的源标签和源序号筛选。这个截断操作不声明历史因果可得性。`assumed` / `evidenced_pit` 暂拒绝，未来有完整合同后单独开放；未知 `known_at` 不能被查询截止值替换。

## 3. 数值与字段状态

确定首批存储类型：源 OHLC 与金额 `DECIMAL(38,18)`，源数量非负 `BIGINT`。Decimal 表示范围为 `abs(x) <= 99999999999999999999.999999999999999999` 且有效 scale≤18；数量为 `0..9223372036854775807`。这是系统明确支持的范围，不声称覆盖所有未来源。源量与规范股数分开，单位未知时 `volume_shares/amount_cny` 保持空；有可核对的合同转换时才生成规范列，原值不变。

已测依赖固定为 Windows 64位 Python 3.14.0、DuckDB 1.5.6、PyArrow 25.0.1。[独立往返报告](../qualification/numeric-roundtrip.md) 的38,763行及34个边界案例支持该选择；报告指纹为 `fc081c094e04c23284f4ad7bb3f223846e0bf8f00e9f3b375644beb20bef223d`。产品入口必须保留独立精确前检，不能用裸CAST校验；最终产品的API/汇总/导出仍须自身测试。

先从原 token/原位精确解码，再验证可无损进入类型。允许删除纯十进制尾零作数值等价检查，原 token 仍由原件保留。超过 18 位有效小数、幅度超过类型、非有限值或不合法 token 各自隔离；不得交给数据库默认 cast 做静默舍入。整数不得经 Float/Double，股票股数不得为适应显示而取整到百股。

binary32 金额用其精确对应的 Decimal；原位/偏移可追溯，源分辨率另存。不能将小数改成“看起来合理”的价格。`DECIMAL` 与 `BIGINT` 的 API/JSON 值均用字符串，空值必须带原因；浏览器坐标转换单列为显示行为，提示和导出使用精确值。

首批数值上下文为 Decimal precision=128、ROUND_HALF_EVEN；原始解析和无损表示检查不依赖隐式舍入。加减/交叉乘法要求 exact，使用 Inexact/Rounded 检查且溢出报错。派生除法暂不开放；不得在 DuckDB 中利用浮点除法冒充精确均价。

汇总结果不回写单值列；使用上述精确上下文与Python整数输出字符串。单值均可存但总和超过列范围时，允许在该更宽的结果上下文内精确报告，结果注明汇总类型；若仍超出精确上下文则明确失败。不能转浮点、截断或把汇总溢出变为NULL。数值负值可解码时保留原件/拒绝定位，业务规则与表示资格分别报告。

质量结果分三层：文件不可解码（保留原件和拒绝原因，无解析快照）；字段不可用（源定位与错误保留，规范值为空）；带标记可观察（如严格量额边界冲突、同标签重复、单位/柱定义未知）。真零、缺失、源补值、部分柱、停牌、无法定义分别命名，没有证据时不推定其原因。

首批检查仅包括结构/编码、数值合法性、重复/逆序标签、OHLC 包含关系、负值、零量非零额、以及有相同覆盖股/元前提的量额边界。未知单位样本的边界结果明确为条件诊断；不据诊断修改金额。基于固定 240/48 根的全市场完整性规则不进入实现。

每个检查的结果使用 `pass / fail / not_evaluated`，未评价必须有原因，不能计入通过。条件量额诊断携带假设ID，正式单位/覆盖检查仍为not_evaluated。质量报告与规则版本随批次冻结，升级规则产生新批次，不修改旧报告。

## 4. 保存、发布与失败

仅主应用进程读写一个 DuckDB；CLI 先同步执行单个导入。所有本工具的数据根访问先取得同一Windows OS字节操作锁（`msvcrt.locking`，非阻塞），锁文件本身存在不代表持锁；进程退出由OS释放。锁覆盖数据库打开、关闭后的备份复制及校验全过程。第二个本工具实例明确失败，不绕过锁。首批不承诺其他OS；禁止外部工具直接打开数据库，不声称该约束能控制不遵守协议的外部程序。采集、UI、计算后续通过同一应用层串行写入。

原件先写入数据根目录同卷暂存文件，写完刷新并算 SHA-256；以 `raw/<前两位>/<sha>` 发布。已存在对象须核对字节/长度/哈希，损坏时停止相关导入，不覆盖。文件名只作清单信息，不能构造物理路径。认证/控制响应和任意 SDK 方法不进入行情导入入口。

BaoStock响应须在持久化载荷之前预检行情信封：当前限定类型96、方法query_history_k_data_plus、匿名用户、成功业务码以及本合同允许的行情字段。登录/登出/认证控制响应属于非行情拒绝，只记录非敏感拒绝原因，不保留其载荷；这项优先于普通损坏行情文件的原件隔离流程。

一个导入的不可变清单包含原对象、来源合同、解释声明、Schema/解码/规范化/质量/数值上下文版本。该清单的规范 JSON 哈希作为批次身份；导入时刻、显示文件名不改变相同解释的内容身份，尝试记录另存。改变单位/身份声明或任一规则版本必须得到新批次。

读取/解码/发布原件前，先独立事务持久化 `attempt_id`、UTC开始时间、非敏感输入说明与running状态。最终由同一数据库事务提交原件引用、批次、解析行、质量报告、快照成员、幂等结果及该尝试的终态。首批一个快照引用一个批次，不复制全部历史。文件级拒绝只发布原件引用、拒绝报告及尝试终态，不产生解析快照；原件读取失败则终态failed及明确原因。多源合并/更新分片水位在其具体合同通过后加入；未实现水位不能显示为采集成功。

单写者在进入提交临界段前执行最后一次取消检查；该点之前接受的取消持久化cancelled且不产生解析快照。进入临界段后不再确认取消成功，只回报提交处理中及最终committed/failed；COMMIT成功为发布线性化点。Ctrl+C/异常使结果不明时，先查询持久化尝试及幂等账本，再决定终态，禁止先回报cancelled再出现快照。

启动在持有数据根操作锁后恢复：有提交账本/快照的尝试保持committed；无已提交结果的遗留running尝试记为interrupted。暂存/孤儿文件不自动生效、不自动清理。相同内容与解释重跑只返回原批次/快照，新增尝试记录指向该结果；供应商内容修订产生新对象和新快照。故障测试覆盖attempt-start后、raw发布后、事务内、COMMIT成功但返回前四处中止。

读取或导出必须验证所引用原件存在且哈希正确；缺失/损坏明确阻断该快照，不跳过记录。数据目录迁移、自动 GC、在线压实不在此版本实现。磁盘满、重命名失败和数据库/WAL中断需要故障测试，不能只测正常导入。

## 5. 查询、导出与备份

查询身份包含快照、模式、排序标签截止/源序号范围、所选字段、合同与规则版本。无持久特征缓存。相同查询驱动命令行结果、导出与之后的图形；禁止只截断图形而保留未来卡片/汇总。

明确边界：`parsed_label <= cutoff`，源序号窗口上下界均包含；按 `(parsed_label, source_record_ordinal)` 升序，同标签全部保留。没有可解析标签的记录留在单独的unlocated清单，不归入任何截止窗口。无标签截止时仍分开返回可定位记录与unlocated，不丢弃。质量响应分别命名 `selected_rows`、对应记录的pass/fail/not_evaluated计数、`batch_rows`与`unlocated_rows`；批次全局问题另列，不能冒充窗口统计。分页若开放，质量计数按整个选择范围，页内条数另列；导出应用同一选择范围。合同/规则版本从快照继承，不允许调用方覆盖不一致版本。

先闭合精确JSON导出，再启用明确schema的Parquet快照导出；不为首个JSON闭环制作生产重采样器。导出记录源字段状态、资格、清单和内容哈希，失败不改变数据库。Arrow/Parquet产品路径必须对Decimal、整数、NULL/0完整往返；独立实验不能替代其实现测试，未通过时保持未启用，未启用项目不能计作完整合同通过。

离线备份：完成/取消写任务，正常关闭 DuckDB，复制数据库及其全部已引用原件、清单；逐项校验哈希后才标 complete。崩溃目录先按 DuckDB/WAL 恢复，禁止只拷主文件。恢复仅到新的空目录，验证冻结查询结果和引用对象；不覆盖用户已有库。初版不承诺硬件断电/介质损坏保证。

备份持有数据根操作锁直至复制和校验完成；过程中关闭数据库不会释放该操作锁。测试暂停在数据库已关闭/复制未完成处，另一个本工具写入进程必须被拒绝。任何复制/校验失败都不能标complete；应用重新打开数据库前仍持锁。完整操作链含备份时，必须完成这一竞争测试。

## 6. 原型处置与有限验收

现有 12 个原型文件在本合同与受影响模块门槛通过前保持原样。定案后先复制到私有 `artifacts/prototype-v0/` 并逐个核对冻结哈希；正式内核可重写对应文件。JSON 分目录存储、固定交易时段/一分钱阈值、导入即算全部指标的路径不采纳。基础语法/测试仅在逐条复核后复用，旧 26 项测试不直接充当新系统通过证据。

有限验收必须包含：

1. G1 固定真实文件控制值/规范哈希、1228/211 条两种边界计数、跨周期差异原样可重现；未解释差异不因入库消失。
2. 超精度、整数边界、NaN/Infinity、零/缺失、未知单位、错误身份、重复/逆序标签、截断文件的独立负例；每项先有预期行为。
3. 相同解释幂等、不同解释/规则版本分离、供应商新内容不覆盖旧快照；未知身份/单位不能被 API 参数晋级。
4. 已保存快照按源标签截断时，结果、质量计数及导出一致；两种尚未实现的 PIT 模式明确拒绝。
5. 提交前后进程中止、磁盘满/重命名失败、取消竞态、原件损坏、第二写入者；无半发布快照或虚假成功。
6. 精确数据库/Arrow/Parquet/API/导出往返，以及离线备份恢复到新目录后冻结查询相等。

上述通过只放行对应证据工作台能力。仍需当前客户端、完整源语义、证券主数据、自动更新、图形交互及每个分析方法的独立验收，才能关闭相应 G1/G2/G3 任务。首批合同定案不得删除或降低完整目标。
