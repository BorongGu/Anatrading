# 当前 TQ 一分钟来源诊断 v0.2

2026-10-08，待独立反方评审；尚不放行请求、产品格式或指标。承接[当前日线精度实测](../qualification/tdx-cache-diagnostic.md)，验证同一安装客户端的分钟历史来源，保留日线和分钟两种独立资格。

## 本轮唯一对象

`D:\tdx_64`、单证券 `000001.SZ`、周期 `1m`。当前 `sz/minline` 与 `sz/fzline` 未发现文件。本轮只考察少量已结束历史分钟标签；不获取盘中实时数据、不订阅、不取 tick、不请求账户或交易，不借 `5m` 通过 `1m`。

官方[行情方法](https://help.tdx.com.cn/quant/docs/markdown/mindoc-1ctuhthaq5qmg/mindoc-1h10g60jt68sc.html)说明正 count 从结束时间向前取指定条数，开始时间无效；[刷新说明](https://help.tdx.com.cn/quant/docs/markdown/ctx.stock.md/mindoc-1h10fh9m6recg.html)允许单证券 `1m` 缓存下载，盘中仅到上一交易日。完整客户端内部下载量、日期范围和工作时长不可由此接口限定。只使用本机 HTTP，不使用需 Key／积分的 TdxAiData。

安装 SDK 的公共函数接受 8／14 位时间，随后将其转换为 `YYYY-MM-DD HH:MM:SS` 交 DLL。HTTP 是否同样接受 14 位尚未实测，本轮明确将该参数格式作为待验证候选；业务码 0 或空数据都不能证明截止参数生效。禁止改成 19 位或其他时刻重试。若返回标签超过候选截止，或 Time 格式不足以无歧义比较截止，只记录本次观察／参数资格未通过，不刷新、不追加请求。

## 受限观察顺序

1. 每次 HTTP 请求前后持久化 UTC 时刻及本机 17709 的唯一 localhost 监听路径、PID、启动时间；必须始终是同一 `D:\tdx_64\TdxW.exe` 会话，变化立即停止。保存安装 SDK 哈希及缓存文件清单；不读账户配置。
2. 首次只发一次 `get_market_data`，固定 `id=201`、`stock_list=['000001.SZ']`、`period='1m'`、`end_time='20260930150000'`、`count=3`、`dividend_type='none'`、`fill_data=false`，不筛字段，不传开始时间。完整等待 10 秒、连接 2 秒、响应 1 MiB，无重试／重定向／翻页。
3. 仅在完整严格 JSON、同 id、对象形状、外层与证券层成功码均精确为字符串 `0`，且证券层 `Value=[]` 的情况下，允许一次 `refresh_kline`（id 202、该证券、`1m`）。完整 HTTP 等待 45 秒、连接 2 秒、响应 1 MiB；不能称为只下载三分钟。刷新可能出现客户端加载窗口；取消 HTTP 不能证明客户端任务停止。
4. 仅当刷新完整严格响应 id 202、`result` 对象及 `ErrorId='0'`，并且会话仍相同时，再执行一次与第 2 项完全相同的行情请求，关联 id 改为 203。若首次已经返回记录，不刷新、不追加行情请求。合计最多三个 POST。
5. 任何超时、断连、非 200、未知形状、重复键、非有限常量、类型／id 不符、业务失败、会话变化或超限均停止，不重试，不转换 SDK，不停止用户客户端。只记录本次失败及结果未知；不从失败推定未登录或券商权限不足。

全程只在新私有 `artifacts/qualification/tdx-minute-source/<UTC>/` 保存请求、原响应、元数据和可能新生成的 `sz000001.lc1` 缓存副本。核对客户端缓存读取前后大小／mtime 与副本 SHA-256；文件超过 16 MiB 时仅记录大小、流式哈希，不在本轮复制或解码。副本预算是本方保存限制，不限制客户端后台下载。

## 审计和停止边界

响应的日期、时间、价格、Volume、Amount 均保留原字符串。只在观察到真实 Time 格式后解释日期与时间标签；标签的开／闭端、时区、闭合状态和交易阶段继续独立待核，不能因 `15:00` 请求推定末条是收盘集合竞价。

记录实际数组数量、字段长度一致性、可解析数值、重复／顺序及超出请求截止的标签；`KlineTotal=3` 不代替实际三条。空结果、少于三条、存在缺失、语义未决分开报告。不填充、不清洗、不推定停牌或完整交易日。

若产生 `.lc1`，只按已记录的 32 字节候选布局（`<HH5f2I`）作私有位型观察，原位和量价相同比例必须由独立反方复核。对五个 binary32 字段分别保留原四字节／位型和精确对应 Decimal，以独立整数尾数／指数计算核有效 scale／幅度；非有限、范围外、未知字段不补成正常值。候选解码不构成正式格式或单位证明，超过既有 Decimal(38,18) 表示范围时明确列为阻断项，不静默舍入，也不由 HTTP 两位小数输出推定分价精确。

TQ 日线已发现上游量化损失；本轮不能预设分钟 Volume 无损。HTTP 与缓存值各自保留，禁止覆盖／合并，不能从舍入值恢复真值。当前 `.lc1/.lc5` 的产品白名单不扩展，不打开产品数据库或导入。金额单位、源量单位、交易范围、复权、时区、时间标签和真实手动导出对账另验。

本轮成功标准是取得有限分钟响应和缓存精度的可核对观察，或明确停止证据，从而决定是否可为分钟格式另写数据合同；不据三条通过分钟复盘、实时择时、全市场或指标。
