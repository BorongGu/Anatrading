# TQ 单证券日线缓存诊断 v0.2

2026-10-08，待独立反方评审；本文件尚不放行请求或产品代码。承接[两次空返回实测](../qualification/tdx-installed-client.md)，检验“该安装缺少可读取的历史缓存”这一候选解释。

## 范围与依据

官方[刷新历史缓存](https://help.tdx.com.cn/quant/docs/markdown/ctx.stock.md/mindoc-1h10fh9m6recg.html)允许按证券和 `1d/1m/5m` 定向下载，完成后返回，并会出现加载界面。它没有起止日期或条数参数。本轮仅候选刷新 `stock_list=['000001.SZ']`、`period='1d'`；这是单证券日线历史下载，不能承诺只下载三天，也不能承诺客户端内部网络量、缓存大小或后台运行时长受 HTTP 等待上限约束。

只使用已经安装、用户已报告登录的 `D:\tdx_64` 与原厂本机 HTTP 接口。不导入 SDK、不改变客户端设置、不安装软件、不修改账户或交易配置，不调用账户、下单、撤单、预警或任意功能串。原始响应及客户端缓存只留私有 artifacts；交易范围继续执行原有冻结。

## 顺序和停止边界

1. 每次请求前核对仅有一个 `127.0.0.1:17709` 监听，且拥有者路径为 `D:\tdx_64\TdxW.exe`；记录其 PID 和启动时间。身份不符、无监听、端点改变立即停止。刷新、查询前后的 PID 和启动时间必须相同，变化即停止；既有原始响应仍保留为跨会话观察，不用来归因本次刷新。
2. 新私有目录保存固定刷新请求及 UTC 时刻。最多一次 `refresh_kline` POST；连接等待最多 2 秒，完整 HTTP 等待最多 45 秒，响应最多 1 MiB；不重试、不跟随重定向、不发送空股票列表或其他周期。
3. 超时、断连、超限、非 200、坏 JSON 或非零业务码均保留独立失败状态，停止后续查询。HTTP 取消不能证明客户端任务已取消；结果未知时不再刷新，也不停止用户客户端。只可清理本次创建且身份已核对的请求进程。
4. 刷新响应同样须严格 JSON 解码、拒重复键和非有限常量，关联 `id` 与固定请求相同，`result` 为对象且 `ErrorId='0'`。只有完整满足这些条件，才允许一次固定 `get_market_data`：`000001.SZ`、`1d`、`end_time='20260930'`、`count=3`、`dividend_type='none'`、`fill_data=false`、不筛字段。连接 2 秒、完整等待 10 秒、响应 1 MiB；不重试、不翻页。合计最多两个新 POST。形状、类型、响应关联不符时不放宽门槛。
5. 前后只读统计 `D:\tdx_64\vipdoc` 文件数量与总字节；若发现 `sz\lday\sz000001.day`，记录该文件路径、长度、修改时间与 SHA-256，不打开产品数据库或自动导入。目录增长不是行情正确性的验收证据。

上述限制约束本方请求、等待和保存；不把它们说成客户端内部下载预算或生产采集容量。若后续需要严格限制客户端总下载量，应另选可指定日期的数据接口或由用户手动限定盘后下载。

## 判断标准

严格解码固定行情响应，拒重复键和非有限常量，核对关联 `id`。分别记录传输状态、外层／证券层业务码、实际字段和数组长度。`KlineTotal=3` 或刷新返回成功均不能代替实际 OHLCV、Date、Volume、Amount 的三条数据。若仍为空，仅记录该次刷新与空查询，保持原因未定，不循环试探。

取得记录时逐项核查数组长度相同、日期不晚于截止、日期顺序及重复，价格／量额保留原字符串，不补值、不猜单位或复权因子语义。不据三条结果宣称历史完整、当前软件兼容或自动更新通过。与同版真实导出逐字段对账仍是后续门槛；内置缓存文件和手动导出须分别标明来源。

本轮完成标准是取得一次可核对的刷新观察及其后的固定查询，或保存明确失败／结果未知证据，决定缓存解释是否值得继续验证。不实现采集器、交易 adapter、指标或新的产品格式。
