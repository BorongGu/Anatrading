# 免手动下载：自动取数方案 v0.2

2026-10-08。响应用户“不要我手动下载”的新增要求。本轮形成可评审方案，不启动长期后台任务；整体目标仍保持用户设置的 paused 状态。既有总体架构、单写者协议和原目标不变：全市场日线与自选分钟最终均需自动更新，先把一只自选股票闭环。

## 当前事实与尚缺证据

- [日线诊断](../qualification/tdx-cache-diagnostic.md)已通过本机 TQ `refresh_kline` 定向准备平安银行缓存；[离线内核](../qualification/tdx-current-cache-import.md)已精确保存 8,464 条记录并验证幂等。当前证据限这一会话／股票／哈希，日常调度和全市场尚未实现。
- [分钟诊断](../qualification/tdx-minute-source-diagnostic.md)只有成功码与空结果。用户在真实客户端界面确认能选择单股票、日期和 1 分钟，随后报告“按照系统安排：当前时间主站不允许下载分钟数据”。这证明该次界面请求被主站时段限制，不能证明它是此前 API 空结果的唯一原因。
- 界面提示当天数据 15:45 后可下载；这不是历史分钟主站的完整开放日程。不得据此保证 15:45 自动任务必成功，也不假定付费／换站能解决。
- 官方[缓存方法](https://help.tdx.com.cn/quant/docs/markdown/ctx.stock.md/mindoc-1h10fh9m6recg.html)支持按股票和 `1d/1m/5m` 定向准备缓存，但不能限定下载日期／总量。安装 SDK 的 DataFrame 会转浮点，实际 HTTP 日线量也有精度差异；不能将它们直接当精确量的主来源。

## 目标用户流程

用户配置自选股票、保持通达信运行并完成登录，随后由工具在可用时段执行“检查客户端→请求补缓存→核真实文件与覆盖→保存原件→提交不可变快照→报告结果”。日常无需点击下载或导出；安装、登录、服务申请仍由用户完成。历史手动导出只用于格式和语义对账，不作为每日采集步骤。

优先复用当前已可调用的本机接口与缓存文件，不新增付费源，避免把 GUI 截图／点击作为采集依赖。这不承诺接口或数据长期免费。主站时段限制必须遵守；分钟尚未取得有效数据前，不能发布“自动分钟已支持”或启用正式分钟入库。

## 阶段和实施边界

| 阶段 | 最小工作 | 通过条件 |
|---|---|---|
| U1 单股票自动获取 | 首个自选 `600059.SH`；通过原厂接口准备日线缓存，复制到私有证据目录；复用已有 `.day` 解码 | 真实缓存、请求身份和日期观察可对账，量为原整数，金额保留源 binary32 精确值；区分新内容、无变化且目标已覆盖、未覆盖、后台完成未知；失败不记成功 |
| U2 发布闭环 | 使用既有 EvidenceStore 导入／幂等和工作台单线程写入队列；自动采集到队列的适配尚未实现，采集与发布分离 | 工作台运行时没有第二 writer；同原件与解释复用快照，新原件产生新快照；旧原件／快照不变 |
| U3 一次分钟可用时段观察 | 用户主站时段限制改变后，另审有限请求；先辨别真实标签、截止参数及缓存布局 | 收到实际分钟数据、同源位型／单位和时间标签通过相应合同；API成功码不足以放行 |
| U4 有限调度 | U1/U2 已验收后，采用一个本机调度入口；固定自选清单，串行小批，有限退避 | 启动／取消／退出、重复触发、客户端离线、主站拒绝、空结果、残缺文件均有真实或明确故障注入证据 |
| U5 扩大规模 | 扩至自选分钟与全市场日线；证券清单、分片和覆盖独立设计 | 明确分母、单位、失败项、请求／存储／资源预算；不能把一只股票推广为全市场 |

调度时刻与股票清单进入有限配置；固定时间只是尝试点，不承诺服务开放。不能在每分钟空返回时不断重试。客户端任务结果未知时停止追加请求；下一次尝试需要明确外部状态变化或已评审的有限重试规则。

## 数据、锁和失败规则

1. 核实际 localhost 监听拥有者、程序路径、PID／启动时间与 SDK／程序指纹，不借品牌名确认兼容。只允许已审行情方法；没有账户、下单、撤单或任意功能转发入口。
2. 保存每次请求前后的身份和时刻。HTTP 成功／ErrorId 0、缓存 mtime 改变均不能单独代表下载完成。原件须稳定可读、有独立哈希，日期及实际记录与任务范围分别检查；日期不符、无数据和不完整分开报告。旧稳定缓存加成功码不能证明本次更新完成；明确区分新内容、无变化且目标已覆盖、未覆盖、后台完成未知。目标日期观察与全部应有交易日覆盖分别标记；交易日、停牌与上市退市分母未验证前，不宣称历史完整或当日最新。
3. 更新前后原件分别保留，按内容哈希保存；不将客户端可变缓存路径作为快照原件，不覆盖产品 raw object。对收到的数值保持原样，HTTP 与缓存差异单列，不能混源修正。
4. 日线初期仍用 `tdx-public-day-v1`；身份声明 assumed、单位与复权等未知资格不晋级。股票交易所真值、金额精度、标准单位和历史可得性仍另验。分钟正式格式、表示范围与语义尚未通过，禁止绕现有白名单导入。
5. 采集等待期间不持有产品数据根锁。发布进入现有唯一写者／任务队列；禁止另开数据库连接、停止工作台抢锁，或退到另一个数据根假报发布成功。原始下载产物、入库终态和可见快照是三个明确状态。发布连接中断时，既有写者可能继续提交；回执未知与入库失败分开，按同一原件／解释核对幂等结果，不凭断开连接判失败或重复追加任务。
6. 原件截断／变动、主站拒绝、空结果、目标未覆盖、单位或时间未知、资源超限有明确状态；不自动填缺失、删异常或取消失败分母。单次及每日请求数量、HTTP等待、文件副本与资源停止值在实现合同中固定，不能伪称这些限制也约束客户端内部后台下载。

## 开工条件与验收

先由独立反方审本方案，再为 U1/U2 写具体文件清单、响应形状、真实样本、测试与执行预算的实现合同；用户恢复项目后按该合同推进。保持一个调度入口、一个写者和现有存储，不引入新的服务／调度框架或第二套数据库。

验收必须覆盖真实成功闭环，以及客户端关闭、接口超时但后台结果未知、成功码空结果、日期不匹配、文件读取不稳定、重复触发、写者忙、提交前后中止等。故障注入只证明本工具状态处理，不能代替主站实际行为。最终用户能在一次启动工具后查看更新结果和失败原因，日常无需逐日手动下载；达到前明确保留未完成状态。
