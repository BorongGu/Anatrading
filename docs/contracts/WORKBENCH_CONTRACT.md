## 2. 最小实现选择与官方依据

### 前端复用

只读核对`web/package.json`与lock：Lightweight Charts **5.2.1**、React／ReactDOM **19.3.0**、TypeScript **7.0.2**、Vite **8.3.2**的声明与解析版本一致。后续[依赖资格核查](../qualification/workbench-dependencies.md)已确认8个直接依赖实际安装及Node模块导入，尚未运行应用构建或浏览器。

选择现有 Lightweight Charts 的源 OHLC 蜡烛与数量直方图，同一图表上下两个 pane；不新增图表库、React 图表包装层或前端 Decimal 库。React 管理控件、精确字段表和 tooltip；图表库只管理坐标与交互。官方 [pane 文档](https://tradingview.github.io/lightweight-charts/tutorials/how_to/panes)说明 `paneIndex`／`moveToPane`；[tooltip 文档](https://tradingview.github.io/lightweight-charts/tutorials/how_to/tooltips)说明 tooltip 需自行实现，本项目从精确记录取值，不照抄例子的浮点 `toFixed`。

**横轴选择：源记录序列轴。** 按后端的 `(parsed_label, source_record_ordinal)` 顺序，为每条有定位记录分配一个仅供绘图的整数位置，用源标签格式化横轴及十字线。相同标签的两条记录占两个相邻位置，保留各自定位和重复标记，不需要伪造不同时间。界面标明“源记录序列，等距不代表时间间隔”；午休、跨日只作标签分隔，不推导缺了多少柱。

此选择使用 [v5.2.1 的 `createChartEx` 原始实现](https://raw.githubusercontent.com/tradingview/lightweight-charts/v5.2.1/src/api/create-chart.ts)和官方 [`IHorzScaleBehavior` 示例](https://tradingview.github.io/lightweight-charts/tutorials/how_to/horizontal-price-scale)，只需一处横轴适配。独立浏览器负例须证明重复标签、无效值占位及截止仍正确；不能用丢行或伪造 UTC 时间绕过库限制。绘图位置、行映射与事件回调绑定当前query_id；Q变化即清除旧映射、回调及标签缓存。它属于渲染坐标，不写回日期、时间或查询身份。

原生交易时间轴待时段／边界合同通过后加入；不在本轮建设通用绘图引擎。保留库的 LICENSE／NOTICE 及页面 attribution 链接，按 [固定版本 README 的许可段](https://raw.githubusercontent.com/tradingview/lightweight-charts/v5.2.1/README.md)核对。页面资源在本地构建并提供，不依赖 CDN 行情或云端绘图服务。

### 本地服务

新增薄层 **FastAPI + Uvicorn**，共用 Python 应用用例、现有 Store 与精确序列化，不新增数据库或第二套业务公式。一个专用执行线程拥有Store，open、全部方法及close均在该线程串行；HTTP事件循环只做有界接收、排队和返回，不通过默认线程池随意分派Store方法。单 worker，显式绑定`127.0.0.1`，使用`asyncio/h11`，运行版关闭reload。同源提供构建后的前端和API。CLI同时访问同一数据根仍须服从既有OS锁。

官方依据：FastAPI的[ASGI运行说明](https://fastapi.tiangolo.com/deployment/manually/)、[lifespan](https://fastapi.tiangolo.com/advanced/events/)和[静态文件](https://fastapi.tiangolo.com/tutorial/static-files/)；[Uvicorn设置](https://uvicorn.dev/settings/)给出host、worker与Windows loop条件。采用本机已安装且经[元数据与导入核查](../qualification/workbench-dependencies.md)的**FastAPI 0.142.2／Uvicorn 0.54.0基础包**，实现时声明直接依赖并冻结报告中的14包闭包；不新增standard extras。应用启动关闭及HTTP兼容仍属实现后验收，不沿用示例的`0.0.0.0`。

## 3. 用户流程与数据边界

| 操作 | 必须得到的行为 |
|---|---|
| 启动 | 本地服务持锁打开指定私有数据根；成功后提供浏览器地址。占用／坏恢复目录等错误可读，不打开第二写入者，不自动创建另一份“临时正式库” |
| 导入 | 原生文件选择框；显式选择已支持格式，填写必要身份／品类声明。声明标为 assumed；来源合同已有证据不可被表单覆盖。只接受现行三类格式，99 批量响应、新 CSV、分钟二进制不因可取／可画就扩白名单 |
| 导入结果 | 显示 attempt 终态、复用或新增的快照、拒绝／字段问题；未提交项不出现在可选数据集中。失败与未知结果不能提示成功 |
| 选择数据 | 以快照／来源／源代码或身份声明／周期识别一项；选中后显示范围。新增必要的目录元数据读取，直接读已存manifest/metadata，不对每个快照执行全量query拼目录；不新增Schema。名称可读，完整哈希及版本可展开；文件名、六位代码不触发自动永久合并 |
| 查看 | 主区源 OHLC 与源数量；邻近原字段表、质量列表、资格摘要。图题显示来源、复权口径、源标签范围、单位及 known／assumed／unknown；未知单位直接显示“源数量（单位未核实）”。`.day`报价除100的既有候选解释保持assumed，可查原整数，不能提升为已证实报价单位 |
| 截止 | 输入／选择源标签，或按“上一标签／下一标签”移动。`parsed_label <= cutoff`，同标签全保留；不把源序号推进称为市场已闭合回放。空结果清楚显示，无上一份曲线残留 |
| 导出 | “导出当前选择（N条定位＋M条无法定位）”导出后端同查询的精确JSON；Parquet按内核能力提供，两个scope都保留。同一范围、排序、原token、质量、资格和版本均可对照，不从画布反取数值 |

首批浏览器单文件接收预算**16 MiB**；每个Q的有定位和无法定位记录合计最多**20,000条**。这是新增HTTP入口待实现、待测的预算，现有Store未有该硬限制。利用源序号窗口限定输入条数：批次超过20,000行必须显式给出跨度不超过20,000的闭区间；执行后再核对rows+unlocated总数，超限拒绝。现有Store仍可能全批读取，性能据此实测，不能声称已实现SQL分页。不偷偷截取最后N行；未来扩大另有资源测量，预算不等于源覆盖。

上传用受限字节流，同时最多接收一个文件，累计不超过16MiB；文件名只用于展示。有界内存接收后复用`import_bytes`，不能让通用multipart临时文件提前落盘。反方已发现原预检只在用户选择Bao格式时执行；开工前必须先修复：可识别的Bao信封不论声明哪一种格式都先通过统一行情预检，控制/未知方法/私有身份响应拒绝且不落原件、临时文件或日志。这是现有合同的缺陷修复，范围仅预检与回归，不承诺识别任意敏感文件。官方 [`Request.stream`](https://fastapi.tiangolo.com/reference/request/)提供分块读取；[Starlette文件说明](https://starlette.dev/requests/)明确上传文件可使用临时存储。

服务只暴露固定导入、列举、查询、导出与尝试状态操作；不接受任意本地读取路径、SDK 方法或 SQL。固定本地 Host／Origin 策略及写请求校验在 HTTP 测试中落实；跨源网页不能触发本地写操作。错误和日志保留安全代码，不打印文件内容。此约束不引入账号系统或外部认证服务。

## 4. 一个查询驱动所有当前结果

工作台的**数据窗口Q**沿用内核：快照、`retrospective`、截止标签、可选源序号闭区间，及快照继承的合同／规则版本。字段固定为现有OHLC、volume、amount六项，本轮不新增可选投影。服务返回Q的身份及结果；页面不另行计算质量真值。`assumed`／`evidenced_pit`查询仍拒绝，表单不能绕过。

Q 同时驱动两图、字段表、当前质量计数、最后一条记录卡和导出。改变快照或截止时，所有当前结果进入加载状态；旧请求晚到不得覆盖新 Q。导出在新 Q 确认前禁用。查询失败或原件哈希异常时，清空该面板当前图、tooltip 与卡片，阻断导出，不能用浏览器旧缓存继续显示为已核验。

画布缩放／拖动仅改变 Q 内的**可视区域**，不改变 Q、统计或导出；按钮明确导出“当前选择”。不把“图上暂时可见 50 条”标成“选择 50 条”。本轮不增加从任意画布范围反推不等价源序号区间的隐式筛选。

统计分三处：

- **当前数据窗口**：`selected_rows` 及对应 `pass/fail/not_evaluated` 计数；需要数值汇总时只使用已有后端精确结果，量额语义未知时不命名为成交总量／额。无对应后端输出的摘要先不显示。
- **全批信息**：`batch_rows`、`batch_unlocated_rows`与批次全局问题独立命名，可折叠；属于材料清单，不充当截止时点指标。不在此处放全批最终价格、未来高低点、后续收益或涨跌榜。
- **无法定位记录**：Q中的`unlocated`及`counts.unlocated_rows`受源序号范围过滤，独立列表及原因；无法归入任何cutoff，不补日期、零值或图形位置。它们不在图上定位，仍属于Q和导出；即使cutoff令定位记录为空，也可存在无法定位记录。被源序号窗口排除的数量由全批计数与所选计数区分。

没有预加载未来柱到图层再仅靠遮罩隐藏的做法。图表自动缩放、图例、tooltip、默认“最新值”、键盘移动目标与导出均不得访问 Q 外的价格／量。批次中有未来记录这个清单事实不产生未来行情卡片。

## 5. 源值怎样画，异常怎样保留

API 中 OHLC、量、金额及汇总真值使用字符串；空值带状态和原因。绘图适配只为坐标建立 `Number` 副本；不能把它写回 API、查询、比较、统计、tooltip 或导出。二进制字段展示精确解码字符串及原位／偏移依据，不能称作不存在的“原始文本 token”。文本字段同时保留原 token 和精确解码值，两者不相同时可分别查看。

| 源记录状态 | 图形与原字段表现 |
|---|---|
| 有效数值但单位／柱定义未知 | 可画“源 OHLC／源数量”，就地保留未知标记；不据此命名实际首笔成交、真实交易均价或买卖信号 |
| OHLC 可画，量额条件诊断失败 | OHLC 与量保留；明显问题标记链接到原记录及条件前提。不得删除、截尾或放宽阈值使其消失 |
| 缺失／非法 OHLC 或包含关系失败 | 该实际源记录保留横轴位置，以缺值／错误标记占位；不构造正常蜡烛，不自动交换 H/L。其他独立可用字段仍可显示 |
| 数量为精确 0 | 轴基线处零值标记及 tooltip 的 `0`；不人为抬高为非零柱。不能仅据零判断真实无成交或停牌 |
| 数量未知／非法 | 区别于零的缺值标记及具体原因；图形空位对应这条已存在记录，不生成不存在的分钟柱 |
| 重复／源顺序问题 | 每条源记录独立保留；重复标签并列，排序遵循 Q；提示其原序号及既有质量结果。不静默去重或覆盖 |
| 两个精确值转浮点后重合 | 在Python应用展示层新增基于Decimal比较的up/down/equal/unknown方向，不改Store数值、质量和Schema；不能按显示浮点判涨跌。重合时标“显示分辨率不足”，必要时不画有误导的正常蜡烛；tooltip／导出仍分别保留原值 |

禁止插值、前值补柱、跨午休拼接、默认复权、平滑和缩小时抽点后继续称原 OHLC。没有交易日历／阶段证据的空档只陈述源标签不连续，不能给出伪造的缺失柱数。第一版超过显示预算要求缩小窗口，重采样另过数据门槛。

tooltip 通过源记录定位读取精确字符串，包括源日期／时间、OHLC、数量、金额、单位资格与错误原因；不能仅从图表事件的浮点值生成。原 token 作为纯文本渲染，不作为 HTML。十字线离开、快照切换或截止退回时清理旧 tooltip；同屏颜色不能取代问题文本和键盘可访问的字段表。

## 6. 日线与分钟的显式条件配对

此节属于紧接的第二切片，单快照闭环通过后再实现。至多两个独立快照面板：用户明确选择日线与分钟快照，记录配对声明、源代码／市场／品类／复权差异及两份快照身份。仅在可比的源断言明确冲突时阻止“同证券配对”；`601577`与`sh.601577`这种编码形式差异本身不证明冲突，也不证明永久身份相同。身份未知时只允许标注条件的回顾。配对不生成规范instrument_id、不写跨批永久历史、不合并字段、不共用价格或数量轴，不按数组位置强行同步十字线。

联动截止定义固定如下：

1. 分钟面板 cutoff 为源标签 `D T`，只查询该快照 Q 内 `<= D T` 的记录。
2. 日面板限 `source_date < D`。可由应用层把上界表达为 D 的前一自然日，不需要猜前一交易日；若结果为空就显示为空，不回退到 D 的完整日柱。
3. D 日完整 OHLC、全日数量／金额及相关卡片不进入这个联动视图，包括分钟标签到 15:00 时。源标签不证明柱闭合或供应商日线当时已发布。
4. 查看 D 的完整日线须退出联动、明确进入单快照日线历史回顾；返回联动时重建 Q 并清理旧值。该操作不能留下隐蔽的当日日收盘卡片。

这个严格日期规则只防止明显的同日终值泄漏；前一日数据也未因此获得历史可得证明。界面持续标记“历史回顾，可能包含事后修订”。今天手选两份历史资料只建立条件样本，不重建过去全市场选股或过去自选集合。[架构时间与研究边界](../ARCHITECTURE.md)、[修订研究](../research/008-acquisition-and-revisions.md)

一个临时配对请求代次固定两个snapshot_id、分钟D及派生日截止、两个预期Q和配对声明；两面都收到属于本代次的query_id后才可配对导出。任一面加载、失效或失败，整体配对导出禁用；单面回顾可以独立进行，但不能混入上代次数据。无需持久配对数据库。导出时两份Q分别保存并附声明，不输出拼接行情表。不同来源、单位或调整口径只作明示条件，不自动生成相关性、信号或跨源均价。

## 7. HTTP 与窗口失败状态

服务生命周期拥有Store；开始关闭先停止新提交，等待已接受操作在专用线程结束，最后在该线程close并释放锁，不能靠取消HTTP等待释放Store。不得每请求打开数据根。浏览器刷新、取消等待或关闭标签页均不等于导入已取消；首版不提供取消按钮。默认最多接受一个导入；查询、导出及账本读取均与导入串行，明确不承诺长导入期间实时轮询账本。

首版可以同步完成小文件导入；开始后按钮显示处理中、防止重复提交，结果以应用层 attempt 账本为准。回执丢失显示“结果待核对”，通过尝试列表核对后才宣告终态；不能凭网络异常宣告导入失败，也不能通过重命名文件绕开内容幂等。若提供取消按钮，须消费既有接受点／提交中／终态语义，不能先提示已取消后出现新快照。

API 查询和导出每次执行既有原件哈希验证。外部修改不承诺瞬时自动发现；下一次查询／导出发现损坏必须阻断并清掉对应当前显示。源值原件缺失不能降级成仅依赖数据库缓存的成功。预期业务拒绝显示可操作原因；未捕获异常、React 错误或绘图库报错不能被吞掉后留下空白成功页面。
