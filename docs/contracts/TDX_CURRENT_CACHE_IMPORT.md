## 输入与来源边界

唯一输入是 `artifacts/qualification/tdx-cache/20261008T040520901324Z/source-sz000001.day`，270,848 字节，SHA-256 `715cee9f7203c560944c8ffa665321ace00805f6648d6892f81d8230baa66cca`。输入为当前安装客户端缓存的私有字节副本，不能标成手动导出；来源链见[缓存诊断](../qualification/tdx-cache-diagnostic.md)和[精度反方 017](../reviews/017-tdx-live-precision-review.md)。

017 的精度 P1 按如下边界落实：TQ 原响应与缓存原件各自保持独立哈希和定位；只导入缓存原件，不导入／合并 HTTP，不用 HTTP 成交量替换缓存整数，也不以缓存替换原 HTTP 响应。金额保留收到的 binary32 精确值，不推定交易所原始金额。两种来源差异保留为失败证据。

格式名称与结构通过不授予客户端兼容资格。解释只声明 `instrument='000001.SZ'`、`venue='SZ'`、`asset_type='stock'`，保留 assumed；不声明量额单位。沿既有合同，`instrument_id`、`volume_shares`、`amount_cny` 保持空，源单位、覆盖、复权、历史可得性和标准化资格保持 unknown；四个报价整数除 100 的现有解释保持候选状态。若现有代码将这些声明升级为已验证单位／身份，立即停止，不静默修复代码。

## 执行与验证

1. 执行前核对输入完整哈希和长度，核读现有 `formats._day`、CLI 及首批合同；先以独立 `struct`／整数和 Decimal 计算全部记录的日期、价格、量、金额、保留字节及预期数值问题。无请求、不改客户端缓存。输入异常不能自动删除或修正。
2. 仅在新私有 `artifacts/qualification/tdx-current-import/<UTC>/data/` 打开 EvidenceStore。使用既有 CLI 完成一次导入，不打开旧性能副本或现有个人数据根。全部操作依现有持锁协议，禁止并行访问数据根。
3. 独立读所有已导入行，以原字节定位逐项核对 8,464 个记录槽和全部源值、token；数值不可用或异常按既有规则保留并报告。不能把原文件条数当作已通过值校验条数。直接产品查询／SQL 解码仅在持有本工具操作锁、关闭前一 CLI 后通过同一个 EvidenceStore 进行。
4. 以源序号 8462—8464 固定三条记录，核对产品查询及 JSON／Parquet 导出中的整数成交量、精确 binary32 金额、日期、checks、token、原件身份与未知资格。这个窗口有独立原位预期；不执行全量 HTTP 性能测量，不据三条往返宣称性能通过。
5. 重复相同文件和解释一次，须返回相同快照／批次，新增尝试指向原结果。正常关闭后检查原件哈希和没有遗留 WAL；失败不重建／覆盖旧根，不删除证据。无需为已验证的格式重写产品测试。

每个私有子进程最长 60 秒；观察到当前／峰值 WorkingSet 或 PrivateUsage 超过 2 GiB 即停止，仅停止本次创建且 PID／启动身份已核对的进程。此为观测停止值，不能证明硬内存隔离。入库与全行核对分开运行，不同时物化两个大结果。超时保留失败和现场，不重复已超限输入。

## 成功标准与停止条件

当前新缓存能被既有内核导入为独立不可变快照；全部可解释源值与原件定位一致；未知资格没有晋级；三条窗口两种导出与查询一致；重复导入幂等。这只验源值保存和往返，不验交易所真值、真实手动导出兼容、分钟、全市场、PIT、VWAP／量能指标或收益。

哈希变更、原件异常、源值新增舍入、HTTP 混入、单位／身份晋级、旧根被打开、资源超限任一出现立即停止。若需要修改产品或增加字段／格式，另写实现合同和反方；本轮不借导入验证解冻产品代码。
