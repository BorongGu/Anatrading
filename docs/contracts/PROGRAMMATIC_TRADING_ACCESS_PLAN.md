# 程序化交易接入方案 v0.1

2026-10-08，待反方复审与运行位置确认。对应[研究记录](../research/010-programmatic-trading-access.md)。本方案承接用户新增的自动委托需求；不修改已冻结的总体架构，不解除交易产品代码范围。

## 最终目标与当前范围

最终目标是用户自编逻辑通过已获授权的券商通道自动委托，并可核对订单状态。优先保留 Anatrading 独立程序目标；GWT 客户端内策略只是候选，用户对运行位置的选择尚待回复。内置模拟路径成功不能标记独立接口或实盘自动交易完成。

当前交付：核本机 TQ 文件与监听，确认一级接口来源，形成向长城申请测试和确认外部 API 的具体问题，冻结候选路径与验收门槛。当前没有交易 adapter、实盘连接或外部委托程序配置变更。

## 连接职责

- **行情**：通达信 TQ，只调用经审的只读行情方法；原始响应、单位、时间及复权按数据合同验收。
- **研究输出**：Anatrading 保存来源与研究证据。当前输出不是已验证的自动交易策略。
- **模拟执行候选**：用户取得 GWT 测试账号后，若接受内置运行，则在明确的测试环境内运行最小自编 Python 模型；使用该平台自身行情，不先构建未经证明的两端通信桥。
- **独立执行候选**：仅在长城提供正式外部 API 契约与测试权限后，设计 Anatrading 的接口适配和订单生命周期。内置 API、外部解释器支持、可启动交易软件三者均不能代替该契约。

## 阶段验收

| 阶段 | 通过证据 | 当前状态 |
|---|---|---|
| A 本机与来源 | 实际 AMD64 程序、SDK 指纹、监听归属；官方来源链 | 文件／监听层已核；实际行情响应仍待验 |
| B 路线与权限 | 用户运行位置选择；长城对新账户测试资格、接口范围和版本的确认 | 待确认 |
| C 模拟闭环 | 明确测试环境；自编触发→意图→受理／拒绝→最终状态；重复触发不重复委托 | 未实现、未运行 |
| D 独立接入 | 若目标要求独立进程，必须有真实外部 API、权限及相应模拟闭环 | 未确认 |
| E 后续实盘 | 券商权限、具体账户／环境、当前审核要求和独立实施决定 | 本轮范围外，未取得证据 |

模拟验收须覆盖拒绝、部分成交、取消、断连／超时后结果未知和重复触发。未取得可核对回报时停止追加委托，不能以重试推定未受理。无明确测试身份时不调用下单方法。

## 限定下一步

主方完成文档和独立 rebuttal。用户向长城确认测试账号与接口模式；不开通快速柜台、不变更风险测评、不提交协议作为这一步的默认操作。随后按确认结果写有限实现合同，明确允许修改的产品文件、模拟环境、失败边界和验收案例，评审关闭后才能编码。

此方案不把收费页面、账号新开、TQ 监听或策略样例提升为可交易资格，也不将模拟收缩为用户完整目标。
